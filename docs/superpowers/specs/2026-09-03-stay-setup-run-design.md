## 1. 목적과 범위

`stay-setup-guide` 가 만든 입력 지시서(HTML 또는 manual.md)를 받아, 사용자가 이미 로그인해 둔 크롬 탭에서 ERP Stay 화면을 1단계부터 순서대로 채우고 저장한다. 코딩 에이전트 비유로 stay-setup-guide 가 Plan, 이 스킬이 Execute 다.

- 하는 것: 호텔 만들기 → 기본정보·이미지 → 호텔 정보 → 취소정책 → 룸·룸 사진 → 오퍼 → 판매 연결 → 시즌 → 요금제 → 판매일 → 시즌 가격 → 부과금·부가옵션·프로모션·혜택 → 경고 넘어가기. 단계마다 저장 뒤 화면을 다시 읽어 설명서 값과 대조하고 로그에 남긴다.
- 하지 않는 것: **[판매 시작] 은 사용자가 누른다.** 로그인·비밀번호 입력, 설명서에 없는 값의 판단, 내부 API 호출. confirm 창을 띄우는 버튼(삭제·보관·닫기·공용으로 등)은 설명서가 요구할 때만, 사용자에게 채팅으로 확인받은 뒤에 누른다.
- 배포 대상: 여행사(eoding ERP 계정을 가진 고객·파트너). 라이선스 1조가 이미 "사용자를 위해 일하는 AI 에이전트 도구의 실행"을 허용한다.

## 2. 입력과 출력

입력
- 공유 폴더: `<이름>_입력지시서.html` (필수) + `사진/` (있으면). 같은 폴더에 `manual.md` 가 있으면 그것을 우선 읽는다.
- 로그인된 크롬 탭. 사용자는 목록 페이지 또는 편집 페이지 주소를 알려준다. 스킬 파일에는 호스트명·URL 을 적지 않는다.
- 옵션: `--title-prefix` (호텔명·상품명 앞에 붙일 접두, 예 `__skills__`), `--photos <폴더>` (설명서의 `폴더:` 대신 쓸 사진 폴더), 모드(연속/검토).

출력
- ERP 에 설정된 호텔(판매 시작 직전).
- `run-log.md` (실행 로그, §7) 와 `steps.json` (파서 산출물). 산출물은 공유 폴더 옆 `<이름>_실행/` 에 둔다.
- 마지막 보고: 완료·건너뜀·실패 단계, 대조 불일치, 비워 둔 칸, 사용자가 누를 [판매 시작].

## 4. steps.json 스키마

```json
{
  "guide": {"title": "…", "source": "manual.md|html", "share_folder": "우에노_토우가네야", "photos_dir": "/abs/…/사진", "title_prefix": "__skills__"},
  "steps": [
    {
      "no": 10,
      "title": "룸 만들기 (1번째, Single)",
      "kind": "룸 만들기",
      "head": {"screen": "…", "tab": "객실", "card": "…", "block": "…", "buttons": ["기존 `스탠다드` 행의 [편집]", "드로어 안 `침대 구성` 의 [침대 행 추가] 1번"], "folder": "…", "notice": "…"},
      "fields": [
        {"label": "룸 이름", "kind": "typed", "value": "Single"},
        {"label": "상위 동/윙", "kind": "select", "value": "(없음)"},
        {"label": "요일", "kind": "uncheck"},
        {"label": "대상 룸", "kind": "multi", "values": ["A", "B"]},
        {"label": "전망", "kind": "empty"},
        {"label": "수수료명", "kind": "auto"},
        {"label": "오퍼 이미지", "kind": "file", "file": "offer_hero.jpg"}
      ],
      "longtexts": [{"label": "상세설명", "text": "…"}],
      "photos": [{"file": "hotel_01.jpg", "source": "https://…"}],
      "submit": "저장",
      "raw": "## 10. …(원문 마크다운)"
    }
  ]
}
```

- `kind` 는 제목의 첫 괄호 앞 부분(예 `룸 만들기`). 스킬은 `kind` 로 화면 대응표를 찾되, 실제 이동은 `head` 의 탭·카드·버튼 글자를 따른다.
- 값 종류(`kind`)는 MANUAL-SPEC 의 표기 그대로: 값 그대로 → `typed`, `선택: X` → `select`(콤마로 여럿이면 `multi`), `체크`/`해제` → `check`/`uncheck`, `비움` → `empty`, `자동 입력됨 · 그대로 둠` → `auto`, `파일: x.jpg` → `file`.
- HTML 입력일 때는 렌더된 마크업(단계 `h2`, `화면:` 류 문단, `칸|값` 표, 복사 버튼의 원문, `선택 ▸`, 흐린 글씨, 파일 목록, 마지막 버튼 상자)에서 같은 구조를 복원한다. 파서 테스트는 예시의 manual.md 와 HTML 을 각각 파싱해 같은 steps 가 나오는지 본다.
- `--title-prefix` 는 `호텔 만들기` 단계의 `호텔명` 과 `기본정보 글 입력` 단계의 `상품명` 값 앞에 붙인다. 다른 값은 건드리지 않는다.
- `--photos` 가 있으면 `photos_dir` 로 쓰고, 없으면 설명서의 `폴더:` 를 공유 폴더 기준으로 푼다. 파일이 없으면 파서가 경고 목록을 낸다(실행 때 그 단계는 건너뛰고 로그에 남김).

## 5. 페이지 도우미(stay_helper.js) API

한 번 주입하면 `window.stayRun` 이 생긴다(멱등). 페이지가 새로 뜨면 다시 주입한다. 서버 요청을 직접 보내지 않고, 화면의 입력 요소와 버튼만 다룬다. 내부 URL 을 갖지 않는다.

```
stayRun.state()                → {url, loggedIn, loginPage, logoutWarning, drawer:{open,title}, modal:{open,title}, activeTab, banner:{blockers:[…], warnings:[…]}, toast, hotelId}
stayRun.tab(name)              → 탭 글자로 전환, 완료 대기
stayRun.open(spec)             → spec = {button:"편집", row:"스탠다드", card:"판매 연결 (오퍼 × 객실)", block:"…", inDrawer:false}
                                 행·카드 글자로 범위를 좁혀 버튼을 누르고 드로어/모달이 열릴 때까지 기다린다
stayRun.fill(fields, opts)     → 각 칸 결과 [{label, status:"ok|not-found|ambiguous|needs-upload|skipped", detail}]
                                 needs-upload 인 파일 칸에는 data-stay-upload="<label>" 표식을 남겨 에이전트가 find 로 찾게 한다
stayRun.addRow(buttonText, n)  → 반복 행 추가 버튼을 n 번 누른다
stayRun.submit(buttonText)     → 범위 안 버튼을 누르고 응답을 기다린다 → {status:"closed|stayed|navigated|login|timeout", errors:[…], toast, url}
stayRun.readback(fields)       → 지금 화면의 값 [{label, actual}]
stayRun.close()                → 드로어·모달 닫기(Escape 또는 닫기 버튼)
stayRun.keepAlive()            → 자동 로그아웃 경고 모달이 떠 있으면 [확인] 을 누른다
```

칸 찾기 순서: `label[for]` → 감싸는 `label` → 같은 행 `th` → 형제 제목 요소(`.head` 등 라벨 글자 요소) → placeholder. 범위: 열린 드로어 본문 → 열린 모달 → 활성 탭 → 문서. 같은 라벨이 여럿이면(한 행 2칸) 화면 사전의 순서로 n 번째, 파서는 `label` 에 `#2` 를 붙일 수 있다. 라벨 비교는 공백·`*`·구두점을 지운 뒤 한다.

값 넣기
- `typed`: value 대입 후 `input`·`change` 이벤트. textarea 도 같다.
- `select`: 네이티브 select 는 옵션 글자 일치(괄호 안팎·공백 무시). Materialize 는 트리거 클릭 → 항목 클릭. select2 는 열기 → 검색 칸에 값 넣고 keyup → 결과 글자 일치 클릭. 후보가 둘이면 `ambiguous`.
- `check`/`uncheck`/`multi`: 체크 그룹에서 라벨 글자 일치. `multi` 는 목록에 없는 것은 해제하지 않는다(설명서에 적힌 것만 켠다).
- `empty`: 값을 지운다(텍스트) / 첫 빈 옵션(셀렉트) / 해제(체크). `auto`: 건드리지 않고 `skipped`.
- `file`: 값을 넣지 않고 `needs-upload`. 에이전트가 브라우저 도구의 파일 업로드로 올린다.
- 반복 행(침대 구성, 추천 포인트, 요율, 구간, 단): 라벨이 `침대 구성 1 · 침대 종류` 꼴이면 n 번째 행의 그 칸. 행이 모자라면 추가 버튼을 먼저 누른다.

버튼 누르기: 범위 안에서 글자 일치. `hx-confirm` 이 있거나 글자가 삭제·보관·닫기·공용으로·판매 시작이면 `refused` 로 돌려준다(에이전트가 사용자 확인 뒤 `force:true` 로만 누를 수 있고, 그때는 confirm 을 일시적으로 자동 승인해 다이얼로그가 뜨지 않게 한다. [판매 시작] 은 force 로도 안 된다).

대기: htmx 요청 시작/종료 이벤트 또는 드로어·모달 상태 변화, 최대 10초. 응답 뒤 로그인 폼이 보이면 `login`.

## 6. 실행 절차 (SKILL.md 요지)

1. 준비: 공유 폴더·사진 폴더·크롬 탭 확인. `parse_guide.py` 로 steps.json. 사진 누락 경고를 사용자에게 보여 준다.
2. 시작 화면: 목록 페이지에서 시작하면 1~3번(확인 단계)과 4번(호텔 만들기)을 거쳐 편집 페이지로 넘어가고, 주소에서 호텔 번호를 읽어 `run-log.md` 에 적는다. 편집 페이지 주소를 받았으면 그 호텔에 이어서 한다(호텔 만들기 단계는 건너뛰고 로그에 "이미 있음").
3. 단계 반복: `state()` → 필요하면 `keepAlive()` → `tab()` → `open()` → `fill()` → 파일 업로드 → (검토 모드면 스크린샷 후 사용자 확인) → `submit()` → 결과 판정 → `readback()` 으로 대조 → 로그.
4. 중단 조건: 칸 못 찾음·모호, 저장 뒤 남은 오류 문구, 대조 불일치, 로그인 페이지, 10초 초과. 멈추면 스크린샷과 함께 무엇이 어긋났는지 보고하고 사용자의 "계속"을 기다린다.
5. 중복 방지: 만들기류 단계는 실행 전에 목록에 같은 이름이 있으면 건너뛰고 "이미 있음". 호텔 만들기는 목록에 같은 호텔명이 있으면 사용자에게 묻는다.
6. 끝: [판매 시작] 앞에서 멈춘다. 검증 배너의 남은 항목, 비워 둔 칸, 건너뛴 단계를 보고한다.

## 9. 화면 사실 (조사 결과 요약)

- 서버 렌더 + htmx + Alpine. 탭은 글자로 전환되고 주소의 해시가 바뀐다. Stay 탭의 입력은 전부 오른쪽 드로어 안 표 구조(머리칸 라벨 + 입력 칸 + 도움말). 체크박스는 감싸는 라벨. 셀렉트는 네이티브. 날짜·시각은 데이트피커 없는 일반 텍스트(`2026-01-01`, `14:00`, `2026-01-01 00:00`).
- 기본정보 탭과 호텔 만들기 폼만 Materialize 셀렉트와 select2 자동완성을 쓴다. select2 는 검색 칸에 keyup 이벤트가 있어야 검색된다.
- 저장은 htmx 요청이고 드로어 본문이 교체된다. 오류면 폼이 다시 그려지고, 성공이면 드로어가 닫히는 것으로 추정(실행하며 확인).
- 이미지 모달: 지역·국가·도시 셀렉트(선택), 이미지설명(Alt), PC 이미지 파일 1개, 모바일 이미지 파일 1개, 헤더 [저장].
- 검증 배너: 막힘 목록·권고 목록, 줄마다 [이건 넘어가기] → 사유 칸 → [넘어가기]. [판매 시작] 은 막힘이 없어야 활성.
- 위험: [삭제]·[보관]·[N월 닫기]·[공용으로]·[그룹 삭제] 는 confirm 창. 자동 로그아웃 경고 모달이 있고, 만료되면 드로어 요청이 로그인 페이지를 받아온다.
- 파일 업로드: 크롬 도구는 세션에 공유된 폴더의 파일만, 한 번에 10MB 까지 올린다. 사진 폴더는 프로젝트 안 `산출물/` 처럼 세션이 접근할 수 있는 곳에 둔다.

## 10. 검증 계획

1. 파서: 예시(우에노) HTML ↔ manual.md 동일성, 그리고 내부 시험 설명서 7개(67~134단계) 파싱에서 알 수 없는 값 종류·단계 종류가 0 인지.
2. 도우미: 편집 페이지에서 저장 없이 칸 찾기·채우기·읽기 검증.
3. 엔드투엔드: `--title-prefix __skills__` 로 시험 설명서 7개를 각각 새 호텔로 끝까지 실행(사진 포함). 실행하며 대응표(§8)와 도우미를 보강한다. [판매 시작] 은 사용자.
