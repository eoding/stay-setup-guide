1한 장 요약

코드 세 벌(엔진 → ERP → 고객 화면)을 먼저 내보내고 그다음 prod 서버에서 손으로 데이터 이사(마이그레이션 0013)를 돌린다. 파이프라인은 migrate 를 돌리지 않는다. 워크플로·스크립트·Dockerfile 어디에도 그 단어가 없다.

2왜 그 순서인가

옛 데이터 (2)새 데이터 (A2)
옛 코드된다안 된다 — A2 를 못 읽는다
새 코드된다 — 숫자 키 폴백된다

새 코드는 옛 키를 읽는 폴백이 있다. 옛 코드는 새 키를 못 읽는다. 그래서 코드가 다 나간 뒤에 데이터를 옮기면 깨지는 창이 없다.

3DB 에서 바뀌는 것

표(테이블)는 둘만 건드리고 스키마는 그대로다. ALTER 는 한 줄도 없다.

테이블무엇을로컬 실측
stay_productpriceoccupancy_key 값만 바꾼다. "2" → "A2"95,829행
stay_productprice같은 자리에 A<n> 이 이미 있는 숫자 셀을 지운다84행

로컬 DB 에서 실제 SQL 을 잡아 봤다(트랜잭션 안에서 돌리고 롤백). UPDATE 53문, DELETE 2문, SELECT 4문. 행 하나씩 가지 않고 id 묶음으로 간다.

UPDATE `stay_productprice` SET `occupancy_key` = 'A2' WHERE `stay_productprice`.`id` IN (196132, 195916, …)
DELETE FROM `stay_productpricevalue` WHERE `stay_productpricevalue`.`product_price_id` IN (337063, 337105, …)
DELETE FROM `stay_productprice` WHERE `stay_productprice`.`id` IN (337063, 337105, …)

보류 61건은 로컬 오퍼 188 이야기다. 유료 연령 구간이 둘(ADULT · CHILD)이라 코드 없는 A2C1 이 어느 구간의 1명인지 정해지지 않아 그대로 둔다. prod 에 이런 오퍼가 있으면 dry-run 이 목록을 내고, 사람이 정한다.

운영 DB 는 9월 9일에 터널로 붙여 읽기 전용 dry-run 을 돌렸다(e0 세션). 셀 39,878행 중 숫자 키 28,954행이 옮겨지고 삭제 0 · 보류 0 이다. 2→A2 10,631 · 3→A3 8,834 · 4→A4 4,014 · 5~9 각 1,095. A-형 셀은 아직 0 이다. 그래서 겹칠 것이 없다. 박수 층이 둘 이상인 좌표도 0 이다. 스테이지는 별도 DB 이고 옮길 좌표가 없다(빈 키 61행). 스테이지 migrate 는 운영과 무관하다.

4django_migrations 에도 남나

migrate stay 로 돌리면 남는다. showmigrations stay 에 [X] 0013 으로 찍히고 다시는 안 돈다. sqlmigrate stay 0013 은 "THIS OPERATION CANNOT BE WRITTEN AS SQL" 만 낸다. RunPython 마이그레이션이라 SQL 이 미리 정해져 있지 않아서다. 위 SQL 은 실제로 돌려 잡았다.

관리 커맨드 stay_normalize_occupancy_keys 로 돌리면 데이터는 같게 바뀌지만 django_migrations 에는 안 남는다. 나중에 migrate 가 0013 을 또 돌리는데 같은 규칙이라 0건 처리로 끝난다. 그래도 prod 는 migrate 로 돌린다. 기록이 남아야 한다.

고친 것 — ERP (테스트 2218 → 2310)

  • 마이그레이션 0013 을 한 트랜잭션으로 감쌌다. MySQL 은 RunPython 을 자동으로 감싸지 않아 2,000행 묶음마다 따로 커밋됐는데 이제 전부 아니면 전무로 끝난다.
  • 재실행이 멱등이다. "2" 와 "02" 처럼 1회차가 보류한 셀을 2회차가 지우던 것을 막았다. 선행 0 키는 언제나 보류다.
  • 비활성(use_flag=False) A2 는 활성 숫자 셀을 못 지운다. 생존 후보는 활성 행만이고, 아니면 보류다.
  • 코드 없는 A2C1 과 A02C1 이 같은 A2C1_CHD 로 가려다 UNIQUE 에 걸리던 것을 보류로 돌렸다.
  • 옛 규칙 연령 구간 코드(CHILD_UNDER12)가 견적을 500 으로 만들던 것을 성인 취급 + 경고로 바꿨다.
  • 코드 없는 A2C1 후보는 그 오퍼의 유료 구간이 정확히 하나일 때만 넣는다. 문서와 마이그레이션이 이미 그 규칙이었다.
  • 유료 아동인데 조합 셀이 없으면 성인 전용 A2 로 내려가 아이 요금이 사라졌다. 이제 머릿수 A3 로 간다. 옛 총원 규칙과 같은 값이다. 조합 셀도 A3 도 없는 계약은 과소 청구 대신 판매 불가로 접힌다. 이 선택은 James 가 9월 9일에 확인했다.
  • 다객실·성인만 요청의 폴백에서도 A-형이 숫자보다 먼저다.
  • 직원 예약이 실패한 화면에서 견적을 재조회할 때 여행사·마스터 조건을 걸었다. 다른 여행사 견적의 아동 정보가 그 화면에 나오지 않는다.
  • los_prices·occupancy_adjust 의 dict 입력도 문자열과 같은 검증을 지난다. 파서는 A2C1_C1_CHD 같은 혼합 형식과 33자 결과를 거부한다.
  • 삭제 예정 셀을 CSV 로 떠 두는 --dump-deletes 옵션을 더했다. 확인창은 마스크를 눌렀을 때만 닫힌다.
  • 맨 숫자 셀을 지우기 전에 살아남는 A-형 셀과 가격·정가·상태·권위값을 대조한다. 하나라도 다르면 지우지 않고 보류로 남긴다. 활성 A-형이 둘 이상이어도 보류다.
  • FIT 예약 상세의 추가수집정보 탭을 저장해도 stayOccupancy 가 남는다. James 가 배포 차단으로 지정해 fit/ 한 곳을 고쳤다.
  • 박수 층 규칙을 James 결정대로 바꿨다. 층은 날짜마다 고른다. 요청 박수 이하 층이 없으면 최소 층으로 물러나지 않고 마감한다. 견적은 PRICE_CELL_UNAVAILABLE, 룸 리스트는 빈 행과 같은 코드의 경고를 낸다. 어떤 날에만 층이 있어도 다른 날이 비지 않는다.
  • PR 의 CodeRabbit 지적 12건을 처리했다. 정리 로직의 parse_key 예외는 보류로 돌리고 참조 구간(REF_BAND)은 푼 뒤 유료를 판정한다. 좌표로 못 쓰는 구간 코드는 시즌 전개에서 제외하고 32자 초과 키는 500 대신 경고를 낸다. 시즌 전개는 기존 셀을 한 번에 읽고 bulk_create 로 넣어 쿼리가 10회로 고정된다.

고친 것 — 엔진 (Stay 테스트 696 → 726, DB 미접속 9건은 전과 같음)

  • ERP 와 같은 네 규칙: 코드 없는 후보 가드, 머릿수 폴백, 폴백의 A-형 우선, 읽지 못한 구간 코드는 성인 취급 + AGE_BAND_CODE_UNREADABLE 경고.
  • 견적 요청에 optional children 을 받아 룸 리스트와 같은 "나이가 다 왔나" 판정을 한다. 나이 없는 옛 요청에서 목록 130 · 견적 150 으로 갈리던 답이 같아진다.
  • 최종 필터가 정규화 키로 비교한다. a2 와 A2 가 한 좌표다.
  • 잘못된 키마다 예외를 만들던 자리를 parseKeyOrNull 로 바꾸고 LOS 주석과 원장 문구를 새 규칙으로 고쳤다. 조합 좌표를 못 만든 요청에 OCCUPANCY_WITHOUT_PARTY 경고를 남긴다.
  • 박수 층 규칙을 ERP 와 같은 명세로 미러링했다. 층은 날짜마다 고르고 자격 없는 층은 마감한다. PRICE_CELL_UNAVAILABLE 코드도 같다.
  • PR 의 CodeRabbit 지적을 처리했다. 파티 판정이 예외를 삼키지 않고 Composed/Unavailable 로 돌아온다. 32자 초과 키는 OCCUPANCY_KEY_TOO_LONG 경고로 룸 리스트와 견적 둘 다에 남는다.

고친 것 — 고객 화면 (Stay 테스트 974 → 999)

  • 키 파서를 순차 파싱으로 다시 썼다. 5초 넘게 돌던 123자 악성 키가 1ms 안에 거부되고 A2_C1_CHDC1_TEEN 처럼 반만 읽히던 키를 거부한다.
  • 재조회 중에는 이전 가격 옆에 새 아이 나이가 붙지 않는다. 화면에 있는 행을 만든 검색 인원을 함께 들고 다닌다.
  • 검색 인원 주석을 본문 캡션으로 내렸다. 터치·키보드에서도 보인다.
  • 마이페이지 성인 행의 나이 표기, 아이 수 불일치 주석, CHILD_AGE_MAX 단일 원천, React key 중복을 고쳤다.
  • 견적 요청에 children 을 싣는다. 결제 준비 요청의 selection 에서는 뺀다. ERP 가 selection 전체를 해시하므로 실으면 모든 예약이 튕긴다.
  • PR 의 CodeRabbit 지적을 처리했다. 아동 요금 항목을 하나라도 못 읽으면 아동 축 전체를 접는다. 표시 인원은 렌더 중 ref 갱신 대신 파생 상태로 든다. native select 를 Theme UI Select 로 바꾸라는 한 건은 src/stay 규약에 맞춰 두었다.

남긴 것 — 없다. 리뷰가 짚은 것 중 코드로 고칠 수 있는 것은 전부 이번 배포에 들어갔다. 데이터 점검 둘(옛 규칙 구간 코드, 박수 층 둘 이상인 좌표)은 7절 체크리스트에 있다.

8남긴 것

박수 층 규칙은 James 결정대로 이번 배포에 들어갔다. 날짜마다 층을 고르고 자격 없는 층은 마감한다. FIT 추가수집정보를 저장할 때 stayOccupancy 가 사라지던 것도 고쳤다. 코드로는 다 고쳤고 결정도 닫혔다. 유료 아동인데 조합 셀도 머릿수 셀도 없으면 판매 불가로 접는 선택은 James 가 9월 9일에 확인했다. 코드는 그대로다.
