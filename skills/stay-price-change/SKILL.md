# 가격 바꾸기 도우미

호텔 하나의 가격 캘린더 값을 담당자의 로그인된 크롬 탭에서 읽고, 미리보기를 보여 주고, 담당자가 "적용"이라고 한 뒤에만 저장한다. 저장 전 값과 넣은 값은 이 컴퓨터의 장부에 남아 되돌릴 수 있다. 담당자에게는 이 스킬을 **도우미**라고 부른다.

하는 일은 다섯이다. 1 지금 가격 보기 · 2 지금 상태만 저장 · 3 가격 바꾸기 · 4 되돌리기 · 5 새 요금표로 맞추기.

- 명령: 이 스킬 폴더의 `scripts/price_change.py`. 아래의 `python3 scripts/price_change.py …` 는 이 스킬 폴더에서 부르는 꼴이다. 다른 폴더에서는 `python3 "<이 스킬 폴더>/scripts/price_change.py" …` 처럼 절대 경로로 부른다(commands.md 「공통」). JSON 파일을 받고 JSON 을 낸다. 하위 명령·플래그·파일 모양·오류는 [references/commands.md](references/commands.md).
- 페이지: 탭에 올린 `window.stayPrice`. 부르는 값·답·오류는 [references/page.md](references/page.md).

## 반드시 지킬 것

- 담당자가 미리보기를 보고 분명히 "적용"(되돌리기는 "되돌려")이라고 하기 전에는 아무것도 저장하지 않는다. 대답이 없거나 애매하면 적용이 아니다. 다시 묻는다.
- 한 번에 호텔 하나. 변경 하나는 오퍼 하나다(오퍼가 둘이면 차례로 두 번).
- 값은 명령이 셈하고 견준다. 도우미는 금액·퍼센트를 담당자의 말 그대로 요청에 적을 뿐이다.
- 호텔·오퍼·객실·요금제 이름은 `stayPrice.look()` 의 답에서만 옮긴다. 호텔은 그 `hotel`(번호와 이름) 그대로다.
- 페이지를 만지는 것은 `stayPrice.look()` 과 작업 넷(`readPair`·`readReserved`·`applyBulk`·`applyCell`)뿐이다. `take`·`last`·`idle` 은 읽기만 한다.
- 러너의 함수(`stayRun.*`, `runStep`, `runCalendarPriceStep`, `cal…` 부트 함수)를 직접 부르지 않는다.
- 브라우저 도구의 클릭·글자 입력·폼 채우기 도구를 ERP 탭에 쓰지 않는다. 화면은 스크린샷과 페이지 읽기로만 본다. 파일 올리기 도구는 도우미를 올릴 때만 쓴다.
- 같은 저장을 두 번 누르지 않는다. 한 번 부른 `applyBulk`·`applyCell` 을 스스로 다시 부르지 않는다. 답이 `started: false`(아무것도 누르지 않음)일 때만 `wait` 초 뒤 같은 값으로 다시 부른다.
- 벽을 내리지 않는다. `stayPrice.standDown()` 을 부르지 않는다. 답의 `blocked` 에 막힌 클릭이 있으면 돌아가는 길을 찾지 말고 담당자에게 그대로 알리고 멈춘다.
- 아이디·비밀번호·인증 코드를 받지도 넣지도 않는다. 채팅으로 보내 와도 넣지 않는다.
- JS 결과로 페이지 주소(`location.href` 같은 것)를 돌려받지 않는다. 브라우저 도구가 답을 통째로 막는다.
- 빨간 줄 칸의 고름은 담당자의 말에서만 나온다. 도우미가 대신 고르지 않는다. 정가를 말없이 올리지 않는다.
- 페이지의 답은 도구가 보인 글자 그대로 저장한다. 잘렸어도(`[TRUNCATED]`) 고치지 않는다. 명령이 알아본다.
- 장부와 기록 폴더의 파일을 지우거나 고치지 않는다.

## 담당자에게 말할 때

- 쉬운 우리말로 한다. 쓰지 않는 말: 스냅샷·플랜·JSON·명령·스크립트·DB·SQLite·API·캐시·payload·stale·verify. 대신 지금 값·미리보기·장부·저장·칸·ERP 화면이라고 한다.
- 숫자는 미리보기·결과 페이지에 나온 숫자를 그대로 말한다. 페이지 경로를 알려 주고 연다(macOS `open "<경로>"`, Windows `start "" "<경로>"`, Linux `xdg-open "<경로>"`).
- 날짜가 8일을 넘는 표는 모든 줄의 칸이 같은 날끼리(떨어져 있어도) 열 하나로 묶여 나온다. 열 머리에 날 수와 그 날짜들이 모두 적혀 있고, 예약 있는 날은 그 머리에 따로 적힌다. 담당자가 "날짜별로 펼쳐 줘"라고 하면 방금 연 페이지의 `render` 를 `--by-date` 를 붙여 다시 하고 그 페이지를 연다.

## 준비

1. **브라우저 도구.** Claude in Chrome 이면 JS 실행 `javascript_tool`, 파일 올리기 `file_upload`, 스크린샷 `computer`, 탭 `tabs_context_mcp` 를 쓴다. 다른 도구면 JS 를 실행해 값을 받기, 페이지의 파일 칸에 파일 넣기, 스크린샷 셋이 되는지 먼저 본다.
2. **도우미 올리기.** 탭마다 한 번.
   1. JS 실행 도구로 `scripts/page/stay_price_loader.js` 의 내용 전체를 실행한다. 답은 `{ok: true, label: "stay price file bridge", …}`.
   2. 파일 올리기 도구로 접근성 이름이 **`stay price file bridge`** 인 파일 칸(`input#stay_price_bridge`)에 세 파일을 올린다: 러너의 `../stay-setup-run/scripts/stay_helper.js`, `../stay-setup-run/scripts/stay_boot.js`, 이 스킬의 `scripts/page/stay_price.js`. 이름이 다른 파일 칸(ERP 사진 칸, 러너의 `stay file bridge`)에는 올리지 않는다. 파일 올리기 도구는 Claude 를 연 폴더(처음 작업 폴더, `pwd`) 아래의 파일만 읽어서 스킬 폴더의 경로를 거절할 수 있다. 그러면 그 폴더에 `stay-price-upload/` 를 만들어 세 파일을 복사하고 거기서 올린다.
   3. `await stayPriceLoader.load()` 를 실행한다. `ok: true` 와 `helper`·`price` 판 번호(`0·15·0` 꼴)가 오면 됐다. 복사본을 썼으면 이제 `stay-price-upload/` 폴더를 지운다(페이지가 원본을 적어 두어 다시 쓰지 않는다). `올라온 파일에 없는 것` 이면 빠진 파일을 같은 칸에 올리고 다시 부른다.
   4. **이동 뒤**(새로 고침·로그인·다른 화면에 갔다 옴, 또는 작업 답이 `stayPrice is not defined`): 1 을 다시 하고 `stayPriceLoader.again()`. `적어 둔 원본이 없습니다` 면 2·3.
3. **어디인지 보기.** `await stayPrice.look()`.
   - `login: true` 면 멈추고 "크롬의 ERP 탭에서 직접 로그인해 주시고, ○○ 호텔 화면이 뜨면 알려 주세요". 돌아오면 2 의 「이동 뒤」와 3.
   - `호텔 번호를 찾지 못했습니다` 면 "크롬의 ERP 탭에서 ○○ 호텔의 Stay 화면을 열어 주세요". 도우미는 ERP 주소를 모른다.
   - `hotel.name` 이 말한 호텔이 아니면 "지금 탭에는 △△ 호텔이 열려 있습니다. ○○ 호텔 화면을 열어 주세요."
   - `offers` 는 오퍼, `offer` 는 고른 오퍼, `pairs` 는 그 오퍼의 객실 · 요금제다. 다른 오퍼는 `stayPrice.look({offer: "<이름>"})`.
   - `pairs` 대신 `body` 가 오면(목록이 길다) 답을 `<작업>/look/look-1.json` 에 저장하고 `price_change.py look --answers <작업>/look`. 종료 2 의 `refetch` 는 「읽기」 5 처럼 받아 `<작업>/look/` 에 저장하고 다시 한다.
4. **장부 보기 · 작업 폴더.** `python3 scripts/price_change.py list` 를 한 번 본다.
   - 이 호텔(`hotel_id` 가 `look()` 의 `hotel.id`)의 `status: stopped` 인 변경이 있으면 다른 일보다 먼저 말한다. "장부 N번 '<sentence>'이 중간에 멈춰 있습니다(○월 ○일). 이어서 할까요, 된 것까지 되돌릴까요, 이대로 둘까요?" 고르면 「중간에 멈췄을 때」로 간다. 담당자가 다른 일을 먼저 하자고 하면 그 일을 한다.
   - `ledger` 가 든 폴더가 기록 폴더다(보통 `~/Documents/어딩 Stay 가격 변경 기록`). 이번 일의 파일은 `<기록 폴더>/작업/<YYYY-MM-DD HHMMSS>/`(아래 `<작업>`)에 둔다. 작업 폴더는 담당자가 시킨 일 하나(보기 · 저장 · 바꾸기 · 되돌리기 · 이어서)에 하나이고, 그 일의 읽기(미리보기 · 적용 직전 · 적용 뒤 · 멈췄을 때)는 모두 그 안의 `읽기-1`, `읽기-2` … 다. 같은 세션에서 방금 멈춘 변경을 이어서 하면 그 작업 폴더를 그대로 쓴다. 새 세션의 "N번 이어서", 되돌리기, 나중의 보기는 새 작업 폴더를 만든다.

## 읽기 — 네 일이 모두 이것으로 읽는다

브라우저 도구는 답을 1,000자쯤에서 자른다. 그래서 페이지는 읽은 화면(조각)을 페이지에 두고 답에는 짧은 머리만 싣는다. 머리의 `body` 는 그 조각을 알아볼 값이다. 명령은 앞선 읽기에서 이미 받은 같은 조각이면 그것을 쓰고, 어디에도 없는 조각만 받아 오라고(`refetch`) 한다. 읽기 한 번에 폴더 하나(`<작업>/읽기-1`, `읽기-2` …, 아래 `<R>`)를 쓴다. 아래 `<앞선>` 은 같은 호텔을 읽은 앞선 읽기 폴더마다 `--earlier <폴더>` 를 붙인 것이다. 어느 작업 폴더의 것이든 된다 — 「지금 상태 저장」 뒤에 바꾸기를 하면 그 저장의 `읽기-1` 도 준다. 같은 호텔의 읽기가 아직 없으면 없다.

범위는 처음에는 요청 파일(바꾸기 요청, 바꾸지 않으면 `kind: range` — commands.md 「요청 파일」)로, 장부 번호가 있는 일(적용 직전·뒤, 되돌리기, 이어서)은 `--record <번호>` 로 준다. 번호를 주면 장부가 그 번호를 계산할 때 읽은 범위를 그대로 다시 읽는다.

1. `python3 scripts/price_change.py read-calls --request <요청 파일> --out <R>/calls.json`(또는 `--record <번호>`).
2. **가격.** `calls.json` 의 `pairs` 값마다(i = 1, 2 …) `await stayPrice.readPair(<값 그대로>)` 의 답을 `<R>/pair-<i>.json` 에 저장한다. 조각은 아직 받지 않는다.
3. **예약 있는 날.** `price_change.py reserved --calls <R>/calls.json --answers <R> <앞선>` 의 `ask` 값마다(n 은 이어서 1, 2 …) `await stayPrice.readReserved(<값 그대로>)` 의 답을 `<R>/resv-<n>.json` 에 저장한다. `done: true` 까지 되풀이한다. `failed` 가 있으면 멈추고 그 `error` 를 page.md 에서 찾는다.
4. **지금 값으로 묶기.** `price_change.py read --calls <R>/calls.json --answers <R> <앞선> --out <R>/snapshot.json`.
5. **조각 받기.** 3·4 의 명령이 종료 2 에 `refetch` 를 내면 그 `{id, at, size}` 마다 `stayPrice.take("<id>", <at>, <size>)` → `<R>/take-<id>-<at>.json`, 답의 `next` 가 `end` 가 될 때까지 `stayPrice.take("<id>", <next>)` 를 한 쪽씩 이어 받고, 그 명령을 다시 한다. 가격 조각도 예약 있는 날의 조각도 이렇게 받는다. 잘려서 `next` 가 안 보이면 그대로 저장하고 명령을 다시 한다(명령이 더 작은 크기를 댄다).
   - `그 조각이 페이지에 없습니다` 면 새 폴더로 처음부터 다시 읽는다. 그 밖의 오류는 commands.md.

답이 `started: false` 면 아무것도 하지 않은 것이다. 저장하지 않고 `wait` 초 뒤 같은 값으로 다시 부른다.

## 1. 지금 가격 보기

1. 오퍼·객실·요금제·기간 가운데 말이 없는 것을 묻는다. 고를 이름은 `look()` 의 답에서 보여 준다. 범위가 크면(호텔 전체, 몇 달) "읽는 데 시간이 꽤 걸립니다"라고 먼저 말한다.
2. `<작업>/range.json`(`kind: range`)을 쓰고 「읽기」 → `<R>/snapshot.json`.
3. `save-snapshot --snapshot <R>/snapshot.json --sentence "<담당자 말>"` → 장부 번호 S. 문장은 담당자의 말 그대로다. 말이 "응 저장해"처럼 무엇을 적었는지 알 수 없으면 읽은 범위를 쓴다: "<오퍼> · <객실 · 요금제> · <날짜> 지금 상태".
4. `render prices --snapshot <R>/snapshot.json` → `page` 를 연다.
5. "○시 ○분에 ERP 에서 읽은 지금 가격입니다. 아무것도 바꾸지 않았습니다. 장부 S번에 적어 두었습니다." ○시 ○분은 지금 값의 `read_at`(ERP 에서 읽은 시각)이다.

## 2. 지금 상태만 저장

말한 범위만 저장한다. "호텔 전체"면 시간이 걸린다고 먼저 말하고 한다. 1 의 1~3 을 하고 이렇게 말한다(○시 ○분은 ERP 에서 읽은 시각 `read_at` — 장부 목록에서 이 번호의 상태는 `saved`). "지금 값을 장부 S번(○시 ○분)으로 적어 두었습니다. 나중에 'S번 상태로 되돌려'라고 하시면 그 값으로 되돌리는 미리보기를 보여 드립니다."

## 3. 가격 바꾸기

**묻고 확인한다.** 빠진 것(호텔·오퍼·객실·요금제·기간·요일·바꾸는 값과 금액)은 묻는다. 그다음 아래 꼴로 보여 주고, 담당자가 "응"·"맞아"처럼 분명히 답한 뒤에 읽는다. 스스로 채운 것은 괄호로 밝힌다.

```
이렇게 이해했습니다. 맞으면 지금 가격을 읽어 미리보기를 만들겠습니다.
호텔 데모 호텔
오퍼 기본 오퍼 (오퍼가 여럿이라 이것으로 골랐습니다)
객실 · 요금제 디럭스(조식 포함 · 룸온리), 스위트(조식 포함 · 룸온리) (말씀이 없어 전부)
날짜 2026-12-20 ~ 2027-01-05 의 금·토 → 12/25, 12/26, 1/1, 1/2 (4일)
바꾸는 값 판매가 +10% (어느 값인지 말씀이 없어 판매가로 했습니다 · 정가 · 공급 원가는 그대로)
칸 모든 인원 조합 · 모든 박수 (말씀이 없어 전부)
"연말"을 12/20 ~ 1/5 로 읽었습니다. 다르면 알려 주세요.
```

- 퍼센트면 한 줄을 더한다. "아동이 있는 칸은 ERP 와 똑같이 성인 몫에만 곱하고 아동 추가분은 그대로 둡니다. 아동 추가분도 같이 바꾸려면 말씀해 주세요." 같이 바꾸라고 하면 `scale_child_surcharge: true`.
- 새 값("350 으로")이면 어느 인원 조합의 1박 칸을 그 값으로 하는지(보통 성인 2) 밝히고, 다른 칸은 지금 차이를 그대로 둔다고 말한다.
- "성인 2만", "1박만"처럼 칸을 좁히면 요청의 `occupancies`(성인 2 는 `A2`)·`nights`(1박은 `1`)에 적고 「칸」에 그렇게 쓴다. 새 값이면 기준 칸(그 인원 조합의 1박)이 그 안에 있어야 한다.
- 짧은 표(확인 상자에서 다시 읽어 볼 만한 몇 칸)를 붙여 넣으면 칸마다의 숫자를 그대로 목표 값 표(`kind: targets`)에 옮긴다. 줄마다 다른 "+금액"이면 줄마다 따로 변경한다.
- 표에 인원 조합 · 박수가 없으면 목표의 `occupancy`·`nights` 를 빼고 적는다. 확인 상자의 「칸」에는 "표에 인원 · 박수가 없어, 그 객실 · 요금제에 줄이 하나뿐이면 그 줄에 넣습니다(어느 줄인지 미리보기 머리에 나옵니다)"라고 쓴다. 줄이 여럿이면 `plan` 이 고를 줄을 대며 거절한다. 그 줄들을 담당자에게 보여 주고 고른 줄을 적어 다시 한다.

**읽고 미리보기.**

1. `<작업>/request.json` 을 쓴다(commands.md 「요청 파일」). 이것을 범위 파일로 「읽기」 → `<R>/snapshot.json`.
2. `plan --snapshot <R>/snapshot.json --request <작업>/request.json --record --out <작업>/plan-1.json` → `change_id`(N)·`counts`·`unresolved`·`steps`. 계산 파일은 기록이라 다시 쓰지 않는다. 그 작업에서 k 번째 계산은 `<작업>/plan-<k>.json` 이다(명령이 있는 파일을 덮어쓰지 않는다).
3. `render preview --plan <작업>/plan-<k>.json` → `page` 를 연다.
4. "미리보기를 열었습니다. 아직 아무것도 바뀌지 않았습니다." 그리고 `counts` 로 바뀌는 칸(`will_change`)·적용할 수 없는 칸·예약 있는 날의 칸·판매 마감인 칸·새로 생기는 칸 수를 말한다(0 인 것은 뺀다). 예약 있는 날도 바꾸고 이미 받은 예약의 금액은 그대로라는 것, 마감인 날은 값만 바뀌고 마감은 그대로라는 것, 새로 생기는 칸은 되돌려도 지울 수 없다는 것을 해당될 때 말한다. 표에 인원 · 박수가 없던 목표 값 표면 미리보기 머리의 「칸」(예: 성인 2 · 1박)으로 어느 줄에 넣는지 말한다. 그다음은 빨간 줄에 따라 다르다.
   - **빨간 줄이 남아 있으면**(`counts.red` 가 0 보다 큼, `steps` 가 null) 저장 횟수는 아직 정해지지 않았다. 저장 횟수를 말하지 않고, 규칙마다(`unresolved` 의 `verdict` 로 센다) 고를 것을 말한다: "빨간 줄 ○칸은 어떻게 할지 골라 주셔야 합니다. 정가보다 비싸지는 ○칸 — 정가도 같은 만큼 올림 / 정가 지움 / 그 칸은 안 바꿈. 고르시면 미리보기를 다시 보여 드리고, 그때 몇 번 나눠 저장하는지 말씀드립니다." 아래 「빨간 줄」로 간다.
   - **빨간 줄을 다 골랐거나 없으면**(`counts.red` 가 0, `steps` 가 있음) 저장 횟수(`steps` 수)를 말한다. 고른 빨간 줄(`counts.chosen`)이 있으면 고름마다(`counts` 의 `raise_list`·`clear_list`·`keep`·`include`, 0 인 것은 뺀다) 무엇이 바뀌는지 말한다: "정가를 넘는 ○칸은 정가도 같은 만큼 올립니다(미리보기 표의 「정가 … → …」)" · "○칸은 정가를 지웁니다" · "○칸은 바꾸지 않습니다" · "○칸은 그대로 바꿉니다". 그리고 "맞으면 '적용'이라고 해 주세요."

**적용할 수 없는 칸**(`counts.blocked`)은 저장하지 않는다. "이 ○칸은 ERP 가 받지 않는 값이라 바꿀 수 없습니다(까닭). 그 칸도 바꾸려면 금액을 바꿔 다시 말씀해 주세요." 나머지만 적용하는 것은 담당자가 그것을 알고 "적용"하면 된다.

**빨간 줄**(`unresolved` 가 있음, `steps` 가 null)은 담당자가 그 칸을 다시 짚어 고른 뒤에만 들어간다.

| 빨간 줄 | 고를 수 있는 것 (`rule` · `choice`) |
|---|---|
| 정가보다 비싸짐 | 정가도 같은 만큼 올림 `ABOVE_LIST`·`raise_list` / 정가 지움 `clear_list` / 그 칸은 안 바꿈 `keep` |
| 공급 원가보다 싸짐 | 이대로 바꿈 `BELOW_COST`·`include` / 안 바꿈 `keep` |
| 30% 넘게 바뀜 | 이대로 바꿈 `OVER_30`·`include` / 안 바꿈 `keep` |

- 묶어서 말하면("정가 넘는 2칸은 정가 지우고") 그 규칙 전체, 칸을 짚으면 그 칸만(`cells`) 고른다. 말한 칸 수가 미리보기와 다르면 다시 묻는다. 30% 넘는 칸이 많으면 금액을 잘못 말한 것은 아닌지 먼저 묻는다(10% 를 100% 로 말한 것처럼).
- 고른 것을 `<작업>/choices-<k>.json` 에 적고 2 를 다시 한다: `plan --snapshot <R>/snapshot.json --request <작업>/request.json --resolutions <작업>/choices-<k>.json --replaces <N> --record --out <작업>/plan-<k>.json`(k 는 다음 계산 번호, N 은 바로 앞 미리보기의 번호). 새 번호가 이제 N 이다. 앞 번호는 장부에 `replaced`(바뀐 미리보기)로 남고 `begin` 이 받지 않는다. `unresolved` 가 비고 `steps` 가 있어야 적용할 수 있다.
- 고름과 "적용"을 한 번에 말했으면("정가 넘는 2칸은 정가 지우고 적용") 바로 「적용하기」로 간다. 고름만 말했으면 3 으로 미리보기를 다시 열고 "적용"을 기다린다.

## 4. 되돌리기

`python3 scripts/price_change.py list` 로 장부 목록(번호·종류·상태·호텔·요청 문장·적용 시각)을 본다. 상태가 `previewed`(미리보기만)·`replaced`(다시 계산해 바뀐 미리보기)인 줄은 저장한 적이 없어 되돌릴 것이 없다. "어제 바꾼 거"처럼 말하면 맞는 줄을 골라 확인받는다. 맞는 줄이 하나뿐이어도 묻는다. "이것 맞나요? 장부 12번 · 11/19 14:05 적용 · '연말 금·토 디럭스·스위트 10% 올려줘'". 담당자가 "응"·"맞아"처럼 분명히 답한 뒤에 읽는다. 종류가 `change`·`rollback` 이면 변경 되돌리기, `snapshot` 이면 저장해 둔 상태로 되돌리기다.

1. `read-calls --record <번호>` 로 「읽기」 → `<R>/snapshot.json`.
2. 되돌리기 계산. 일부만이면 고르기 플래그를 붙인다: `--room`·`--rate-plan`(여러 번)·`--from`·`--to`(날짜)·`--occupancy`(인원 조합 키를 읽은 값에서 골라서, 성인 2 는 `A2`).

   ```bash
   python3 scripts/price_change.py rollback --change <N> --snapshot <R>/snapshot.json --record --sentence "<담당자 말>" --out <작업>/rollback.json
   python3 scripts/price_change.py restore --saved <S> --snapshot <R>/snapshot.json --record --sentence "<담당자 말>" --out <작업>/rollback.json
   ```

   답의 `change_id` 가 이 되돌리기의 번호다.
3. `render rollback --plan <작업>/rollback.json` → `page` 를 연다. 그리고 말한다: "○월 ○일 ○시 ○분에 적어 둔 값으로 되돌립니다(`rollback.restore_to`)." 되돌리는 칸 수, 지울 수 없는 칸 수(가격이 없던 칸에 새로 생긴 칸, ERP 에 지우는 길이 없다), 예약 있는 날도 되돌리고 이미 받은 예약의 금액은 그대로라는 것. 그대로 두는 칸(`rollback.kept`, 그 사이 값이 달라진 칸)이 있으면 반드시 그 수와 까닭을 말한다. 칸마다 적어 둔 값 · 도우미가 넣은 값 · 지금 값은 페이지에 있다.
4. "되돌려" → 「적용하기」(이 되돌리기의 번호, 계산 파일 `rollback.json`). "○칸도 포함해서 되돌려"면 2 의 `rollback` 을 `--include-kept` 를 붙여 다시 하고, 새 번호로 「적용하기」.

## 5. 새 요금표로 맞추기

담당자가 호텔의 새 요금표(엑셀 · PDF 같은 파일, 객실 × 시즌 × 인원)를 주며 ERP 가격을 거기에 맞추라고 하면, 길을 말하지 않았을 때 두 길을 한 줄씩 말하고 고르게 한다. 계약이 바뀐 요금표면 (가)를 권한다.

- "(가) 시즌 원판 바꾸기 — ERP 시즌의 [가격]을 새 요금으로 다시 채웁니다. 계약이 바뀐 요금표라면 이쪽이 맞습니다. 이 길은 도우미가 아직 못 합니다. ERP 시즌 화면에서 직접 해 주세요." 도우미는 시즌 화면을 만지지 않는다.
- "(나) 날짜별 가격만 고치기 — 요금표를 날짜마다의 칸으로 펼쳐, 지금 값과 다른 칸만 바꿉니다. 여기서 날짜별로 바꾼 가격은 누가 ERP 시즌 화면에서 그 시즌의 [가격]을 '덮기'(이미 값이 있는 날도 덮기)로 다시 채우면 옛 요금으로 돌아갑니다."

(나)를 고르면 이렇게 한다. 몇 칸만 고치는 짧은 표는 이 길이 아니라 「3. 가격 바꾸기」의 목표 값 표다.

1. **준비.** 「준비」 1~4. `look()` 의 답을 그대로 `<작업>/look/look-1.json` 에 저장한다. 아래 `<look>` 은 그 파일이다. 답이 `pairs` 대신 `body` 로 왔으면 `price_change.py look --answers <작업>/look --out <작업>/look.json` 이 묶은 파일이 `<look>` 이다.
2. **요금표를 글로 읽기.** 이 스킬 옆에 `../stay-setup-guide/scripts/convert_contract.py` 가 있으면 `python3 ../stay-setup-guide/scripts/convert_contract.py "<요금표 파일>" -o <작업>/요금표.md` 로 글로 바꿔 읽는다. 없거나 실패하면 쓰는 환경이 할 수 있는 것(파일 읽기 · PDF 읽기 · 이미지 보기)으로 읽는다. 읽지 못한 숫자, 흐린 숫자, 뜻이 둘인 줄("주말"이 금·토인지 토·일인지, 아동 요금이 1박마다인지)은 짐작하지 않고 담당자에게 묻는다.
3. **요금표 파일 쓰기.** `<작업>/sheet.json` 을 commands.md 「요금표」대로 쓴다.
   - 요금표의 줄 하나가 파일의 줄 하나다(객실 · 요금제 · 시즌의 기간 · 요일). 시즌 이름은 `season` 에 요금표 글자 그대로 적는다.
   - 숫자는 요금표에 적힌 숫자만 옮긴다. 차이로 적힌 값("성인 추가 +60", "아동 +30", "싱글 -20", "3박 이상 -10%")은 셈하지 않고 차이 그대로(`from` 과 `add` 또는 `percent`) 적는다. 셈은 명령이 한다.
   - 객실 · 요금제 이름은 `<look>` 의 `pairs` 에서 고른다. 요금표의 이름과 어느 ERP 객실이 짝인지 모호하면 묻는다. 맞는 것이 없으면 요금표의 이름을 그대로 적는다(「호텔에 없는 객실 · 요금제」로 나온다).
   - 인원 조합 키는 성인 2 `A2` · 성인 3 `A3` · 인원 무관 `""` 이고, 박수는 1박 `1` · 3박 이상 `3` 이다. 아동 줄의 키 뒤쪽(`A2C1_CHD` 의 `CHD`)은 호텔마다 달라 읽은 값에서만 안다. 모르면 `A2C1` 로 적고 7 에서 맞춘다.
   - `currency` 는 요금표에 적힌 통화다.
4. **확인.** `python3 scripts/price_change.py sheet --sheet <작업>/sheet.json --look <look> --out <작업>/sheet-check.json`. 종료 2 면 그 문장대로 한다(commands.md 「오류와 할 일」). 옮겨 적다 틀린 것(없는 줄을 가리킴 · 고리 · 기간)은 고치고, 요금표 자체가 어긋나면(두 줄이 한 칸에 다른 값) 담당자에게 묻는다.
5. **이렇게 읽었다고 보여 주기.** `render sheet --plan <작업>/sheet-check.json` → `page` 를 연다. "요금표를 이렇게 읽었습니다. 종이 요금표와 한 줄씩 견주어 보시고, 맞으면 '맞아'라고 해 주세요. 아직 ERP 에서 아무것도 읽지 않았습니다." 답의 `gaps` 가 있으면 말한다: 호텔에 없는 객실 · 요금제(`unknown`, 넣지 않음)와 요금표에 없는 객실 · 요금제(`unnamed`, 그대로 둠). 담당자가 "맞아"처럼 분명히 답하기 전에는 읽지 않는다. 고치라고 하면 3 으로 돌아간다.
6. **읽을 범위 · 나누기.** 읽기는 요금표의 객실 · 요금제(호텔에 있는 것) × 첫 날부터 끝 날까지 모든 날이다. 요금표가 비운 날도 읽어 그대로 둘 칸을 댄다. 1년짜리면 객실 · 요금제마다 가격 읽기(`readPair`) 2번(186일에 한 번)과 호텔 전체로 예약 있는 날 읽기(`readReserved`) 1번(550일에 한 번, 숨은 줄이 있으면 쪼개져 늘어난다), 그리고 읽은 화면 조각마다 받기(`take`, 800자에 한 번)다. 읽기 한 번은 가격 읽기와 예약 있는 날 읽기를 합쳐 40번까지라(페이지가 화면 조각을 40개까지만 둔다) 1년짜리는 객실 · 요금제 19개까지 한 번에 읽는다. 바꾸기 한 번은 이 읽기를 세 번 한다(미리보기 · 적용 직전 · 적용 뒤). 범위가 크면 "읽는 데 시간이 꽤 걸립니다"라고 먼저 말한다.
   - 이 수는 예약 있는 날 읽기가 쪼개지기 전의 것이다. 요금표를 읽다가 `그 조각이 페이지에 없습니다` 가 나면 같은 범위로 다시 읽지 말고 아래처럼 나눈다(예약 읽기가 쪼개져 조각이 40개를 넘었다).
   - 답의 `reads.fits` 가 false 이거나 담당자가 나눠 하자고 하면 한 부분씩 한다. 객실 하나는 4 를 `--room <객실>` 을, 시즌 하나는 `--from <시작일> --to <종료일>` 을 붙여 `<작업>/sheet-check-<n>.json` 으로 다시 하고, 그 부분마다 7 부터 「적용하기」까지 한다. 부분마다 장부 번호가 따로다.
7. **읽고 넣지 않는 것 말하기.** `<작업>/sheet-check.json`(나눴으면 그 부분의 파일, 아래도 같다)을 범위 파일로 「읽기」 → `<R>/snapshot.json`. `plan --snapshot <R>/snapshot.json --request <작업>/sheet-check.json --record --out <작업>/plan-1.json`.
   - 미리보기를 열기 전에 답의 `coverage` 를 말한다(목록은 `plan.coverage`, 0 인 것은 뺀다): "요금표에 없는 칸 ○칸은 그대로 둡니다 · 이 객실 · 요금제에 없는 인원 조합 · 박수 ○칸은 만들지 않습니다 · 판매일 없는 날 ○일은 넣을 수 없습니다 · 호텔에 없는 객실 · 요금제 ○개 · 요금표에 없는 객실 · 요금제 ○개는 그대로 둡니다." 어느 칸인지는 미리보기의 「요금표가 넣지 않는 것」에 있다고 말한다.
   - `unseen` 이 이름만 다른 것으로 보이면(요금표의 `A2C1`, 읽은 값의 줄은 `A2C1_CHD`) 두 이름을 보여 주고, 담당자가 같다고 하면 요금표 파일의 키를 고쳐 4 와 `plan` 을 다시 한다. 인원 조합은 읽을 범위를 바꾸지 않으므로 다시 읽지 않는다.
   - 통화가 다르다는 거절이면 멈추고 담당자에게 묻는다. 바꿔 셈하지 않는다.
8. **미리보기.** `render preview --plan <작업>/plan-<k>.json` → `page` 를 연다. 「3. 가격 바꾸기」의 「읽고 미리보기」 4 처럼 수를 말하고, 이 문장을 꼭 붙인다: "여기서 날짜별로 바꾼 가격은 누가 ERP 시즌 화면에서 그 시즌의 [가격]을 '덮기'(이미 값이 있는 날도 덮기)로 다시 채우면 옛 요금으로 돌아갑니다."
9. 그다음은 「3. 가격 바꾸기」와 같다. 빨간 줄은 고른 뒤 7 의 `plan` 을 `--resolutions <작업>/choices-<k>.json --replaces <N>` 을 붙여 `--out <작업>/plan-<k>.json` 으로 다시 하고(`--request` 는 같은 `sheet-check.json`), "적용"이면 「적용하기」. 결과를 말할 때도 8 의 문장을 붙인다.

## 적용하기 — 바꾸기·되돌리기 공통

필요한 것: 장부 번호 N, 그 번호를 낸 계산 파일(`plan-<k>.json` 또는 `rollback.json`).

1. **직전에 다시 읽고 시작하기.** `read-calls --record N` 으로 「읽기」 → S2. `begin --change N --plan <계산 파일> --snapshot S2`. `begin` 이 S2 를 미리보기 때 읽은 값과 견준다.
   - 종료 1(`same: false`)이면 아무것도 시작하지 않았다. "적용 직전에 ERP 를 다시 읽었더니 미리보기 때와 다른 칸이 ○칸 있어 아무것도 바꾸지 않았습니다. 새 미리보기를 보여 드립니다." S2 로 계산을 다시 하고(`plan` 은 `--replaces N --record --out <작업>/plan-<k>.json`, 되돌리기는 `rollback`/`restore` 를 `--record`) 미리보기부터 다시 한다. 빨간 줄도 다시 고른다.
   - `…분 전 것입니다` 면 읽은 지 15분이 지났다. 1 을 다시 한다.
   - `status: applying` 이면 "적용 직전에 ERP 를 다시 읽었습니다. 미리보기 때와 모든 칸이 같아서 그대로 적용합니다."
2. `calls --change N` 의 `calls` 를 차례로 하나씩 한다.
   - `op` 가 `applyBulk` 면 `await stayPrice.applyBulk(<payload 그대로>)`, `applyCell` 이면 `await stayPrice.applyCell(<payload 그대로>)`.
   - 답을 그대로 `<작업>/적용-N/<no>.json` 에 저장하고 `record-result --change N --result <그 파일>`.
   - `started: false` 면 아무것도 누르지 않았고 장부에도 적히지 않았다. `wait` 초 뒤 같은 payload 로 다시 부르고 다시 `record-result`.
   - `saved: true` 이고 `status: applying` 이면 다음으로, `status: applied` 면 3 으로 간다. 그 밖(저장이 안 됐거나 `status: stopped`)이면 다음 저장을 하지 않고 「중간에 멈췄을 때」로 간다. 15분 동안 아무 일이 없던 변경은 그 뒤 저장이 돼도 멈춘 채로 적힌다.
   - JS 호출이 답 없이 끊겼거나 답이 잘렸으면 `stayPrice.last()` 로 그 답을 받는다(`running` 이면 10초 뒤 다시). 같은 작업을 다시 부르지 않는다.
3. **뒤에 다시 읽기.** 다 저장되면 `read-calls --record N` 으로 「읽기」 → S3. `verify --change N --snapshot S3`.
4. `render result --change N` → `page` 를 연다.
   - `same: true` 면 "적용했고, 다시 읽어 확인했습니다. 손님 화면에는 길어야 5분 안에 새 가격이 보입니다. 이미 받은 예약의 금액은 그대로입니다. 되돌리려면 'N번 되돌려'라고 하세요."
   - `same: false`(종료 1)면 "적용했지만 다시 읽었더니 ○칸이 넣은 값과 다릅니다. 페이지의 빨간 칸을 ERP 에서 확인해 주세요." 다시 저장하지 않는다.

## 중간에 멈췄을 때

멈춘 변경은 저장이 실패했거나, 저장됐는지 모르거나(「모름」), 세션이 끊겨 15분 동안 아무 일이 없던 변경이다. 장부가 그렇게 가리고, 다시 읽어 `check` 가 이어서 해도 된다고 하기 전에는 `calls` 가 남은 저장을 내지 않는다.

여기로 오는 길은 셋이다. 적용하다 멈췄을 때, 담당자가 "N번 이어서"라고 할 때, 「준비」 4 에서 이 호텔의 멈춘 변경을 알렸을 때. 새 세션이면 「준비」 1~4 를 하고 새 작업 폴더에서 한다. 장부 번호 N 만 있으면 된다.

1. `read-calls --record N` 으로 「읽기」 → S4. `check --change N --snapshot S4`.
   - 저장마다 `seen` 이 `saved`(됨)·`not_saved`(안 됨)·`mixed`(섞임)·`changed`(그 사이 바뀜)다. `saved: "unknown"`(단추는 눌렸고 저장됐는지 모름)이던 저장은 읽은 값으로 가려져 장부에 적힌다(`settled`).
   - `status` 가 `applied` 면 다 저장된 것이다. 「적용하기」 3 으로 간다.
   - `last_saved` 는 마지막으로 저장된 단계, `next` 는 다음에 할 단계다(`{no, label}`, 없으면 null). `cause` 는 멈춘 까닭이다: `failed` 저장이 실패함(`note` 가 그 까닭) · `unknown` 저장 단추는 눌렸고 저장됐는지 몰랐음 · `cut_off` 실패한 저장 없이 중간에 끊김.
   - `can_continue` 는 남은 저장(`remaining`)을 계획대로 해도 되는지, `why` 는 안 되는 까닭이다.
2. `render result --change N` 을 열고 말한다.
   - `cause: cut_off` 면 "○번째 저장(`last_saved`)까지 하고 끊겼습니다. 저장이 실패한 것은 아닙니다. 지금은 일부만 바뀐 상태입니다." `last_saved` 가 null 이면 "첫 저장을 하기 전에 끊겼습니다. 아무것도 바뀌지 않았습니다."
   - 그 밖이면 "○번째 저장(`next`)에서 멈췄습니다(`note` 를 쉬운 말로). 지금은 일부만 바뀐 상태입니다."
   - 그리고 묻는다. "어떻게 할까요? 이어서 — 남은 ○번을 마저 적용합니다 / 된 것까지 되돌리기 — 이미 바뀐 ○번을 원래 값으로 되돌립니다(미리보기를 먼저 보여 드립니다) / 이대로 두기." 바뀐 것이 없으면 되돌리기는 빼고, `can_continue` 가 false 면 이어서는 빼고 `why` 를 쉬운 말로 전한다. 로그인이 풀린 것이면 먼저 로그인을 부탁한다(「준비」 3).
3. **이어서.** `stayPriceLoader.status()` 로 도우미가 살아 있는지 보고, `can_continue: true` 면 다시 읽지 않고 「적용하기」 2 부터 한다. 1 의 읽은 값에서 15분 안이면 `calls` 가 남은 저장을 낸다. `calls` 가 `멈춰 있습니다` 로 거절하면(담당자가 고르는 사이 15분이 지났다) 1 부터 다시 한다. `can_continue` 가 false 면 이어서 하지 않는다. `why` 를 알리고 '된 것까지 되돌리기'나 '이대로 두기'를 고르게 하고, 남은 부분은 새 변경으로 다시 말해 달라고 한다.
4. **된 것까지 되돌리기.** 「4. 되돌리기」를 그 번호로 한다. 저장된 단계만 되돌린다.
5. **이대로 두기.** "장부에 '중간에 멈춤'으로 남아 있습니다. 나중에 'N번 이어서'라고 하시면 이어서 합니다."
