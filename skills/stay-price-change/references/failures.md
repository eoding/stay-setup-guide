# 읽기 · 적용이 막힐 때

SKILL.md 가 이 파일을 여는 때: 「읽기」나 「적용하기」의 명령 · 페이지가 아래의 답을 냈을 때. 아래에 없는 명령 오류는 commands.md 「오류와 할 일」, 페이지 오류는 page.md 「오류와 할 일」에서 찾는다. 거기에도 없으면 멈추고 문장 그대로 보고한다.

놓치면 안 되는 것: **같은 저장을 두 번 누르지 않는다.** 한 번 부른 `applyBulk`·`applyCell` 은 스스로 다시 부르지 않는다(`started: false` 일 때만 `wait` 초 뒤 같은 값으로). 아무것도 시작하지 않은 채 미리보기를 다시 만들었으면 담당자의 "적용"을 다시 받는다.

## 읽기

- **`read-calls` 가 `이 범위는 읽기 한 번에 들지 않습니다`** — 아무것도 부르지 않았다. "한 번에 읽기에는 범위가 커서 객실(또는 기간)별로 나눠 하겠습니다"라고 말하고, 범위를 객실 · 요금제나 날짜로 나눠 나눈 것마다 따로 한다(읽기 · 장부 번호 · 페이지가 따로다).
- **읽기 작업(`look`·`readPair`·`readReserved`)의 답을 잃었다** — JS 호출이 답 없이 끊겼거나 답이 잘렸다. 둘 가운데 하나를 한다. 둘 다 된다.
  - `stayPrice.last()` 의 답을 같은 읽기 폴더에 **새 파일**로 저장한다(이름은 같은 머리 — `pair-<i>-다시.json`, `resv-<n>-다시.json`, `look-2.json`). `{running: …}` 이면 아직 도는 중이다. 10초 뒤 다시 받는다(그 답은 저장해 두어도 명령이 답으로 치지 않는다).
  - 같은 값으로 그 작업을 다시 부르고 그 답을 새 파일로 저장한다. 읽기는 아무것도 저장하지 않으니 다시 불러도 된다.
  - 잘린 답을 저장해 둔 파일은 그대로 둔다(기록 폴더의 파일은 고치거나 지우지 않는다). 명령은 잘린 읽기 답과 `{running}` 을 답으로 치지 않고, 한 물음에 온전한 답이 둘이면 늦게 끝난 것을 쓴다.
- **`reserved`·`read` 가 종료 2 에 `refetch`** — 「읽기」 5 의 조각 받기를 한다.
- **`그 조각이 페이지에 없습니다`** — 페이지가 바뀌었거나(이동 · 새로 고침) 조각이 밀려났다. 새 폴더로 처음부터 다시 읽는다. 같은 범위에서 또 나면 위의 「읽기 한 번에 들지 않습니다」처럼 나눈다.
- **`… 의 답에 끝난 시각(doneAt)이 없어 언제 읽었는지 모릅니다`** — 예전 판 페이지의 답이다. 「준비」 2 로 도우미를 다시 올리고 새 폴더로 처음부터 읽는다.
- **`reserved` 의 `failed`** — 멈추고 그 `error` 를 page.md 에서 찾는다.

## 적용

- **`begin` 이 종료 1(`same: false`)** — 아무것도 시작하지 않았다. "적용 직전에 ERP 를 다시 읽었더니 미리보기 때와 다른 칸이 <`differences` 의 수>칸 있어 아무것도 바꾸지 않았습니다. 새 미리보기를 보여 드립니다." 적용 직전에 읽은 값(S2)으로 계산을 다시 하고(`plan` 은 `--replaces N --record --out "<작업>/plan-<k>.json"`, 되돌리기는 `rollback`/`restore` 를 같은 고르기 플래그로 `--replaces N --record --out "<작업>/rollback-<k>.json"`) 미리보기부터 다시 한다. 빨간 줄도 다시 고른다. 새 미리보기에 담당자가 다시 "적용"(되돌리기는 "되돌려")이라고 해야 적용한다.
- **`begin` 이 `…분 전 것입니다`** — 적용 직전에 읽은 값이 15분보다 오래됐다(읽은 시각은 페이지 작업이 끝난 때다). 「적용하기」 1 의 읽기를 다시 한다.
- **저장 답이 `started: false`** — 아무것도 누르지 않았고 장부에도 적히지 않았다. `wait` 초 뒤 같은 payload 로 다시 부르고 다시 `record-result`.
- **저장 호출이 답 없이 끊겼거나 답이 잘렸다** — `stayPrice.last()` 로 그 답을 받는다(`running` 이면 10초 뒤 다시). 같은 저장을 다시 부르지 않는다. 받은 답을 `<작업>/적용-N/<no>.json` 에 저장하고 `record-result`.
- **`record-result` 가 저장이 안 됐다고 하거나 `status: stopped`** — 다음 저장을 하지 않는다. [stopped.md](stopped.md) 로 간다. 15분 동안 아무 일이 없던 변경은 그 뒤 저장이 돼도 멈춘 채로 적힌다.
- **`calls` 가 `…번 변경은 멈춰 있습니다`** — [stopped.md](stopped.md). 다시 읽어 `check` 가 이어서 해도 된다고 하면 `calls` 를 다시 부른다.
- **`verify` 가 종료 1(`same: false`)** — "적용했지만 다시 읽었더니 <`mismatches` 의 수>칸이 넣은 값과 다릅니다. 페이지의 빨간 칸을 ERP 에서 확인해 주세요." 다시 저장하지 않는다.
