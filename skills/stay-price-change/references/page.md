# 페이지 쪽 — 올리기 · 보기 · 작업 · 답 · 오류

차례: 올리기 · 보기와 작업 · 답의 모양 · 오류와 할 일

## 올리기

| 부르는 것 | 답 |
|---|---|
| `scripts/page/stay_price_loader.js` 전체 실행 | `{ok: true, bridge: "stay_price_bridge", label: "stay price file bridge", want: ["stay_helper.js", "stay_boot.js", "stay_price.js"]}`. 파일 칸은 1px · 거의 투명이라 화면에 안 보이지만 접근성 트리에 그 이름으로 있다 |
| (파일 올리기 도구) 그 칸에 세 파일 | 한 번에 셋이든 하나씩이든 모인다. 이름이 `stay_helper.js`·`stay_boot.js`·`stay_price.js` 인 파일만 고른다 |
| `await stayPriceLoader.load()` | `{ok, label, helper, price, stored, loaded}`. 세 파일을 도우미 → 부트 → 가격 도우미 차례로 실행하고 `stayPrice…` 키 셋에만 적어 둔다. 러너의 키(`stayHelperSrc`·`stayBoot`·`staySteps`·`stayRunCursor`)는 읽지도 쓰지도 않는다. 올라온 파일이 설치된 것과 다르면 아무것도 실행하지도 적지도 않고 `{ok: false, wrong: ["stay_price.js"], error: "올라온 파일이 설치된 도우미의 것과 다릅니다: stay_price.js — 올린 폴더에 남은 예전 복사본일 수 있습니다. …"}` |
| `stayPriceLoader.again()` | 이동 뒤에 적어 둔 원본을 같은 차례로 다시 실행한다. 원본이 없으면 `적어 둔 원본이 없습니다`. 적어 둔 원본이 설치된 것과 다르면(도우미를 새로 깔기 전에 적어 둔 예전 판) 아무것도 실행하지 않고 `{ok: false, wrong, error: "적어 둔 원본이 설치된 도우미와 다릅니다: … — … 세 파일을 다시 올립니다(load)"}` |
| `stayPriceLoader.status()` | `{ok, label, helper, price, stored}`. 올라 있는지 볼 때 |

**예전 판은 올리지 않는다.** 올리개는 설치된 세 파일의 알아볼 값(줄 끝을 맞춘 UTF-8 의 바이트 수 · CRC-32 · FNV-1a)을 안다. 도우미는 올리개를 늘 설치된 스킬에서 새로 붙여 넣으므로, 그 값과 다른 글자는 예전 판이다. 플러그인을 새로 깐 뒤에도 예전 탭이 예전 코드를 되살리지 않는다.

**페이지에 남기는 것.** 이 탭의 출처(ERP 주소)의 localStorage 에 `stayPrice` 로 시작하는 키 넷만 쓴다. 올리개가 적어 두는 원본 셋 `stayPriceHelperSrc`(러너의 도우미) · `stayPriceBootSrc`(러너의 부트) · `stayPriceSrc`(가격 도우미) — `again()` 이 다시 실행한다. 그리고 가격 도우미가 적는 `stayPriceLast`(마지막 작업의 답 · 도는 중이면 `{running}`) — `last()` 가 읽는다. 러너의 키(`stayHelperSrc`·`stayBoot`·`staySteps`·`stayRunCursor`)는 읽지도 쓰지도 않는다.

올리면 페이지에 벽이 선다. 작업이 도는 동안에는 그 작업의 허용 목록에 없는 클릭·폼 제출을 막고, 작업 밖에서는 스크립트가 만든 클릭을 막는다(사람이 직접 누른 클릭은 지난다). 같은 탭에서 러너(stay-setup-run)를 돌려야 하면 담당자에게 그 탭을 새로 고쳐 달라고 한다. 새로 고치면 도우미가 내려간다.

## 보기와 작업

한 번에 하나씩 `await` 로 부르고, 작업 넷의 값은 명령(`read-calls`·`reserved`·`calls`)이 낸 그대로 넣는다. 답의 `ask` 는 넣은 값의 지문이라 값을 바꾸면 명령이 그 답을 거절한다. 작업 하나는 45초 안에 화면이 정리된 뒤 답한다.

**누르기.** 페이지는 단추마다 누를 수 있을 때까지 기다린 뒤 한 번 누른다 — 화면에 있고, 막히지 않았고, htmx 가 연결했고(`data-htmx-powered`), 도는 요청이 없을 때. 저장 단추도 읽기 단추도 다시 누르지 않는다. 칩 · 오퍼 · 보기 · 탭 · 달 · 드로어 단계를 바꾼 뒤에는 바뀐 화면이 오고 요청이 끝난 뒤에 다음으로 간다. htmx 가 갈아 끼운 단추는 연결되기 몇 ms 전에 먼저 보이고, 그때 누르면 아무 일도 없다.

**호텔.** 페이지는 이 탭의 호텔을 페이지가 스스로 적어 둔 번호로 안다: 기본정보 폼의 숨은 칸 `#master_id` 와, [에이전트에 복사] 창의 문구 "ERP 호텔 <번호> (<이름>) 편집 화면"(`#stay_agent_resume`). 두 번호가 다르면 거절한다. 작업 넷의 값에는 언제나 `hotel`(`look()` 의 `hotel` 그대로)이 들고, 페이지는 무엇이든 누르기 전에 탭이 그 번호의 호텔인지 본다. 이름은 보여 주기만 한다(이름이 같은 호텔이 있다).

| 부르는 것 | 넣는 값 | 하는 일 |
|---|---|---|
| `stayPrice.look(v)` | 없음, 또는 `{offer}` | 이 탭이 어디인지. 로그인 화면이면 `{login: true}` 만. 아니면 `hotel`(`{id, name}`) · `offers`(캘린더의 오퍼) · `offer`(고른 오퍼) · `pairs`(그 오퍼의 객실 · 요금제 `[{room, rate_plan}]`, 캘린더 칩 이름 그대로). 누르는 것은 [가격 캘린더] 탭 · [룸별 입력] · (`offer` 를 주면) 그 오퍼 칩뿐이다. 목록이 길면 `pairs` 대신 `body` 와 `count` |
| `stayPrice.readPair(v)` | `{hotel, offer, room, ratePlan, from, to, weekdays}` | [선택 날짜 가격 수정]을 확인 단계까지 열어 지금 값을 읽고 닫는다. 저장 단추는 허용 목록에 없다. 판매일 없는 날은 읽지 않고 「판매일 없음」으로 알린다 |
| `stayPrice.readReserved(v)` | `{hotel, offer, rooms, ratePlans, from, to, weekdays, occupancy, nights}` | [선택 날짜 가격 가감]을 확인 단계까지 열어 「예약이 있는 날」을 읽고 닫는다. [가감 적용]은 누르지 않는다 |
| `stayPrice.applyBulk(v)` | `{no, hotel, offer, room, ratePlan, dates, rows}` | [선택 날짜 가격 수정] 저장 한 번. `dates` 는 겹치지 않는 오름차순 날짜이고 떨어져 있어도 된다 — 창의 숨은 날짜 구간 줄에 그 날들만 넣어 고른다(첫 날부터 끝 날까지 550일 안). 확인 단계가 그 오퍼 · 요금제 · 그 날들인지 본 뒤 칸을 치고, 저장 단추는 그 요금제 · 그 날짜 구간으로 연 창일 때 한 번만 눌린다 |
| `stayPrice.applyCell(v)` | `{no, hotel, offer, room, ratePlan, date, occupancy, nights, clear}` | 날짜 칸을 눌러 여는 셀 창 저장 한 번(정가 · 공급 원가 비우기). 연 창의 날짜 · 요금제 · 줄이 맞을 때만 |
| `stayPrice.take(id, at, size)` | 조각 id, 자리(0 부터), 크기(200~800, 기본 800) | 읽은 조각의 한 쪽. 페이지는 마지막 200개 조각만 둔다(읽기 한 번에 부를 수 있는 작업 수 — `read-calls` 가 그보다 큰 읽기를 거절한다) |
| `stayPrice.last()` | 없음 | 마지막 작업의 답. 아직 돌고 있으면 `{running: {op, no, at}}` |
| `stayPrice.idle()` | 없음 | 작업 밖 벽의 상태 `{idle, blocked, count}` |

`standDown()`·`standUp()`·`config()`·`guard()` 는 시험용이다. 이 도우미는 부르지 않는다.

## 답의 모양

작업과 `look()` 의 답(JSON 으로 800자 안). 페이지와 올리개의 답에서 점으로 이은 조각(글자·숫자·`_`·`-`) 셋 이상뿐인 글자는 점이 `·` 로 바뀌어 온다 — 브라우저 도구가 그 모양(`0.15.0`)을 토큰으로 보고 가리기 때문이다. 판 번호는 `0·15·0` 처럼 온다.

| 칸 | 뜻 |
|---|---|
| `op` · `no` · `ok` | 작업 이름 · 저장 번호(저장 작업만) · 됐는지 |
| `ask` | 넣은 값의 지문. 명령이 물음과 짝짓는다 |
| `started` · `wait` | `started: false` 면 지나가는 까닭(앞 작업이 아직 끝나는 중, 앞 화면이 아직 정리 중)으로 아무것도 누르기 전에 멈췄다. 실패가 아니다. `wait` 초 뒤 같은 값으로 다시 부른다 |
| `saved` | 저장 작업만. `true` 저장됨 · `false` 저장 안 됨 · `"unknown"` 단추는 눌렸고 저장됐는지 모름 |
| `pressed` · `refused` | 저장 단추를 눌렀는지 · 누르기 전에 스스로 거절했는지 |
| `body` | 읽기 작업과 긴 `look()` 만. `{id, chars, bytes, crc32, fnv}` — 조각 id 와 그 글자를 알아볼 값(글자 수 · UTF-8 바이트 수 · CRC-32 · FNV-1a). 명령이 `refetch` 로 댄 조각만 `take` 로 받는다. 조각 안에는 페이지가 알아본 `hotel` 이 든다 |
| `hotel` | `look()` 은 이 탭의 호텔 `{id, name}`. 다른 호텔이라 거절한 작업의 답에도 이 탭의 호텔이 든다 |
| `rest` · `warn` | 답할 때 화면(드로어 · 셀 창 · 요청)이 정리됐는지. 정리되지 않았으면 다음 작업이 `started: false` 로 기다릴 초를 알려 준다 |
| `what` · `days` · `note` | 무엇을 했는지 · 읽은 날 수(`asked`·`open`·`noSale`) · 메모 |
| `error` · `errors` | 까닭(200자 안) · 화면이 보인 오류 줄 |
| `clicks` · `blocked` · `blockedMore` | 누른 것 수 · 막은 클릭(처음 둘) · 더 막은 수 |
| `cut` | 800자를 넘어 꼭 필요한 칸만 남긴 답 |
| `ms` | 걸린 시간 |

`take` 의 답: `{op: "take", ok, id, at, size, next, end, bytes, crc32, text}`. `at`·`next`·`end` 는 쪽 번호가 아니라 글자 자리다. `next` 가 다음 자리, `end` 가 전체 길이다. `next == end` 면 끝.

`take` 의 `size` 는 받을 조각 글자 수가 아니라 **답 전체를 JSON 으로 쓴 글자 수**의 상한이다(브라우저 도구가 답을 자르지 않는 800자 안). 그래서 `text` 는 언제나 `size` 보다 짧다. 답의 다른 칸(`op` · `id` · `at` · `next` · `end` · `bytes` · `crc32` …)이 100자쯤을 먼저 쓰고, 따옴표 · 역슬래시 · 줄바꿈처럼 JSON 이 두 글자로 적는 글자는 두 글자로 세며, 끝이 아니면 조각을 마지막 `>` 나 `,` 바로 뒤에서 끊는다(끊은 자리에서 글자가 바뀌지 않게). 짧게 왔다고 잘린 것이 아니다 — 다음 쪽은 `next` 부터 받는다.

## 오류와 할 일

| 오류 (앞부분) | 뜻 · 할 일 |
|---|---|
| `stayPrice is not defined` · `러너의 도우미(stay_helper.js)와 부트(stay_boot.js)를 먼저 올려 주세요` | 페이지가 바뀌어 도우미가 내려갔다. 「준비」 2 의 이동 뒤 |
| `탭이 로그인 화면입니다` | 로그인이 풀렸다. 담당자에게 직접 로그인을 부탁한다(「준비」 3) |
| `이 탭에서 호텔 번호를 찾지 못했습니다` | 탭이 호텔의 Stay 편집 화면이 아니다. 「준비」 3 |
| `이 탭은 호텔 … 입니다 — 요청은 호텔 … 입니다` | 탭에 다른 호텔이 열려 있다. 아무것도 누르지 않았다. 저장 작업이면 장부에 멈춤으로 적힌다. 담당자에게 요청의 호텔 화면을 열어 달라고 하고, 「준비」 3 부터 다시 한다 |
| `이 탭의 호텔 번호가 화면 두 곳에서 다릅니다` | 화면이 어긋났다. 담당자에게 탭을 새로 고쳐 달라고 하고 「준비」 2 의 이동 뒤 |
| `` `hotel` 이 없습니다 `` | 넣은 값에 호텔이 없다. 명령이 낸 값을 그대로 넣는다 |
| `앞 작업(…)이 아직 끝나지 않았습니다` · `앞 화면(드로어·요청)이 아직 정리되지 않았습니다` | `started: false`. 아무것도 누르지 않았다. 답의 `wait` 초 뒤 같은 값으로 다시 부른다 |
| `셀 창이 열려 있습니다 — 사람이 닫은 뒤 다시 부릅니다` · `셀 창을 닫지 못했습니다` | 담당자에게 ERP 화면의 가격 칸 창을 닫아 달라고 한다 |
| `드로어를 닫지 못했습니다` | 몇 초 기다린다. 읽기 작업이면 다시 부른다. 저장 작업이면 장부에 적고 멈춘다 |
| `… 이 준비되지 않았습니다(…) — 누르지 않았습니다` · `… — 요청이 아직 끝나지 않았습니다` | 괄호 안의 까닭(화면에 없음 · 막힘 · htmx 가 아직 연결하지 않음 · 앞 요청이 끝나지 않음)으로 그 단추를 시간 안에 누르지 못했다. 그 단추는 누르지 않았다. 몇 초 기다린다. 읽기 작업이면 다시 부른다. 저장 작업이면 답의 `saved` 대로(저장 단추 앞에서 멈췄으면 `false`) 장부에 적고 멈춘다 |
| `[가격 캘린더] 탭을 찾지 못했습니다` · `가격 캘린더가 열리지 않았습니다` | 탭이 그 호텔의 Stay 편집 화면이 아니거나 로그인이 풀렸다. 「준비」 3 |
| `캘린더의 오퍼 칩에서 \`…\` 을 찾지 못했습니다` · `캘린더에 \`… · …\` 칩이 없습니다` · `캘린더에 오퍼 \`…\` 이 없습니다` · `드로어의 오퍼가 \`…\` 입니다` | 이름이 화면과 다르다. 아무것도 바뀌지 않았다. `look()` 으로 이름을 다시 받아 범위 파일을 고친다 |
| `드로어의 요금제가 \`…\` 입니다` | 객실 이름에 ` · ` 가 들어 객실과 요금제를 잘못 갈랐다. 드로어의 요금제 이름으로 요청의 `room`·`rate_plan` 을 고친다 |
| `\`weekdays\` 는 …` · `\`dates\` 는 겹치지 않는 오름차순 날짜 목록이어야 합니다` · `\`dates\` 가 …일에 걸칩니다` · `\`occupancy\` …` · `\`rows\` 가 비었습니다` | 넣은 값이 명령의 값과 다르다. 명령이 낸 값을 그대로 다시 넣는다 |
| `[선택 날짜 가격 수정] 이 기간을 거절했습니다 — …` | ERP 가 그 기간을 받지 않았다(판매일 없는 날이 끼는 등). 뒤의 화면 글을 담당자에게 전한다 |
| `드로어가 …` · `드로어의 날짜(…)가 물은 날짜(…)와 다릅니다` · `가감 확인 단계가 고른 것과 다른 범위를 보여 줍니다` | 화면이 물은 것과 다른 것을 열었다. 읽지도 저장하지도 않았다. 멈추고 보고한다 |
| `이 화면에는 [선택 날짜 가격 가감] 창이 없습니다` | 이 ERP 화면에는 예약 있는 날을 알아낼 창이 없다. 멈추고 보고한다 |
| `드로어 표에 없는 줄이나 칸이 있어 저장하지 않았습니다` · `넣은 값을 다시 읽으니 달라 저장하지 않았습니다` | 누르기 전에 거절했다(`refused`). 저장 안 됨. 장부에 적고 멈춘다 |
| `… 칸을 누를 수 없습니다(판매일이 없거나 이 달에 없는 날)` · `연 셀 창의 날짜(…)가 저장할 날짜(…)와 달라 아무것도 바꾸지 않았습니다` · `연 셀 창이 다른 요금제입니다` · `셀 창에 … 줄이 없어 저장하지 않았습니다` | 셀 창 저장을 누르기 전에 멈췄다. 저장 안 됨. 장부에 적고 멈춘다 |
| `셀 창이 저장을 거절했습니다 — …` | ERP 가 저장을 거절했다. 저장 안 됨. 화면 글을 전하고 멈춘다 |
| `저장 단추는 눌렸고 저장됐는지 알 수 없습니다` · `[저장] 은 눌렸고 저장됐는지 알 수 없습니다` · `저장 단추는 눌렸습니다. 저장됐는지 알 수 없으니 다시 읽어 확인합니다` | `saved: "unknown"`. 다시 부르지 않는다. SKILL.md 「중간에 멈췄을 때」(다시 읽고 `check`) |
| `시간(…초) 안에 끝나지 않아 멈췄습니다` | 시간 안에 못 끝냈다. `pressed` 가 없으면 저장 안 됨, 있으면 위의 「알 수 없음」 |
| `허용 목록에 없는 클릭을 막았습니다: …` · `허용 목록에 없는 클릭이 있어 멈췄습니다` | 벽이 막았다. 돌아가지 않는다. 막힌 것(`blocked`)을 담당자에게 알리고 멈춘다 |
| `그 조각이 페이지에 없습니다` | 페이지가 바뀌었거나(이동 · 새로 고침), 예약 있는 날 읽기가 많이 쪼개져 조각이 200개를 넘어 밀려났다. 새 폴더로 읽기를 다시 한다. 같은 범위에서 또 나면 객실 · 요금제나 날짜로 나눠 읽는다 |
| `자리(at)는 …` · `크기(size)는 200 부터 800 까지입니다` · `이 크기로는 한 글자도 담지 못합니다` · `이 자리에서 자르면 글자가 바뀝니다` | 같은 자리에서 크기를 바꿔(800 → 600 → 400) 다시 받는다 |
