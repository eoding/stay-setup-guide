# 중간에 멈춘 변경 — 다시 읽고, 묻고, 고른 대로

SKILL.md 가 이 파일을 여는 때: 적용하다 저장이 멈췄을 때, 담당자가 "N번 이어서"라고 할 때, 「준비」 5 에서 알린 이 호텔의 멈춘 변경을 담당자가 다루자고 할 때.

놓치면 안 되는 것: **다시 읽어 `check` 가 이어서 해도 된다고 하기 전에는 이어서 하지 않는다.** 같은 저장을 두 번 누르지 않는다. 고를 것은 `check` 뒤에 한 번만 묻는다.

멈춘 변경은 저장이 실패했거나, 저장됐는지 모르거나(「모름」), 세션이 끊겨 15분 동안 아무 일이 없던 변경이다. 장부가 그렇게 가리고, 다시 읽어 `check` 가 이어서 해도 된다고 하기 전에는 `calls` 가 남은 저장을 내지 않는다.

새 세션이면 「준비」 1~5 를 하고 새 작업 폴더에서 한다. 장부 번호 N 만 있으면 된다. 같은 세션에서 방금 멈춘 변경이면 다시 읽기 · `check` · 이어서는 그 작업 폴더를 그대로 쓴다(된 것까지 되돌리기는 4 — 새 작업 폴더).

## 1. 다시 읽고 `check`

`read-calls --record N` 으로 「읽기」 → S4(새 읽기 폴더 — 적용 직전의 읽은 값이나 앞선 폴더의 답을 다시 쓰지 않는다. `check` 는 장부가 그 번호에 마지막으로 적은 것 뒤에 읽은 값만 받고, 아니면 `… 뒤에 읽은 것이 아닙니다` 로 아무것도 가리지 않고 거절한다 — 새로 읽어 다시 한다). 그리고:

```bash
python3 scripts/price_change.py check --change N --snapshot "<S4>"
```

- `scope` 는 그 변경이 덮는 것(객실 · 요금제 · 날짜 · 한 일 · 저장 몇 번 중 몇 번) — 장부 목록의 줄과 같다. 담당자의 문장에 날짜가 없어도 이것으로 말한다.
- 저장마다 `seen` 이 `saved`(됨)·`not_saved`(안 됨)·`mixed`(섞임)·`changed`(그 사이 바뀜)다. `saved: "unknown"`(단추는 눌렸고 저장됐는지 모름)이던 저장은 읽은 값으로 가려져 장부에 적힌다(`settled`).
- `status` 가 `applied` 면 다 저장된 것이다. SKILL.md 「적용하기」 3 으로 간다.
- `last_saved` 는 마지막으로 저장된 단계, `next` 는 다음에 할 단계다(`{no, label}`, 없으면 null). 저장은 차례로 하므로 `last_saved.no` 가 이미 된 저장 횟수다. `remaining` 은 남은 단계 번호들이고 그 수가 남은 저장 횟수다.
- `cause` 는 멈춘 까닭이다: `failed` 저장이 실패함(`note` 가 그 까닭) · `unknown` 저장 단추는 눌렸고 저장됐는지 몰랐음 · `cut_off` 실패한 저장 없이 중간에 끊김 · `halted` 저장은 됐는데 ERP 가 다음 저장을 하지 말라고 함(시즌 창의 「공급 통화 없음」 띠 — `note` 가 그 글. record-result 가 그 저장 바로 뒤에 변경을 멈춘다).
- `can_continue` 는 남은 저장을 계획대로 해도 되는지, `why` 는 안 되는 까닭이다.

## 2. 페이지를 열고 한 번 묻는다

1 의 `check` 뒤에 `render result --change N` 의 `page` 를 연다 — 페이지는 장부에 적힌 그 `check` 대로 말한다(이어서 해도 된다고 했으면 이어서를 보이고, 안 된다고 했으면 이어서를 빼고 `why` 를 보인다. `check` 가 없으면 이어서 할 수 있는지는 다시 읽어 봐야 안다고 한다). 칸마다 저장한 칸은 「전 → 넣은 값 · 저장함」, 아직 저장하지 않은 칸은 「미리보기 때 값 → 넣을 값 · 아직 저장 안 함 · ○번째 저장」(눌렸는데 됐는지 모르던 저장이면 「저장됐는지 모름」), `check` 가 미리보기 뒤에 바뀌었다고 본 칸은 「미리보기 때 … · ○시 ○분에 다시 읽으니 … · 그 사이 ERP 에서 바뀜 · 넣지 않음」, 이 변경이 일부러 손대지 않는 칸만 「그대로」다. 다시 읽은 값은 그 `check` 때 ERP 에 있던 값이라 페이지도 도우미도 「지금」이라고 하지 않는다 — 말할 때도 「○시 ○분에 다시 읽었을 때 …」로 말한다(다른 날 연 페이지는 날짜도 붙인다). 저장 단계 목록에는 단계마다 됐는지와 칸 수가 있다.

**미리보기 뒤에 칸이 바뀌어 멈췄을 때**(`record-result` 가 `moved` 를 냈거나 `why` 에 「미리보기 때 읽은 값과 다릅니다」가 있다) 길은 둘이고 문장은 하나씩이다. <moved> 는 `steps` 에서 그 단계의 `moved` 다.

- 이 변경에서 아직 아무것도 저장하지 않았으면(`last_saved` 가 null): "미리보기 뒤에 ERP 에서 칸 <moved>개의 값이 바뀌어 아무것도 넣지 않았습니다. 지금 값으로 미리보기를 새로 만들어 보여 드립니다." 묻지 않고 6 「새 미리보기」로 간다.
- 앞 저장이 됐으면: "<`next.no`>번째 저장에서 멈췄습니다 — 미리보기 뒤에 ERP 에서 그 저장의 칸 <moved>개가 바뀌어 아무것도 넣지 않았습니다. 지금은 일부만 바뀐 상태입니다." 그리고 아래 물음을 한다(`can_continue` 가 false 라 이어서는 없다). 이 문장이 까닭을 이미 말했으니 `why` 의 「…미리보기 때 읽은 값과 다릅니다」는 다시 말하지 않는다. 새 미리보기는 만들지 않는다.

그 밖의 멈춤이면 말한다. 꺾쇠 자리는 `check` 의 답에서 옮긴다.

- `cause: cut_off` 이고 `last_saved` 가 있으면: "<`last_saved.no` — 단계 번호>번째 저장까지 하고 끊겼습니다. 저장이 실패한 것은 아닙니다. 지금은 일부만 바뀐 상태입니다."
- `cause: cut_off` 이고 `last_saved` 가 null 이면: "첫 저장을 하기 전에 끊겼습니다. 아무것도 바뀌지 않았습니다."
- `cause: halted` 면: "<`last_saved.no`>번째 저장까지 했는데 ERP 가 다음 저장을 하지 말라고 해 멈췄습니다(<`note` 그대로>). 지금은 일부만 바뀐 상태입니다. 이어서 하지 않습니다 — 된 것까지 되돌리거나 이대로 두고, 그 까닭(예: 기본정보의 통화)을 고친 뒤 새로 말씀해 주세요." `can_continue` 는 늘 false 다.
- 그 밖이면: "<`next.no` — 단계 번호>번째 저장에서 멈췄습니다(<`note` 를 쉬운 말로>). 지금은 일부만 바뀐 상태입니다."

그다음 고를 것을 묻는다. 이 물음은 여기서 한 번만 한다(「준비」 5 에서는 알리기만 했다).

"어떻게 할까요? 이어서 — 남은 저장 <`remaining` 의 수>번을 마저 적용합니다 / 된 것까지 되돌리기 — 이미 된 저장 <`last_saved.no`>번을 원래 값으로 되돌립니다(미리보기를 먼저 보여 드립니다) / 이대로 두기." 횟수가 하나면 「1번」 대신 「한 번」이다(페이지와 같은 말).

- 바뀐 것이 없으면(`last_saved` 가 null) 되돌리기는 뺀다.
- 멈춘 것이 되돌리기면(목록의 `kind: rollback`, 또는 범위 한 줄이 「…번 저장 상태로 되돌리기」) '된 것까지 되돌리기'의 「원래 값」은 「되돌리기 전 값」이다 — 되돌리기도 바꾸기처럼 되돌린다(rollback.md 「되돌리기를 되돌려 달라면」). 페이지도 그렇게 보인다.
- `can_continue` 가 false 면 이어서는 빼고 `why` 를 쉬운 말로 전한다. 다만 「미리보기 뒤에 칸이 바뀌어 멈췄을 때」의 문장으로 이미 말한 까닭(`why` 의 「…미리보기 때 읽은 값과 다릅니다」)은 다시 말하지 않고 남은 까닭만 전한다 — 남은 것이 없으면 `why` 는 말하지 않는다.
- 로그인이 풀린 것이면 먼저 로그인을 부탁한다(SKILL.md 「준비」 4).
- 대답이 없거나 애매하면 고른 것이 아니다. 다시 묻는다.

## 3. 이어서

`stayPriceLoader.status()` 로 도우미가 살아 있는지 보고, `can_continue: true` 면 다시 읽지 않고 SKILL.md 「적용하기」 2 부터 한다. 1 의 읽은 값에서 15분 안이면 `calls` 가 남은 저장을 낸다. `calls` 가 `멈춰 있습니다` 로 거절하면(담당자가 고르는 사이 15분이 지났다) 1 부터 다시 한다 — 다시 읽고 `check` 하고, 사정이 같으면 다시 묻지 않고 이어서 한다.

`can_continue` 가 false 면 이어서 하지 않는다. `why` 를 알리고 '된 것까지 되돌리기'나 '이대로 두기'를 고르게 하고, 남은 부분은 새 변경으로 다시 말해 달라고 한다.

## 4. 된 것까지 되돌리기

SKILL.md 「4. 되돌리기」를 그 번호로 한다 — 되돌리기 요청이라 「준비」 3 부터 새 작업 폴더에서 한다(rollback.md 와 같다. 앞 폴더의 조각은 명령이 빌린다). 「준비」 5 의 멈춘 변경 알림은 하지 않는다(지금 다루는 그 변경이다). 저장된 단계만 되돌린다.

## 5. 이대로 두기

`can_continue` 가 true 였으면: "장부에 '중간에 멈춤'으로 남아 있습니다. 나중에 'N번 이어서'라고 하시면 다시 읽어 확인하고 이어서 합니다." false 였으면: "장부에 '중간에 멈춤'으로 남아 있습니다. 남은 부분을 바꾸려면 새로 말씀해 주세요."

## 6. 새 미리보기

미리보기 뒤에 ERP 의 칸이 바뀌어 첫 저장 전에 멈춘 변경이다. 1 의 읽은 값(S4)으로 같은 요청의 새 미리보기를 만든다 — 바꾸기는 `plan --snapshot "<S4>" --request "<같은 요청 파일>" --record --out "<작업>/plan-<k>.json"`, 되돌리기는 `rollback`/`restore` 를 같은 고르기 플래그로 `--snapshot "<S4>" --record --out "<작업>/rollback-<k>.json"`. 새 번호로 SKILL.md 「3. 가격 바꾸기」의 「읽고 미리보기」 3 부터 한다(빨간 줄도 다시 고른다). 새 미리보기에 담당자가 다시 "적용"(되돌리기는 "되돌려")이라고 해야 적용한다. 장부의 앞 번호는 아무것도 바꾸지 않은 채 멈춤으로 남는다.

## 시즌 다시 채우기가 멈췄을 때

같은 길이다(1 다시 읽고 `check` → 2 묻기). 다른 것만 적는다.

- 시즌 창 저장 하나는 통째로 되거나 안 된다. 「모름」인 저장은 `check` 가 다시 읽은 값으로 가린다 — 넣으려던 칸이 모두 넣으려던 값이면 저장됨, 모두 전 값이면 저장 안 됨, 섞였으면 그 사이 다른 손이 탄 것이다. 시즌 창의 띠(`readSeason` 의 `banner`)가 남아 있으면 그것이 ERP 가 말한 칸 수다.
- `calls` 가 그 저장 직전에 다시 읽은 값이 미리보기 때와 달라 멈춘 변경(`stopped: true`)은 페이지가 누르기 전에 거절한 것과 같다 — 결과 페이지는 마지막 `check` 의 읽은 값으로 「그 사이 ERP 에서 바뀜」 칸을 보인다.
- 3 의 이어서는 저장마다 [season-fill.md](season-fill.md) 5 의 2 다 — 남은 저장도 그 범위를 다시 읽어 `calls --change N --snapshot` 으로 낸다(2분 안).
