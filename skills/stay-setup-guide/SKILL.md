# 호텔 세팅 입력 지시서 만들기

담당자가 읽는 문서가 아니라 **따라 치는** 문서를 만든다. "어디 들어가서 → 어느 탭/버튼 누르고 → 어느 칸에 무엇을 넣고(또는 비우고) → 저장"만 순서대로.
형식·순서·값 표기의 정본은 `references/MANUAL-SPEC.md`, 화면의 칸·옵션·버튼 정본은 `references/screen-dictionary.md`다. 이 두 파일과 다르게 쓰지 않는다.
여기서 만든 지시서는 짝 스킬 `skills/stay-setup-run` 이 화면에서 그대로 실행한다 — 아래 표기(단계 제목·`카드:` 줄·마지막 `→ [버튼]`)가 그 러너가 알아보는 형식이므로 글자 그대로 지킨다.

## 입력
1. 계약서 또는 요금표 파일(xlsx·xls·csv·pdf·docx·hwp·hwpx 등). `python3 scripts/convert_contract.py <파일> -o contract.md` 로 텍스트로 바꾼다(시트가 여럿이면 `## 시트명` 절, 숨긴 행·열은 제외). 필요한 파이썬 패키지(firecrawl-anydoc, rhwp-python, openpyxl)는 스크립트가 처음 한 번 현재 파이썬 환경에 스스로 설치한다(설치 전 안내 한 줄 출력, Node 불필요). 달러가 반올림돼 나오면 원본 셀 값을 사용자에게 확인한다.
2. 호텔 이름·도시·공급 통화·계약 주체(자사/거래처)·여행사 번호·**취소정책**은 시작할 때 사용자에게 한 번 묻는다. 취소정책은 계약서에 없으면 사용자가 정한 공용 정책 이름을 받아 두고, 오퍼의 `기본 취소 정책` 에 그 이름을 고른다 — `지정 안 함` 으로 지시서를 만들지 않는다. **공급 통화의 기본은 USD 다** — 계약서에 현지 통화(VND·JPY 등) 열이 있어도 사용자가 그 통화로 하자고 확인해 주기 전에는 USD 로 쓰고, 다른 통화를 쓰면 확인받은 내용을 `changes.md` 맨 위에 적는다. 도시는 공항코드(IATA 3자)까지 확정한다(`references/facts-guide.md` §도시 코드) — 지시서의 `도시` 값은 화면 항목 글자 그대로 `한글명(공항코드)` 다.
3. 사진은 사용자가 준비하거나(호텔 사진팩) 공식 사이트에서 받는다. 파일명 규칙은 규칙서 §사진 단계. **사진의 저작권·사용 허락 확인은 사용자 책임**이며, 마지막 보고와 `changes.md` 첫 줄에 그 사실을 적는다.

## 절차
1. **룰 정리** — 계약서에서 룸 목록, 기준·최대 인원, 시즌(날짜 규칙), 요금제, 가격표, 부과금(호텔이 물리는 돈), 부가옵션(고객이 골라 사는 것), 프로모션, 취소 규정, 혜택을 `rules.md` 로 뽑는다. 계약서에 없는 값은 지어내지 않는다.
2. **팩트 수집** — `references/facts-guide.md` 순서대로 호텔·룸 팩트(주소·전화·체크인/아웃·성급·개장연도·시설, 룸별 면적·전망·침대·정원·어메니티, 위도·경도 6자리)를 모아 `facts.json` 으로. 팩트 출처는 판매 페이지·호텔 공식 사이트·여행 예약 사이트·호텔이 준 자료이며, 없는 값은 지어내지 않고 `비움` + `changes.md`. 좌표는 판매 페이지 지도 → 예약 사이트 → OpenStreetMap, 없으면 `비움`.
3. **지시서 작성** — `references/MANUAL-SPEC.md` 의 구조 그대로 `manual.md` 를 쓴다. 단계 = 저장 한 번. 표는 `칸 | 값` 2열, 그 화면의 칸을 화면 사전 순서대로 전부, 값 종류 표기(`선택:`/`체크`/`해제`/`비움`/`자동 입력됨 · 그대로 둠`/`파일:`) 준수. 예시는 `examples/우에노_토우가네야/manual.md`.
4. **🟡 0건 만들기** — 지시서를 끝까지 따라간 뒤 판매 시작 배너에 🟡 가 하나도 남지 않아야 합격이다. `경고 넘어가기` 단계는 넣지 않는다 — 🟡 를 만드는 것(시즌 날짜 겹침/포함, 오퍼의 취소정책 미지정, 선택 부과금 금액 없음, 표시명 없음)을 지시서에서 미리 없앤다.
5. **검사** — `python3 scripts/check_manual.py manual.md --photos <사진 폴더> --share-name <공유 폴더명>` 이 ALL OK 가 될 때까지 고친다(단계=저장 1:1, 번호 연속, 금지어·원문자·좌표·절대경로 0, 사진 파일 존재).
6. **렌더** — `python3 scripts/render_card.py manual.md -o <이름>_입력지시서.html --font scripts/fonts/PretendardVariable.woff2 --title "<호텔> 입력 지시서"`. 공유 폴더는 `<공유 폴더명>/<공유 폴더명>_입력지시서.html` + `<공유 폴더명>/사진/` (예: `우에노_토우가네야/`).

## 반드시 지킬 것 (재현 시험에서 틀렸던 것)
- **호텔 만들기가 `기본 오퍼`(임시 저장)·룸 `스탠다드`·연결행 `기본 오퍼 · 스탠다드` 를 자동으로 만든다. 새로 만들지 말고 고쳐 쓴다.** 1번째 룸 = `객실` 탭 기존 `스탠다드` 행의 [편집], 오퍼 = `오퍼` 탭 `기본 오퍼` 행의 [편집](단계 제목 `오퍼 고치기`), 판매 연결 일괄은 **2번째 룸부터**(1번째 룸은 자동 연결행이 이미 있다). 새로 만들면 임시 오퍼와 빈 룸이 남고 1번째 룸이 판매 연결에서 빠진다. 예시 `examples/우에노_토우가네야/manual.md` 10·18·19·27단계(룸 1번째 · 오퍼 고치기 · 판매 연결 일괄 · 요금제 고치기)가 이 모양이다.
- **시즌은 겹치지 않는다**: 같은 오퍼의 두 시즌은 하루도 같은 날을 가질 수 없다(포함도 겹침이다). 넓은 시즌을 `비연속 날짜 나열` 로 바꿔 좁은 시즌 날짜를 빼거나, 요일로 갈리는 요금이면 같은 기간을 `요일 규칙` 시즌 둘(나머지 요일 / 그 요일)로 나눈다. `우선순위` 는 표시 순서일 뿐이고 `이미 값이 있는 날도 덮기` 는 언제나 `해제` 다. 채우는 순서는 넓은 시즌 먼저 → 좁은 시즌 나중 그대로.
- **오퍼마다 `기본 취소 정책`** 을 고른다. `지정 안 함` 은 배너에 🟡 를 남긴다 — 계약서에 취소 규정이 없으면 시작할 때 사용자에게 물어 정한 공용 정책 이름을 쓴다.
- **`시즌 만들기` 단계의 마지막 줄은 `→ [추가]`** (드로어 버튼 문구). 기존 시즌을 고치는 단계만 `→ [저장]`.
- **부가옵션 가격 넣기**: 같은 이름의 부가옵션이 오퍼 여러 개에 있으면 카드 줄에 오퍼를 함께 적는다 — 카드: `<이름>` — 오퍼 칸이 `<오퍼>` 인 카드.
- **`기준 요금제 바꾸기`** 단계 표에는 `기준 요금제` 한 줄만 적는다(사본 드로어에는 그 체크만 있다).
- **`가격 셀 만들기`** 는 그 날짜에 셀이 없을 때만. 시즌 전개가 덮은 날이면 `가격 셀 손으로 고치기` + `→ [저장]`.
- **호텔 전체 할인은 `전 오퍼 공통` 카드에 한 번만** 쓴다(오퍼 없는 공통 프로모션, 모든 오퍼에 붙음). 공통 프로모션이 0건이면 화면이 카드를 감추지만 러너가 오퍼 0 요청으로 연다.
- **캠페인 만들기**의 `화면:` 줄은 `Stay 호텔 목록 화면 위 [캠페인] → 캠페인 목록 화면의 [캠페인 만들기]` (상품 목록이 아니다).
- **공급 통화는 USD 가 기본**이다. 시트가 현지 통화를 주축으로 써도 스스로 그 통화를 고르지 않는다 — 사용자 확인 없이는 USD(시트의 USD 열 또는 시트 환율로 환산). 검사기가 USD 가 아니면 ⚠ 로 알린다.
- 계약서의 룸은 사용자가 고르지 않는 한 **전부** 넣는다.
- 계약서에 요금표가 여럿이면 **유효기간이 살아 있는 표만** 쓴다. 그 표에 없는 규정(취소·조식·체크인 시각)은 다른 표나 관행으로 채우지 않고 `비움`으로 두고 `changes.md` 에 "후보 값·출처" 로 적는다. 요금 셀이 빈 시즌은 만들지 않고 `changes.md` 에 적는다.
- 판매가(Sell) 칸이 비어 있으면 판매 단가 = 공급 원가(Net) 로 넣고 `changes.md` 맨 위에 **"마진 미반영 — 판매 전 검토"** 를 적는다.
- 산출물 경로는 **절대경로**로 쓴다. 사용자가 정하지 않았으면 계약서 파일이 있는 폴더 옆 `산출물/<공유 폴더명>/`.

## 하지 말 것
- 설명·근거·경고문·시트 좌표·사람/회사 이름·내부 용어를 지시서에 쓰지 않는다(규칙서 §절대 금지).
- 화면 사전에 없는 칸·옵션·버튼을 만들어 쓰지 않는다. 사전과 계약서가 충돌하면 사전이 화면의 진실이고, 값은 계약서가 진실이다.
- 가격·시즌·취소 규정은 계약서만 본다. 기존 판매 페이지나 예약 사이트의 가격은 쓰지 않는다(팩트만 참고).

## 산출물
`manual.md`(공개) · `rules.md`(내부 정리) · `facts.json`(팩트) · `<이름>_입력지시서.html` · `changes.md`(계약서와 다르게 결정한 값과 이유, 그리고 **비워 둔 칸 목록** — 담당자가 나중에 직접 채운다).

## 끝낼 때
비워 둔 칸(계약서·팩트 출처에 없어서 `비움` 으로 둔 것)을 `changes.md` 의 `## 담당자가 채울 칸` 절에 단계 번호·칸 이름과 함께 모으고, 마지막 보고에 그 목록을 그대로 보여 준다. 담당자는 화면에서 그 칸만 나중에 채우면 된다.
