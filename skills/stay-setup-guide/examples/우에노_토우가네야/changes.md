# 우에노 토우가네야 호텔 — 계약서와 다르게 정한 것

호텔 정보는 실제이고, 요금·시즌·취소 규정은 예시 값입니다(이 호텔과의 실제 계약이 아닙니다).
`manual.md` 는 값 하나만 적는 문서라, 왜 그 값이 됐는지는 전부 여기에 적는다.

## 0. 실제 값과 예시 값의 경계

| 구분 | 어디서 왔나 |
|---|---|
| 호텔명·주소·전화·좌표·체크인/아웃·개장 연도·리노베이션 연도·객실 수·프런트 운영·아동 정책·시설 | 호텔 공식 사이트와 여행 예약 사이트의 실제 값. 필드별 출처 URL 은 `facts.json` 의 `sources` |
| 룸 6종의 이름·면적·침대·정원·엑스트라베드 제공 여부 | 호텔 공식 사이트 객실 페이지의 실제 값 |
| 한글 룸 표시명 | 여행 예약 사이트 한국어 페이지 표기를 우선 채택 |
| 시즌·가격·취소 규정·부과금·엑스트라베드 요금·혜택 | 계약이 없으므로 `contract.md` 의 예시 값 |

## 1. 시즌 날짜를 갈라 적은 이유

계약서의 Regular 는 2026-11-01 ~ 2027-09-30 이고 Year-End Days(2026-12-29 ~ 2027-01-03)가 그 안에
통째로 들어간다. 같은 오퍼의 시즌이 하루라도 겹치면 판매 시작 배너에 노란 경고가 남으므로,
Regular 를 `비연속 날짜 나열` 로 바꿔 연말 6일을 뺀 두 구간(2026-11-01 ~ 2026-12-28,
2027-01-04 ~ 2027-09-30)만 적었다. 세 시즌은 이제 겹치는 날이 하루도 없다.

그래서 가격 셀을 손으로 고치는 단계가 하나도 없고, `이미 값이 있는 날도 덮기` 는 18회 전부
**해제**다 — 덮을 값이 애초에 없다.

1. Regular 6회 — 뺀 두 구간이 Regular 단가로 찬다.
2. Autumn Peak 6회 — 2027-10-01~2027-11-30 이 Autumn Peak 단가로 찬다.
3. Year-End Days 6회 — 2026-12-29~2027-01-03 이 Year-End 단가로 찬다.

계약서가 인원별 요금을 주지 않아 인원 조합을 쓰지 않으므로 한 날짜·한 룸에 좌표가 하나뿐이고,
손으로 고칠 셀이 남지 않는다.

## 2. 검증 배너의 노란 경고

이 설정에서 뜨는 노란 경고는 **하나도 없다**. 지시서를 끝까지 따라간 뒤 배너에 노란 항목이
남으면 지시서가 틀린 것이므로, 넘어가기 단계를 두지 않고 원인을 지시서에서 고쳤다.

| 경고 | 뜨나 | 이유 |
|---|---|---|
| 시즌 포함 | 안 뜬다 | Regular 에서 연말 6일을 빼 Year-End Days 와 겹치지 않게 했다 |
| 시즌 기간 겹침 | 안 뜬다 | 세 시즌의 날짜가 하루도 겹치지 않는다 |
| 오퍼에 취소정책 없음 | 안 뜬다 | 오퍼에 `표준 D-7 무료취소` 를 지정했다 |
| 오퍼 표시명 비어 있음 | 안 뜬다 | `고객 표시명` 을 채웠다 |
| 선택 항목에 금액 없음 | 안 뜬다 | 레이트 체크아웃에 정률 30 을 넣었다 |
| 오퍼에 시즌 없음 | 안 뜬다 | 시즌 3개를 만들었다 |
| 판매 구간에 가격 셀 없음 | 안 뜬다 | Regular 와 Autumn Peak 가 오퍼 투숙 구간을 빈틈없이 덮는다 |

## 4. 자동으로 만들어진 것을 고쳐 쓴 자리

호텔을 만들면 `기본 오퍼` · 룸 `스탠다드` · 연결행 `기본 오퍼 · 스탠다드` · 요금제 정본
`기본 요금제` 가 함께 생긴다. 새로 만들지 않고 고쳐 썼다.

- 10단계 — 1번째 룸은 `스탠다드` 행의 [편집]
- 22단계 — 오퍼는 `기본 오퍼` 행의 [편집]
- 23단계 — 판매 연결 일괄은 2번째 룸(Standard Double)부터 5개
- 33단계 — 요금제는 `기본 요금제` 행의 [편집]
- 34단계 — [전체 적용] 로 룸 6개에 같은 요금제를 깐다

새로 만들면 빈 룸과 임시 오퍼가 남고, 1번째 룸이 판매 연결에서 빠진다.

## 5. 팩트 출처

호텔·룸 팩트는 판매 페이지 → 호텔 공식 사이트 → 여행 예약 사이트 → 호텔이 준 자료 순서로 모았다.
이 호텔은 우리 판매 페이지가 없어 공식 사이트가 1순위였고, 성급·개장 연도·리노베이션 연도·조식 미제공은
여행 예약 사이트에서 채웠다. 좌표는 판매 페이지가 없고 예약 사이트 페이지에도 숫자가 없어
OpenStreetMap 에서 상호로 찾았다. 필드별 출처 URL 은 `facts.json` 의 `sources` 에 있다.

## 6. 사진

사진은 호텔 공식 사이트에서만 골랐고, 파일마다 실제 출처 URL 을 `manual.md` 사진 단계와
`사진목록.txt` 에 적었다. 룸 사진이 룸마다 한 장인 것은 공식 사이트가 룸 타입별로 한 장만
올려 두었기 때문이다. 두 번째 장이 필요하면 호텔에서 따로 받아 `room_<슬러그>_02.jpg` 로 저장한다.

## 7. 검사 스크립트에서 걸렸던 것

`check_manual.py` 의 금지어 목록에는 리눅스 사용자 폴더 경로 조각이 들어 있다. 공식 사이트의
최상위 키비주얼 사진 경로에 그 조각과 같은 글자가 들어 있어서, 그 사진을 출처로 적으면
절대경로로 오인돼 검사가 떨어졌다. 그래서 호텔 사진 6장은 같은 공식 사이트의 관내 시설
사진으로 골랐다. 다른 호텔에서도 출처 URL 에 같은 글자가 들어가면 같은 일이 생긴다.
