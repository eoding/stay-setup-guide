# 입력 지시서(manual.md) 형식 규칙 — 정본

**예시(정답지)**: `examples/우에노_토우가네야/manual.md` — 구조·어휘·표기를 이 파일과 똑같이 맞춘다.

## 목적
담당자가 읽지 않고 **따라 치는** 문서. "어디 들어가서 → 어느 탭/버튼 누르고 → 어느 칸에 무엇을 넣고(또는 비우고) → 저장". 90살 노인도 이것만 보고 무지성으로 끝까지 갈 수 있어야 한다.

## 절대 금지
- 설명·이유·근거·경고문·시트 좌표(`B46`)·"이 호텔로 무엇을 경험하나"·"먼저 알아 둘 것"·"원본 자료"·기대값·실패 케이스·기존 페이지 비교·검증 배너 대조표.
- 실명(사람 이름·회사 이름), "확인 필요", "임시값", "위와 같이"(앞 단계 참조). 미확정 값도 정해진 값 하나로 적고 그 사실은 `changes.md`(내부)에만.
- 원문자 ①②, HTML 주석, 내부 id·테이블명·코드 경로.
- 예외: 계약서/기존 판매 페이지에서 온 **값 자체**에 회사명이 들어가면(예 오퍼 고객 표시명) 값이므로 그대로 둔다.

## 구조
```
# <호텔 한글명> — 입력 지시서

## 1. 호텔 만들기
화면: 왼쪽 메뉴 `자유여행` → `상품관리` → 목록 위 [호텔 만들기]
주의: (그 단계의 클릭에 꼭 필요한 한 줄만. 없으면 생략)

| 칸 | 값 |
|---|---|
| 호텔명 | … |
| 도시 | 선택: 도쿄(TYO) |
| 공급 통화 | 선택: JPY |
| 수수료명 | 자동 입력됨 · 그대로 둠 |

→ [호텔 만들기]
```
- **단계(`##`) = 저장 버튼 한 번.** 룸 5개면 단계 5개, 시즌 가격 채우기 20회면 단계 20개(순서가 정답), 부과금·부가옵션(정의+가격행)·취소정책·혜택도 각각.
- 단계 제목은 행동 그대로 + "무엇을 몇 번째": `## 10. 룸 만들기 (1번째, <룸 이름>)`, `## 30. 시즌 가격 채우기 (1회차, <시즌> × <룸 이름>)`. 같은 접두로 연속되면 렌더러가 목차에서 묶는다.
- 단계 첫 줄들: `화면:` / `탭:` / `카드:` / `블록:` / `버튼:` / `폴더:` / `주의:` 중 필요한 것만, 드로어 안 하위 버튼은 `버튼:` 여러 줄을 순서대로. 버튼 문구는 `[…]`, 화면 요소 이름은 백틱.
- 마지막 줄 `→ [저장]`(버튼 문구 그대로). 마지막 단계는 `화면: 편집 화면 맨 위 검증 배너` → `→ [판매 시작]`.

## 표 (2열 고정 `칸 | 값`)
- **그 화면에 보이는 입력 칸을 화면 순서대로 전부** 적는다. 칸 목록·순서·옵션은 `references/screen-dictionary.md` 를 따른다. 화면에 보이지 않는 칸(다른 값을 골라야만 나타나는 칸, 화면에 없는 칸)은 넣지 않는다. 화면에 없는 칸(별점 등)은 없는 것이다.
- 칸 이름·셀렉트 옵션·버튼 문구는 **`references/screen-dictionary.md` 문자열 그대로** 쓴다.
- **도시**는 화면 자동완성 항목의 글자 그대로 `한글명(공항코드)` 로 적는다(예 `선택: 다낭(DAD)`, `선택: 푸꼭(PQC)`, `선택: 냐짱(나트랑)(CXR)`, `선택: 도쿄(TYO)`). 화면은 공항코드(IATA 3자)로 검색하면 바로 뜨고, 담당자가 아는 이름(푸꾸옥·나트랑)과 화면 표기(푸꼭·냐짱)가 다를 수 있으므로 **이름이 아니라 코드가 열쇠**다. 도시에 코드가 여럿이면(도쿄 TYO/HND/NRT) 도시 대표 코드(TYO)를 쓴다. 코드는 `references/facts-guide.md` §도시 코드 로 확정한다.
- 값 종류 표기(렌더러가 이걸로 복사 버튼 유무를 정한다):
  - 타이핑·붙여넣기: 값 그대로 → `| 호텔명 | 우에노 토우가네야 호텔 |`
  - 셀렉트·라디오·자동완성·다중 체크 목록: `선택: <옵션 글자 그대로>` (다중은 `선택: A, B, C`)
  - 체크박스: `체크` / `해제`
  - 안 채움: `비움`. 저절로 차는 칸: `자동 입력됨 · 그대로 둠`
  - 파일 한 장: `파일: name.jpg`
- 긴 글(상세설명·정책 문장)은 표 대신 `상세설명:` 라벨 줄 + 펜스 코드블록(전체 복사).
- 반복 값도 매번 다시 적는다.

## 사진 단계
```
## 3. 대표이미지 올리기 (1장)
탭: `기본정보`
폴더: <공유 폴더명>/사진
파일 선택 → 아래 파일
- hotel_01.jpg — 출처: https://www.example-hotel.com/gallery/main.jpg
- hotel_02.jpg
→ [저장]
```
- `폴더:` 는 **공유 폴더 기준 상대 경로**: `<공유 폴더명>/사진` (예: `우에노_토우가네야/사진`). 절대 경로 금지.
- 파일명 규칙은 `references/facts-guide.md` §사진 을 그대로 쓴다(hotel_01~08, room_<slug>_01/02, offer_hero.jpg). 사진을 준비하는 쪽이 같은 이름으로 저장한다.
- 파일 목록 줄은 `- <파일명>` 또는 `- <파일명> — 출처: <URL>` 이다. 출처는 선택이지만 적을 때는 반드시 이 형식(파일명 뒤 ` — 출처: ` + `http(s)://` 로 시작하는 URL 하나)을 지킨다.
- 렌더러가 사진 단계마다 "사진의 저작권·사용 허락 확인은 사용자 책임입니다" 고지를 자동으로 붙이므로 manual.md 에는 쓰지 않는다.

## 순서 (탭 순서가 아니라 의존 순서 — 되돌아가지 않는다)
호텔 만들기 → 기본정보(글·대표이미지·상세 이미지) → 호텔 정보 → **취소정책** → 객실(룸) → 룸 사진 → 오퍼(취소정책 선택) → 판매 연결(일괄) → 시즌(취소정책 선택) → 요금제 → 판매일 → 가격 채우기 → 가격 셀 손입력·셀 상태 → 부과금 → 부가옵션(정의→가격행) → 프로모션 → 혜택 → 판매 시작.
**호텔 만들기가 만든 `기본 오퍼`·`스탠다드`·연결행은 새로 만들지 않고 고쳐 쓴다**(1번째 룸 = `스탠다드` [편집], 오퍼 = `기본 오퍼` [편집] → 단계명 `오퍼 고치기`, 판매 연결 일괄은 2번째 룸부터). 뒤 화면이 셀렉트로 고르는 것은 앞에 만든다. 부과금 `적용 룸 scope` 는 판매 연결이 있어야 후보가 뜬다. 캠페인은 오퍼가 고르므로 쓰는 호텔은 1단계보다 앞에 두고, 그 단계의 `화면:` 줄은 `Stay 호텔 목록 화면 위 [캠페인] → 캠페인 목록 화면의 [캠페인 만들기]` 다(상품 목록이 아니다).

## 화면 제약 (해당 단계에 `주의:` 한 줄로)
- 부과금 드로어: 시간대별 요율 행을 하나라도 추가하면 정액·정률 칸이 사라진다 → 정률/정액을 먼저 채우고 [요율 행 추가].
- 판매 연결 `룸 이름` 비우고 저장하면 `오퍼명 · 룸이름` 으로 채워진다.
- 호텔 만들기: 거래처를 고르면 수수료 4칸이 저절로 찬다. 수수료(율)이 비어 있을 때만 0.
- 시즌 가격 채우기: 회차 순서가 곧 값이다 — 단계 순서 그대로. `이미 값이 있는 날도 덮기` 는 언제나 `해제` 다(시즌이 겹치지 않으므로 덮을 값이 없다). 시즌 날짜를 가르는 법은 아래 §추가 규칙 의 `시즌은 겹치지 않는다` 를 따른다.
- 가격 셀 손입력 작은 창: 카드 `인원별 가격 추가` 와 [추가] 는 그 날짜에 셀이 아직 없을 때만 쓴다. 이미 있는 셀은 그 행을 고치고 [저장].

## 산출물 (호텔마다 작업 폴더 하나)
- `manual.md` — 지시서(공개).
- `rules.md` — 계약서에서 뽑은 룰 정리(담당자 확인용).
- `changes.md` — 첫 줄에 사진 저작권 확인은 사용자 책임이라는 문장, 이어서 계약서와 다르게 정한 값·그 이유, 그리고 `## 담당자가 채울 칸`(단계 번호 · 칸 이름 · 비운 이유) — 담당자가 나중에 화면에서 직접 채운다.
- 보고: 단계 수 · 값 행 수 · 종류별 행 수(입력/선택/체크/해제/비움/자동/파일) · 금지어 0 확인 · 계약서 값 중 미포함 목록.

## 추가 규칙 (실제 생성에서 교정된 것 — 반드시 지킬 것)
- **부가옵션 `적용 방식`** 화면 옵션은 `1회 적용 (박수·날짜와 무관)` / `날짜연동 (박수 따라감 — 엑스트라베드)` / `일자선택 (원하는 날만 — 조식)`. (다른 표현을 쓰면 틀림.)
- **위도·경도**는 소수 6자리 고정(`35.712000`). 7자리 이상은 저장 거부. 좌표는 판매 페이지 지도 → 예약 사이트 → OpenStreetMap 순으로 찾고(`references/facts-guide.md` §좌표), 둘 다 없으면 `비움` 으로 두고 `changes.md` 에 적는다. 같은 브랜드의 다른 지점(예: 같은 호텔 체인의 다른 도시 지점)에 주의.
- **`경고 넘어가기` 단계는 쓰지 않는다.** 판매 시작 전 배너에 🟡 가 하나라도 남으면 지시서가 틀린 것이다 — 사유를 적어 넘기지 말고 원인을 지시서에서 고친다. 🟡 를 만드는 것들과 그 고침: 시즌 날짜 겹침/포함(→ 위 `시즌은 겹치지 않는다` 대로 날짜·요일로 가른다), 오퍼의 취소정책 없음(→ 아래 `오퍼마다 기본 취소 정책` 대로 정책을 고른다), 선택 부과금 금액 없음(→ 금액을 넣는다), 표시명 없음(→ 표시명 단계를 둔다).
- **오퍼마다 `기본 취소 정책`** 을 고른다 — `지정 안 함`(목록 맨 위 빈 항목)으로 두지 않는다. 계약서에 취소 규정이 없으면 지시서를 쓰기 전에 사용자에게 어떤 공용 정책을 쓸지 묻고 그 이름을 고른다(`SKILL.md` §입력). 물어보지 않은 채 `지정 안 함` 으로 지시서를 만들지 않는다.
- **일괄 판매 연결 드로어에는 `오퍼별 표시명` 칸이 없다.** 한글 표시명을 넣으려면 연결행마다 행별 편집 단계(룸 수만큼)를 둔다. 표시명은 한글만(영문 괄호 제외). 표시명을 넣으면 가격 캘린더 카드 이름도 그 이름이 된다.
- **별점 칸은 어느 폼에도 없다.** 넣지 않는다. **룸 설명 칸도 없다.** 룸 설명은 면적·전망·침대·정원·어메니티로 흩어 넣는다.
- **팩트 출처 우선순위**는 `references/facts-guide.md` §출처 우선순위 를 따른다. 전망은 판매 문구(전부 오션뷰 등)보다 공식 사이트의 세분 값을 우선한다.
- **날짜**: 판매일 시작이 오늘 이전이면 오늘 이후로 옮긴다.
- **침대 "킹 1 또는 트윈 2"** 처럼 선택형은 화면이 종류+개수만 받으므로 첫 번째(킹 1)로 적고 changes.md 에 기록.
- **시즌은 겹치지 않는다 (같은 오퍼 안에서 하루도)**: 같은 오퍼의 두 시즌이 하루라도 같은 날을 가지면 안 된다. 한쪽이 다른 쪽 안에 통째로 들어가는 것(포함)도 겹침이다. 겹치면 판매 시작 배너에 🟡 가 남고, 그 🟡 는 지시서가 틀렸다는 뜻이다. 가르는 법:
  1. **날짜로 가른다** — 넓은 시즌의 `날짜 규칙 유형` 을 `비연속 날짜 나열` 로 바꾸고, 좁은 시즌(Peak·연말 등)의 날들을 뺀 구간만 `날짜 나열` 에 적는다. 예: 넓은 시즌이 `2026-11-01 ~ 2027-09-30`, 좁은 시즌이 `2026-12-29 ~ 2027-01-03` 이면 넓은 쪽은 `2026-11-01 ~ 2026-12-28` 과 `2027-01-04 ~ 2027-09-30` 두 줄이다.
  2. **요일로 가른다** — 요일로 갈리는 요금(예 토요일 요금)은 같은 기간을 `요일 규칙` 시즌 둘로 나눈다. 넓은 쪽이 나머지 요일(`기간 시작 2026-06-01` · `기간 종료 2026-08-31` · `적용 요일 선택: 일, 월, 화, 수, 목, 금`), 좁은 쪽이 그 요일(`적용 요일 선택: 토`). 같은 기간을 두 번 깔되 요일이 갈리므로 겹치지 않는다.
  `우선순위` 는 이제 표시 순서일 뿐이고, `이미 값이 있는 날도 덮기` 는 모든 `시즌 가격 채우기` 단계에서 `해제` 다. 겹침이 없으니 덮을 값이 없다 — `체크` 가 남아 있으면 시즌을 아직 안 가른 것이다. 채우는 순서는 넓은 시즌 먼저, 좁은 시즌 나중 그대로 둔다.
- **`시즌 만들기` 단계의 마지막 줄은 `→ [추가]`** 다(드로어의 버튼 문구가 [추가]). 이미 있는 시즌을 고치는 단계(그 줄의 [편집])만 `→ [저장]`.
- **부가옵션 가격 넣기 카드 줄**: 같은 이름의 부가옵션이 오퍼 여러 개에 있으면 카드도 여러 장이라 이름만으로는 못 고른다. 그럴 때 카드 줄은 이 형식 그대로 쓴다 — 카드: `<부가옵션 이름>` — 오퍼 칸이 `<오퍼 이름>` 인 카드. 이름이 한 오퍼에만 있으면 카드: `<부가옵션 이름>` 로 둔다.
- **`기준 요금제 바꾸기`(룸에 깔린 사본 편집)** 단계의 표에는 `기준 요금제` 한 줄만 적는다. 사본 드로어에는 그 체크 하나만 보이고, 요금제명·식사 조건·침대 구성·환불 가능·포함물 같은 정본 칸은 정본에서 내려오므로 나열하지 않는다.
- **`가격 셀 만들기`(카드 `인원별 가격 추가` 의 새 행)** 는 그 날짜의 그 룸 × 요금제에 셀이 **아직 없을 때만** 쓴다. 그 날짜가 시즌 가격 채우기로 덮인 날이면 단계 제목을 `가격 셀 손으로 고치기` 로 하고 마지막 줄을 `→ [저장]` 으로 적는다(새 행 [추가] 는 거부된다).
- **`전 오퍼 공통` 카드의 프로모션은 오퍼 없이 이 호텔의 모든 오퍼에 붙는다** — 호텔 전체에 거는 할인은 그 카드에 한 번만 쓴다(오퍼마다 복제하지 않는다). 특정 계약에만 거는 할인은 그 오퍼 카드에. 공통 프로모션이 하나도 없으면 화면이 그 카드를 감추므로 첫 건은 러너가 오퍼 카드의 [프로모션 추가] 요청을 오퍼 0으로 바꿔 만든다(담당자가 손으로 할 때는 아직 화면에 길이 없다 — ERP 개선 요청).

## 0단계: 시작 전 준비 (여행사 환경 — 지시서 맨 앞에 단계로 넣는다)
지시서 생성기는 여행사의 ERP 설정을 볼 수 없으므로, 있어야 하는 것을 **첫 단계들로** 적어 사람이 확인하게 한다:
- `## 1. 환율 확인` — 공급 통화(USD/VND)가 환율 관리에 등록돼 있는지. 없으면 등록(화면·버튼은 `references/screen-dictionary.md` 의 환율 화면 절).
- `## 2. 거래처 확인` — 계약 주체가 거래처 목록에 있는지(자사 판매면 `자사`).
- `## 3. 도시 확인` — 호텔 도시가 자동완성 목록에 뜨는지.
그 다음이 `호텔 만들기`. 이 단계는 매번 필수다.
