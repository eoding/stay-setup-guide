# 원화 표시·선택 혜택·정보 수집 폼

2026-10-22 배포 화면의 문구와 입력 조건을 대조한 안내입니다. 실제 화면 캡처나 운영 설치 실측 결과는 아닙니다. 기존 2026-09-23 자동 화면 사전과 다른 부분은 이 보충을 따릅니다.

## 원화만 보여 주기

CCS의 **고객사 관리 → 해당 여행사 → 기본정보 → Stay 온라인 요금은 원화만 표시**에서 관리자가 설정합니다. Stay를 사용하는 여행사에 보이며 기본은 꺼짐입니다. 호텔마다 따로 켜거나 고객이 직접 켜는 스위치가 아닙니다. 설치 과정에서 임의로 켜지 않습니다.

켜면 온라인 요금의 외화·환율·약값 기호(≈)를 숨깁니다. 마지막 총액의 ≈도 숨깁니다. 계산 방식은 바꾸지 않으므로 날짜별 원화 금액을 더한 값과 총액 사이에 소액 차이가 날 수 있다는 안내가 함께 나옵니다. **호텔에서 따로 결제할 금액은 실제 납부 통화로 그대로 보입니다.**

지시서에는 `원화 표시 설정 확인` 단계로 원하는 체크/해제 상태를 적고 `→ [확인]`으로 끝냅니다. CCS 관리자가 먼저 저장하고 고객 홈페이지를 새로 열어 표시까지 확인해야 합니다. 브라우저 실행기는 이 단계에서 멈추며, 설치 도구의 설정 되읽기만으로 홈페이지 반영 완료를 선언하지 않습니다.

## 혜택·부과금·부가옵션에 질문 연결하기

픽업·샌딩은 항목의 제목 예시입니다. 특정 이름에만 작동하는 기능이 아닙니다. 먼저 항목을 저장한 다음 질문을 붙입니다.

| 연결할 곳 | 여는 곳 |
|---|---|
| 혜택 | 오퍼의 해당 혜택 [편집] → 혜택 질문 |
| 부과금 | 오퍼의 해당 부과금 행 [정보 수집 폼] |
| 부가옵션 | 해당 오퍼에 속한 부가옵션 카드 [정보 수집 폼] |

한 질문을 한 단계로 작성합니다. 같은 원고에는 질문의 최종 정의를 한 번만 적습니다. 신규 질문을 만든 뒤 뒤에서 다시 고치거나 이름을 바꾸는 단계를 연결하지 않습니다. 같은 칸이나 긴 글 블록을 중복으로 적지 않습니다. 단계 제목은 `정보 수집 질문 만들기` 또는 `정보 수집 질문 고치기`, 카드는 `오퍼명 · 혜택/부과금/부가옵션 · 항목명`입니다. 가운데에는 실제 종류 하나만 적습니다. 고칠 때에는 `버튼: \`기존 질문 제목\` 행의 [편집]`으로 대상을 한정합니다. 질문 제목을 바꾸더라도 기존 제목을 버튼 줄에 남깁니다.

| 칸 | 값·뜻 |
|---|---|
| 구분 | 단답형 / 장문형 / 체크박스 / 객관식 / 서술형 중 선택 |
| 질문 | 제목, 비우지 않고 200자 이내 |
| 필수 여부 | 체크 또는 해제 |
| 선택지 표시 방식 | 칩 선택형 또는 셀렉트 박스형. 객관식에만 적용 |
| 안내문 | 20000자 이내, 긴 글 블록으로 적거나 비움 |
| 선택지 (한 줄에 하나) | 긴 글 블록에 한 줄씩. 쉼표는 문구의 일부 |

구분·질문·필수 여부·선택지 표시 방식 네 칸은 항상 적습니다. 객관식은 하나 선택, 체크박스는 여러 개 선택입니다. 서술형은 **답을 받지 않는 안내**이므로 필수 여부를 해제합니다. 날짜·시간 전용 질문 유형은 없으므로 단답형 또는 객관식 시간 선택지로 작성합니다. 질문 순서 입력 칸은 없습니다.

객관식·체크박스에는 중복 없이 각각 200자 이내의 선택지를 1~100개 넣습니다. 다른 구분에는 선택지를 넣지 않습니다. `선택지 (한 줄에 하나):` 아래의 펜스 블록을 사용하고 쉼표로 나누지 않습니다. 새 질문의 마지막 줄은 `→ [질문 추가]`, 수정은 `→ [질문 저장]`입니다. 바깥 혜택의 [저장]과 다른 버튼입니다.

한 폼은 최대 200문항이며 브라우저 실행기는 열린 폼의 기존 질문까지 세어 신규 추가를 막습니다. 이미 저장된 같은 정의의 확인이나 기존 질문 수정은 가능합니다. 실제 한 예약에서 선택된 정보 수집 항목은 최대 100개·총 200문항입니다. 선택 조합까지 지시서만으로 알 수 없으므로 고객 예약 화면에서 조합을 확인해야 합니다.

고객이 선택한 항목과 적용 조건에 맞는 항상 포함·의무 항목에 연결된 질문이 예약에 나옵니다. 필요 없는 항목의 질문을 무조건 전부 받는 방식은 아닙니다. 입력한 답변은 결제를 준비할 때 보관하고 예약이 만들어지면 예약에 연결합니다. 고객은 예약 화면과 회원 마이페이지·비회원 예약 상세에서, 직원은 ERP 예약 상세에서 답변을 확인합니다. 직원이 답변을 수정하면 변경 이력을 확인할 수 있습니다. 질문 설치 자체가 고객 답변을 만들거나 결제를 실행하지는 않습니다.

브라우저 실행기는 항목 소속을 정확히 찾고, 저장 뒤 질문 [편집]을 다시 열어 입력값을 대조합니다. 같은 정의가 이미 있으면 다시 만들지 않습니다. 이름이 겹치거나 값이 다르면 멈춥니다. 새 기능의 자동 실행은 격리된 화면 시험으로 검증했으며 실제 운영 호텔을 자동 설치한 실측은 아닙니다.

## 선택 그룹

새 지시서는 `선택 그룹 만들기` / `선택 그룹 고치기`를 씁니다. `그룹 이름`, `선택 상한`, `정확히 하나 선택 (끄면 선택 사항)`을 명시합니다. 상한이 비어 있으면 무제한, 2이면 최대 두 개입니다. 정확히 하나 선택을 켜면 상한은 1이고 반드시 하나 고릅니다. 끄면 하나도 선택하지 않아도 됩니다.

그룹의 후보는 그 그룹 안 [이 그룹에 혜택 추가]로 넣습니다. 오퍼 머리 [혜택 추가]로 넣으면 항상 포함되는 혜택이 됩니다. 기존 `택1 그룹 만들기` 제목은 호환용이며 두 신규 칸이 없는 예전 지시서는 정확히 하나 선택으로 유지합니다.

## 호텔에서 따로 결제하는 부과금

부과금의 **현장 결제 안내**에 실제 통화와 단가를 넣습니다. `현장 결제 단가`를 비우면 미정, 0이면 무료입니다. 온라인 결제 합계에는 더하지 않습니다. `부과 단위`의 체류당 1회 / 박당 / 인당에 맞는 단가를 입력합니다.

현장 통화를 쓰면 부과 방식은 정액, 온라인 `정액 금액 (공급 통화)`은 `선택: 지정 (0 포함)`으로 고르고 그 `값`은 0, 온라인 연령별 단가는 0, 시간대별 요율은 비워야 합니다. 현장 연령별 단가는 인당일 때만 넣습니다. 밴드별 칸을 비우면 성인 단가를 따르고 0이면 무료입니다. 지시서 표기는 `현장 연령별 단가 · 소아`처럼 온라인 `연령별 단가 · 소아`와 구분합니다. 화면에서는 **현장 결제 안내 안의 소아 칸**을 찾습니다.

## 기존 배너와 설치 범위

배너 목적지 링크는 기존 ERP 참조정보의 배너 설정을 재사용합니다. 이번 안내 때문에 별도 배너나 새 설정을 자동 생성하지 않습니다. 예약 답변·수정 이력의 조회와 고객 화면 표시 확인은 설치 후 점검이며, 이 지시서가 운영 예약이나 결제를 생성하는 단계가 아닙니다.
