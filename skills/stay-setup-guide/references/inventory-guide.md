# 재고 — 선택 단계와 입력 폼 (운영 2026-10-08 화면)

재고는 **선택 사항**이다. 계약서나 사용자가 판매 연결별·날짜별 객실 수량을 명시했을 때만 아래 단계를 넣는다. 수량이 없으면 이 절의 단계와 질문을 추가하지 않는다. 기존 지시서는 그대로 쓴다.

호텔 전체 객실 수를 판매 재고로 추정하지 않는다. 오퍼마다 같은 객실을 팔더라도 판매 연결은 따로다. 수량이 어느 오퍼·객실·날짜에 해당하는지 불명확하면 재고 단계를 만들기 전에 그 값만 확인한다.

판매 연결과 판매일을 만든 **뒤**, 가격 채우기 **앞**에 놓는다. 순서는 수량으로 판매 켜기 → 총 수량 넣기다. 수량으로 판매를 켠 연결에서 수량이 없는 날은 **안 팖**, 총 수량 `0`은 **마감**이다. 시작일·종료일은 모두 포함하고, 날짜는 투숙하는 밤 기준이다(체크아웃 날 제외).

입력하는 값은 **총 수량**이다. 팔림·결제 중·남음은 읽기만 하고 지시서 표에 넣지 않는다. 기존 예약이 있어도 팔린 수를 빼서 입력하지 않는다. 예약 한 건의 객실 수나 호텔 기본 정보의 총 객실 수도 이 값으로 쓰지 않는다.

화면의 판매 연결 이름은 `오퍼명 · 객실명`이다. 객실명은 그 오퍼별 표시명이 있으면 표시명, 없으면 룸 타입 이름이다. 예시의 오퍼·객실·수량·날짜는 형식 설명용 가상 값이다.

## 수량으로 판매 켜기

`재고` 탭의 해당 행 머리에 있는 `수량으로 판매` 스위치를 **켠다**. 입력 칸은 없다. 이미 켜졌으면 다시 누르지 않는다. 연결마다 한 단계다. 기존 재고를 끄거나 비우는 단계는 생성하지 않는다.

```markdown
## 30. 재고 수량 판매 켜기 (가을 계약 · 디럭스)
탭: `재고`
카드: `가을 계약 · 디럭스`

→ [수량으로 판매]
```

## 한꺼번에 넣기

`재고` 탭 [한꺼번에 넣기]를 연다. 폼의 실제 칸 순서는 아래 그대로다.

| 칸 | 형식 | 조건 |
|---|---|---|
| 시작일 | YYYY-MM-DD | 필수 |
| 종료일 | YYYY-MM-DD | 양끝 포함 최대 400일. 더 길면 기간을 나누어 각각 저장 |
| 요일 | `선택: 월, 화, 수, 목, 금, 토, 일` | 하나 이상. 고른 기간에 해당 요일이 있어야 함 |
| 판매 연결 | `선택: 오퍼명 · 객실명` | 앞 단계에서 수량으로 판매를 켠 연결만. 여러 개는 `, `로 나눔 |
| 총 수량 | 0~9999의 정수 | 계약서 또는 사용자가 명시한 총 객실 수. 비움·자동 값 금지 |

드로어는 전 요일과 켜진 판매 연결 전부를 기본 선택한다. **기본 선택을 그대로 저장하지 않고 지시서에 명시한 대상만 고른다.** 수량이나 요일이 다르면 회차를 나누고, 입력 범위가 겹치면 뒤 회차가 총 수량을 덮는다. [비우기]는 누르지 않는다.

```markdown
## 31. 재고 한꺼번에 넣기 (1회차, 가을 계약 · 디럭스)
탭: `재고`
버튼: [한꺼번에 넣기]

| 칸 | 값 |
|---|---|
| 시작일 | 2026-10-08 |
| 종료일 | 2026-10-31 |
| 요일 | 선택: 월, 화, 수, 목, 금, 토, 일 |
| 판매 연결 | 선택: 가을 계약 · 디럭스 |
| 총 수량 | 10 |

→ [넣기]
```

## 날짜 하나 고치기

해당 달로 이동하고, 해당 판매 연결의 **총** 행에서 날짜 칸을 누른다. 보조 드로어 입력은 `총 수량` 하나다. `카드:`는 판매 연결, `블록:`은 날짜 하나로 한정한다.

```markdown
## 32. 재고 수량 고치기 (가을 계약 · 디럭스, 2026-10-15)
탭: `재고`
카드: `가을 계약 · 디럭스`
블록: `2026-10-15`

| 칸 | 값 |
|---|---|
| 총 수량 | 5 |

→ [저장]
```

원고의 재고 단계는 검사기가 수량·대상·기간·요일·켜기 순서를 검사한다. 재고가 없는 기존 지시서에는 추가 조건이 생기지 않는다. 자동 화면 사전의 재고 표식이 아직 없어 이 파일이 재고 폼의 보충 사전이다. 기존 `screen-dictionary.md/.json`은 손으로 수정하지 않는다.
