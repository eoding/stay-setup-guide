# 운영 FAQ · 오퍼·시즌·아동

출처: [어딩 Stay 파트너 가이드](https://mhj-stack.github.io/eoding-stay-guide/#start),
2026-10-23 확인. 원본의 STEP 화면은 2026-10-15 캡처이며,
[10월 업데이트 안내](https://mhj-stack.github.io/eoding-stay-guide/#update)는 **배포 예정**이다.
기능 적용 여부는 배포 공지와 현재 화면으로 확인한다. 이 문서는 새 운영 화면을 실측한 결과가 아니다.

## 입력 순서와 세 가지 개념

사람용 가이드의 순서는 기본정보·호텔 정보 → 취소정책 → **객실(STEP 04)** →
**오퍼(STEP 05)** → 판매 연결 → 시즌·요금제 → 판매일 → 재고(계약 수량이 있을 때) → 가격이다.
자동 지시서는 기존 `MANUAL-SPEC.md`대로 오퍼를 먼저 만들고 룸·판매 연결을 만든다.
두 순서 모두 판매 연결 전에 오퍼와 룸이 있어야 한다. 사람용 STEP 번호를 실행 단계 번호로 옮기지 않는다.

| 계약에서 달라지는 것 | 넣을 곳 |
|---|---|
| 예약·투숙 기간, 취소 규정, 판매 이름 같은 계약 조건 | 오퍼 |
| 같은 계약 안에서 날짜별로 다른 단가 | 시즌 |
| 같은 방의 조식 포함·룸온리 등 판매 조건 | 요금제 |
| 기존 가격에 붙는 할인 조건 | 프로모션. 필요하면 전용 취소 정책 지정 |

가격 한 칸에는 오퍼·객실·요금제·날짜·인원이 함께 정해진다. 하나라도 빠지면 가격을 넣어도 팔리지 않을 수 있다.
같은 날짜에 겹치는 오퍼는 우선순위가 큰 쪽이 판매되고, 같으면 판매가 차단된다.
한 오퍼 안의 시즌 우선순위와 혼동하지 않는다. 시즌 날짜는 포함 관계까지 겹치지 않게 작성한다.

## 시즌을 나누거나 다시 펼칠 때

- 비수기·성수기는 기간 범위, 주중·주말은 겹치지 않는 요일 규칙, 공휴일만 다르면 비연속 날짜 나열을 쓴다. 가격이 하나면 오퍼 기간 전체를 시즌 하나로 둔다.
- 하루 이틀만 다른 금액은 가격 캘린더에서 해당 날짜를 고친다. 별도 시즌으로 만들면 기존 시즌에서 그 날짜를 먼저 뺀다.
- `[재전개]`는 저장된 날짜 규칙으로 날짜 목록을 다시 계산한다. 시즌을 편집·저장하면 자동으로 처리되므로 평소에 반복할 필요가 없다. 가격을 새로 채우는 버튼으로 안내하지 않는다.
- 같은 오퍼의 시즌이 겹치면 가격 입력 순서와 덮기 여부에 따라 한쪽 값이 남고 검증 경고가 생길 수 있다. 새 호텔 지시서는 겹침과 덮기를 허용하지 않는다.

## 하루만 받는 의무 부과금

오퍼를 새로 만들지 않고 해당 오퍼의 `[부과금 추가]`에서 부과 유형을 `의무`로 고른다.
`적용 날짜`를 지정하며, 비우면 오퍼 기간 매일 적용될 수 있으므로 계약 날짜를 그대로 쓴다.
1박당은 `박당`(지정한 날의 밤만), 1인당은 `인당`, 예약당 한 번은 `체류당 1회`를 고른다.
정액 금액은 `지정 (0 포함)`을 고르고 값 칸에 계약 금액을 입력한다. 회색 예시 글자는 저장된 금액이 아니다.
호텔에서 직접 받는 금액은 [현장 결제 안내](customer-options-guide.md#호텔에서-따로-결제하는-부과금)를 따른다.

## 아동 요금

아동 정책이 있으면 **오퍼마다 연령 구간부터** 만든다. 코드·노출명·나이 경계·방 인원수 포함 여부·요금 기준 유형을 계약서대로 넣는다.
`만 12세 미만`의 최대는 `11.99`이며 최소 나이는 계약서가 정한다. 코드 `CHD`·`INF` 등은 영대문자·숫자 2~8자다.
연령 구간이 없으면 고객 화면에서 아이를 고를 수 없다.

무료 구간에는 가격 창의 아동 추가 금액 입력 줄이 없고, 유료 구간은 해당 줄의 금액을 반드시 채운다.
성인 기준 `A2`와 구간이 붙은 조합 `A2C1_CHD` 등의 작성법은 `MANUAL-SPEC.md`를 따른다.
원본 FAQ의 무료 안내만으로 룸 정원·허용 인원 조합·가격 조합 확인을 생략하지 않는다.
방에서 자는 아이는 연령 구간이며, 별도로 구매하는 아동 식사 등만 부가옵션이다.

## 저장했는데 날짜를 못 고를 때

오퍼가 `작성중`이면 고객 화면과 직원 예약 등록 화면 모두 날짜를 고를 수 없다.
예약 기간·투숙 기간·예약 마감·오퍼 우선순위·룸 허용 인원·요금제 조건·판매일·가격·수량 판매 재고를 확인한다.
검증 배너 **🔴 0 · 🟡 0**을 확인한 뒤 `[판매 시작]`은 담당자가 직접 누른다.
예약 접수·결제 완료·호텔 최종 확정은 구분해 안내한다.

판매일 생성·월 닫기·가격 창의 요금제 비움·박수별 단가는 [가격 도움말](price-guide.md)을,
예정 기능의 서비스 폼·고객 답변·원화 표시는 [고객 옵션 안내](customer-options-guide.md)를 읽는다.
