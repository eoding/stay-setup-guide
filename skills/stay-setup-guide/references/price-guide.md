# 가격 입력·수정 도움말

출처: [어딩 Stay 파트너 가이드 · 가격편](https://mhj-stack.github.io/eoding-stay-guide/#price-start),
2026-10-23 통합 가이드 확인. 저장소의 `docs/파트너-가이드-가격편.html`에 화면 캡처와 입력 예시가 있다.
아래는 스킬 폴더만 설치했을 때도 가격 질문에 답하기 위한 판단 기준이다.
실제 화면과 다르면 현재 화면을 우선한다. 예시 금액·날짜를 실제 계약 값으로 사용하지 않는다.

## 화면 명칭과 적용 범위

2026-10-20 명칭 변경은 `MANUAL-SPEC.md`와 짝 스킬의 `screen-mechanics.md`에 이미 반영되어 있다.
원본 캡처의 옛 글자를 현재 글자와 연결해 설명한다.

| 원본 캡처 | 현재 명칭 |
|---|---|
| 가격 일괄 전개 | 가격 일괄 입력 |
| 이 단가로 깔기 | 가격 적용 |
| 이 시즌이 예전에 깐 다른 인원 조합·요금제 셀 지우기 | 이번에 고르지 않은 인원·요금제 가격 지우기 |

새 시즌은 [시즌 추가] → **[추가]**, 기존 시즌 편집은 **[저장]**이다.
원본 가격편의 새 시즌 [저장] 표기는 그대로 옮기지 않는다.

**새 호텔 지시서**는 `MANUAL-SPEC.md`를 따른다. 시즌을 겹치지 않게 만들고 덮기·지우기는 해제한다.
아래의 기존 가격 수정은 담당자가 현재 값과 변경 범위를 확인하며 따라 하는 도움말이다.
이 도움말을 근거로 검사기 경고를 무시하거나, 기존 호텔 수정 절차를 새 호텔용 자동 실행 지시서로 만들지 않는다.

## 처음 입력할 때

공급 통화 → 오퍼 → 객실·판매 연결 → 시즌·요금제 → 판매일 → 가격 순서다.
아동 정책이 있으면 가격보다 먼저 해당 오퍼에 연령 구간을 만든다.
계약에 재고 수량이 있으면 판매 연결별·날짜별 수량도 입력한다(`inventory-guide.md`).

- 판매일이 아닌 날에는 가격이 들어가지 않는다. 판매일의 `대상 룸`은 반드시 고른다. 비움은 전체가 아니다.
- `[판매일 열기]`는 없던 판매일을 만들고 이미 있는 날은 건너뛴다. 시즌이 없어도 만들 수 있지만, 실제 판매에는 오퍼 투숙 기간 안의 날짜와 가격이 모두 필요하다.
- 같은 금액인 룸끼리 묶고 시즌별로 입력한다. 새 시즌들의 날짜는 하루도 겹치지 않게 한다.
- 가격 창의 `요금제(선택)`을 비우면 **룸마다 기준 요금제에만** 가격이 들어간다. 여러 요금제를 팔면 대상 룸의 각 요금제를 명시한다. 선택한 요금제의 룸은 `대상 룸`에도 있어야 한다.
- `기준 요금제 대비 조정(선택)`은 요금제를 고른 경우에만 쓴다. 조식 포함·룸온리를 함께 고른 예시에서는 기준 가격에 `-15`를 적용해 룸온리를 만든다. 요금제 하나에 그 요금제의 최종 금액을 직접 넣을 때는 조정을 비운다.
- 성인 2명·3명 요금이 다르면 `인원 조합(선택)`에 `A2,A3`, `인원 조합별 조정(선택)`에 `A3:+20`처럼 적는다. 조정에는 부호가 필요하며 룸 정원도 해당 인원을 허용해야 한다.
- `박수별 단가(선택)`의 `3:90`은 3박부터 적용할 1박 단가 90이다. 부호 없는 계약 가격이며, 기존 가격에 할인 조건을 붙이는 프로모션과 구분한다.
- 아동 요금은 `MANUAL-SPEC.md`의 연령 구간·아동 추가 금액 규칙을 따른다. 무료 구간에는 입력 줄이 없고, 유료 구간의 비움과 0은 다르다.
- `판매 단가(공급 통화)`는 계약의 공급 통화 기준 1박 금액이다. 입력 후 가격 캘린더에서 판매 기간 전체와 각 룸·요금제·인원을 확인한다.

## 덮기와 지우기

| 작업 | 이미 값이 있는 날도 덮기 | 이번에 고르지 않은 인원·요금제 가격 지우기 |
|---|---|---|
| 처음 입력·새 요금제 추가·연장 기간의 빈 칸 채우기 | 해제 | 해제 |
| 기존 금액 수정 | 체크 | 해제 |
| 판매할 인원·요금제 구성을 줄이기 | 체크 | 체크 |

덮기를 켜면 대상 날짜에서 하루씩 따로 수정한 가격도 바뀐다. 예외 날짜와 금액을 먼저 확인하고,
일괄 수정 뒤 해당 날짜를 다시 맞춘다. 요금제 하나만 수정하면서 지우기를 켜면 선택하지 않은
다른 요금제의 가격이 없어질 수 있다. 원본 안내상 예약이 걸린 날은 삭제를 건너뛰므로 결과를 확인한다.

## 기존 가격을 바꾸는 상황별 안내

| 상황 | 담당자가 따를 순서 | 가격편 위치 |
|---|---|---|
| 시즌 전체 금액 변경 | 해당 시즌 [가격] → 금액·대상 룸·요금제·인원 확인 → 덮기만 체크 → [가격 적용]. 여러 금액이면 룸 묶음별 반복 | A |
| 일부 룸만 변경 | 대상 룸을 변경할 룸으로 한정하고 그 룸의 요금제만 선택 → 덮기만 체크 | B |
| 룸온리 등 한 요금제만 변경 | 해당 요금제만 선택 → 판매 단가에 최종 금액 → 기준 요금제 대비 조정 비움 → 덮기만 체크 | C |
| 3인 투숙·특정 요금제 판매 종료 | 앞으로 팔 인원·요금제만 지정 → 덮기·지우기 모두 체크. 예약 때문에 건너뛴 셀과 남은 판매 구성을 확인 | D |
| 새 요금제·룸·인원 추가 | 요금제 정본 만들기·배포 또는 룸·판매 연결·판매일 준비 → 새 대상만 선택 → 덮기·지우기 해제 | E |
| 특정 날짜만 금액 변경 | 하루 이틀은 가격 캘린더의 해당 룸·요금제·날짜·인원 행 수정. 별도 시즌이면 기존 시즌에서 그 날짜를 뺀 뒤 새 시즌 [추가] → 이미 가격이 있던 날짜는 덮기만 체크 | F |
| 판매 잠시 중지·재개 | 시즌 [상태] → 날짜·룸·요금제 지정 → 판매 금지 / 마감 / 판매 가능 → [이 상태로 바꾸기] | G |
| 계약 기간 연장 | 계약에 맞게 오퍼의 투숙·예약 기간 → 시즌 날짜 → 연장 구간 판매일 → 가격 순서로 수정. 가격은 덮기·지우기 해제해 빈 칸만 채움 | H |

상태 창에서 `요금제(선택)` 비움은 **전 요금제**다. 가격 창의 비움(기준 요금제만)과 구분한다.
판매가 0인 셀은 판매 가능으로 바꿀 때 건너뛴다. 판매일 탭의 월 닫기는 가격·예약 없는
빈 판매일을 지우는 기능이므로 가격이 있는 날의 판매 중지는 [상태]로 한다.
특정 날짜에 의무로 받는 갈라디너 등의 추가 요금은 [부과금]에 적용 날짜와 함께 넣는다.

## 결과 확인

시즌 목록의 가격 셀 수·깔린 값, 가격 캘린더의 판매 기간 전체, 각 요금제·인원별 금액을 확인한다.
원본 가격편의 빨간 배너 점검에 더해, 이 저장소의 지시서는 **🔴 0 · 🟡 0**을 합격선으로 삼는다.
[판매 시작]은 담당자가 직접 누른다.
