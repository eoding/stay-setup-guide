# 실행 로그(run-log.md) 형식

한 단계에 한 줄. 사람이 읽고, 다음 실행이 이어서 하는 데 쓴다.

## 어디에 두나

공유 폴더 **옆**에 `<공유 폴더명>_실행/` 을 만들고 그 안에 둔다. 지시서 폴더는 건드리지 않는다.

```
<공유 폴더명>/                 ← 지시서(공유 폴더) — 읽기만 한다
  <공유 폴더명>_입력지시서.html
  사진/
<공유 폴더명>_실행/            ← 이 스킬이 만든다
  steps.json
  stay_helper.min.js · stay_boot.min.js
  run-log.md
```

## 형식

```markdown
# <접두><호텔 이름> — 실행 로그
- 시작: 2026-09-03 · 호텔 번호: <번호> · 접두: <접두> · 모드: 연속

| 단계 | 제목 | 결과 | 대조 | 비고 |
|---|---|---|---|---|
| 1 | 캠페인 만들기 (1개, <이름>) | 완료 | 3/3 (뱃지 이미지 비움) | Stay 호텔 목록 [캠페인] → [캠페인 만들기] 드로어 → [추가] |
| 2 | 호텔 만들기 | 완료 | 4/4 (수수료 4칸 자동) | 전체 화면 폼 · 도시·통화·거래처 확인 |
| 3 | 기본정보 글 입력 | 완료 | 한줄설명·상세설명 | 전체 화면 저장, "저장되었습니다" 확인 |
| 4 | 대표이미지 올리기 (1장) | 완료 | 1장 | 이미지 모달 파일칸 0번 |
| 8 | 룸 만들기 (1번째, <룸>) | 완료 | 16/16 | 기존 `스탠다드` 행 [편집] · 침대 구성 되읽기 불일치는 되읽기만 |
| 20 | 시즌 만들기 (1번째, <시즌>) | 완료 | 저장 버튼 [추가] | <오퍼> 카드 |
| 33 | 요금제 배포 (1회차, <요금제> × <오퍼> · <룸>) | 완료 | [이 객실에 배포] | |
| 34 | 요금제 배포 (2회차, …) | **재실행** | | 1차: 카드 범위가 표 그룹으로 안 잡혀 다른 룸에 배포 → 헬퍼 고치고 다시 |
| 34 | 요금제 배포 (2회차, …) | 완료(재실행) | [이 객실에 배포] | 대상 룸 확인 |
| 41 | 기준 요금제 바꾸기 (…) | 완료(수동 보정) | 기준 요금제 체크 → [저장] | **지시서 결함**: 사본 드로어에 `기준 요금제` 하나뿐인데 지시서는 정본 칸 나열 |
| 42 | 요금제 삭제 (…) | 완료 | [삭제] | 위험 버튼 — 러너 거부, 감독자가 대상 행(가격 셀 0) 확인 뒤 직접 누름 |
| 55 | 룸 사진 올리기 (2번째, <룸>) | 건너뜀 | | 파일 없음: <파일명> |
| 96 | 판매 시작 | **사용자 직접** | | 에이전트는 누르지 않음 |

## 마무리
- 호텔 <번호> `<접두><이름>` : 1–95 완료, 96 [판매 시작]은 사용자가 확인 후 직접 누른다. 배너 🔴 0 · 🟡 전부 넘어감.
- 감독자가 직접 누른 위험 버튼: 42 요금제 사본 [삭제] 1회 (가격 셀 없는 항목).
- 지시서(stay-setup-guide) 결함: (1) …, (2) …
- 스킬에 추가된 규칙: …
```

- 머리 줄에 **시작 날짜·호텔 번호·접두·모드**를 적는다. 호텔 번호는 `stayRun.state().hotelId` 로 읽는다.
- 표는 5열 고정: `단계 | 제목 | 결과 | 대조 | 비고`. 단계 번호와 제목은 지시서 그대로 쓴다.
- 실행한 단계만 적는다(건너뛴 것도 적는다). 아직 안 한 단계는 줄을 만들지 않는다.
- 마지막에 `## 마무리` 절을 둔다.

## 결과 낱말

| 낱말 | 뜻 |
|---|---|
| `완료` | 저장이 끝났고 화면 값이 지시서와 같다 |
| `완료(재실행)` | 한 번 어긋나 다시 돌려 성공했다. 앞 줄에 `**재실행**` 줄이 있어야 한다 |
| `완료(수동 보정)` | 화면이 지시서와 달라 페이지 안에서 값을 고쳐 넣었다. **무엇을 왜 고쳤는지 비고에 적는다** |
| `완료(확인 필요)` | 저장은 됐지만 어디에 들어갈지 지시서가 정하지 않았다. 사용자가 정해야 한다 |
| `**재실행**` | 1차 시도가 어긋났다. 무엇이 왜 어긋났는지 비고에 적는다 |
| `건너뜀` | 일부러 하지 않았다 — 이미 있음 · 파일 없음 · 버튼 없음(할 일 없음) |
| `실패` | 저장이 안 됐거나, 저장은 됐는데 값이 다르다 |
| `**사용자 직접**` | 사용자가 해야 한다 — [판매 시작] |

`실패` 가 있으면 실행을 멈추고 사용자에게 보고한다.
같은 단계를 다시 하면 **앞 줄을 고치지 않고 아래에 한 줄 더** 붙인다. 같은 단계가 두 줄이면 아래 줄이 최신이다.
연속된 단계를 한꺼번에 다시 했으면 단계 칸에 `23–25` 처럼 적는다.

## 대조 칸

무엇으로 맞다고 판단했는지를 적는다. 되읽기 수치만 쓰라는 뜻이 아니다.

- 값 칸이 있는 단계: `맞은 칸 수/대조한 칸 수`(예 `13/15`). `자동 입력됨 · 그대로 둠` 과 파일 칸은 세지 않는다.
- 저장 버튼 글자가 지시서와 달랐으면 `저장 버튼 [추가]` 처럼 적는다.
- 사진 단계: `N장` 또는 올린 파일 이름.
- 반복 행이 있으면 `추천 포인트 3행` · `요율 행 1개` 처럼 적는다.
- 되읽기가 못 읽는 칸(포함물 행, 제공 주기, 요금제 scope, 정률 값, 침대 구성)은 화면으로 확인하고 비고에 `되읽기 불일치는 되읽기만` 이라고 적는다.
- 진짜로 어긋난 칸은 비고에 `칸 이름: 기대 X 실제 Y` 로 적는다. 여러 개면 `·` 로 잇는다.

## 마무리 절

`## 마무리` 에 네 가지를 적는다.

1. 호텔 번호·이름, 완료 범위, [판매 시작] 은 사용자 몫이라는 것, 배너 🔴·🟡 남은 수.
2. **감독자가 직접 누른 위험 버튼** — 무엇을, 몇 번, 무엇을 확인하고 눌렀는지.
3. **지시서(stay-setup-guide) 결함** — 화면과 맞지 않아 보정한 곳. 번호를 매겨 짧게.
4. 이번 실행으로 스킬(헬퍼·부트)에 더한 규칙이 있으면 한 줄.

## 이어서 하기

1. `run-log.md` 가 있으면 읽는다. 없으면 1단계부터.
2. **마지막 `완료` 다음 단계**부터 시작한다.
3. `건너뜀` 은 다시 하지 않는다(사용자가 "다시 해" 라고 하면 그 단계만).
4. `실패` 는 사용자가 "계속" 하면 그 단계부터 다시 시도한다.
5. 이어서 시작할 때 머리 줄 아래에 `- 이어서: 2026-09-04 09:20 · 23단계부터` 를 한 줄 더 적는다.
