# 화면 동작 — 단계 종류별로 무엇을 누르고 무엇이 일어나는가

`stay-setup-guide` 의 `references/screen-dictionary.md` 가 **칸 이름·선택지·버튼 글자**의 정본이고,
이 문서는 그 화면들이 **어떻게 열리고 어떻게 저장되는지**를 적는다. 값은 지시서가, 글자는 사전이, 동작은 여기가 정본이다.

아래 내용은 호텔 7곳을 1단계부터 끝까지 실행하며 확인하고, **운영 2026-09-04 화면 기준
(basecamp `origin/develop` 64433dabeb)** 의 템플릿·폼과 한 줄씩 대조해 고친 것이다.

> **운영 2026-09-04 화면 기준(basecamp origin/develop 64433dabeb). 그 전 화면에서는 v0.2.x 를 쓴다.**
> 바뀐 것: 새 호텔이 **오퍼 0 · 룸 0** 으로 생기고(CO-31661), 룸 추가 드로어에 룸별
> [오퍼별 표시명] 칸이 생겼고(CO-31667), 프로모션의 `전 오퍼 공통` 카드가 늘 보이며(CO-31679),
> 시즌 드로어의 취소정책 목록이 이 호텔 것으로 좁혀졌고(CO-31675/31680),
> **[오퍼] 탭에 `연령 구간` 패널이 새로 생겼다(CO-31651 계열).**
>
> **이 문서가 대조하지 못한 화면이 하나 있다.** `기본정보` 탭(대표이미지·상품상세 이미지 모달)은
> Stay 가 아니라 fit 앱의 화면이라(`fit/templates/fit/master_form.html`) 이번 대조에 쓴 export
> 에 들어 있지 않다. 아래 `기본정보 탭` 절은 실행으로 확인한 내용 그대로 두었다 —
> `#content-modal` · [이미지 직접등록] 은 **템플릿으로 확인한 것이 아니다.**

## 2. 공통 동작

**탭** — 편집 화면 위쪽 탭 줄의 글자를 누르면 바뀌고 주소 뒤 `#…` 가 바뀐다. 도우미의 범위는 항상
`열린 드로어 → 열린 모달 → 활성 탭 → 문서` 순서로 좁혀진다.

**드로어** — Stay 탭의 입력은 거의 전부 오른쪽에서 밀려 나오는 서랍(`.stay-drawer`, 본문 `#stay_drawer_body`)에서 한다.
표 구조라 **칸 이름은 같은 행의 머리칸**이고, 그 옆 칸에 입력이 있고 그 아래 작은 도움말이 붙는다.
체크박스는 글자를 감싼 라벨이다. 날짜·시각은 고르개 없는 그냥 글자 칸이다
(`2026-01-01`, `14:00`, 오퍼 예약 시작·종료만 `2026-01-01 00:00`).
닫기는 Escape. 열면 주소에 표시가 붙으므로 **드로어를 연 채로 페이지를 새로 고치지 않는다.**

**카드와 행** — 화면은 오퍼별·룸별 카드가 겹겹이다. 도우미가 범위를 좁히는 규칙:

- 제목이 `.stay-card` 상자 안에 있으면 **그 상자가 카드**다. 행이 하나도 없는 빈 카드도 옆 카드까지 넓어지지 않는다.
- `오퍼 · 룸` 두 겹 이름이 표의 행 묶음일 때(요금제 탭)는 **오퍼 제목 뒤의 룸 제목 행부터 다음 룸 제목 행 전까지**가 한 카드다. 두 겹 이름은 표 그룹을 먼저 찾는다 — 앞 조각(오퍼)만 맞는 제목에 먼저 잡히면 안 된다.
- 행 고르기는 **칸 글자 정확 일치 > 앞글자 일치** 순이고, 칸 글자가 이름의 일부일 뿐인 것(`디럭스` 를 찾는데 `그랜드 디럭스` 행)은 세지 않는다.
- ` · ` 조각 구분은 **빈칸이 둘러싼 가운뎃점만** 이다. `Halfboard (조·석식 포함)` 은 한 조각이다.
- 체크 묶음에서 값이 뒤 조각(요금제 이름)만이면 `오퍼 · 룸 · 요금제` 칸 가운데 **이미 켜 둔 대상 룸 이름을 품은 칸을 전부** 켠다.
- 두 조각짜리 칸 이름(`제공 주기 · 1박당 제공 (…)`)은 통째로 못 찾으면 뒤 조각으로 다시 찾는다.
- **같은 이름이 여러 상자에 있으면 그 버튼을 가진 상자가 이긴다.** [오퍼] 탭이 그렇다 — 오퍼
  이름이 목록 행에도, 그 아래 `연령 구간` 카드 머리에도 있다. 목록 행 쪽 글자가 더 정확히 맞아
  (카드 머리에는 상태 표가 붙는다) 이름만으로 고르면 버튼이 없는 행이 잡히고, 그다음 문서 전체
  찾기가 **첫 오퍼의** 버튼을 눌러 버린다. 그래서 `open({button, card})` 은 버튼을 가진 상자를
  먼저 고른다(`stay_helper.js` `narrowCard`). 행을 따로 준 열기에는 이 규칙을 쓰지 않는다.

**저장** — 드로어 안 [저장]/[추가]/[만들기]/[이 객실에 배포]/[판매일 열기]/[이 단가로 깔기] 는 화면을 통째로 다시 그리지 않고
드로어 본문만 바꾼다. 성공하면 드로어가 닫히고 목록이 갱신되며, 실패하면 폼이 오류 문구와 함께 다시 그려진다.
도우미는 이것을 `closed`(성공) / `stayed`(오류 또는 그대로) 로 돌려준다. `stayed` 인데 `errors` 가 비어 있으면 화면을 눈으로 확인한다.
저장이 **성공해도** 안내 띠가 뜬다("저장되었습니다."). 그 글자는 `toast` 로만 오고 `errors` 에는
들어가지 않는다 — 실패로 읽히는 말(실패·오류·없습니다·할 수 없…)이 있을 때만 `errors` 에 얹힌다.
지시서의 저장 글자와 화면 글자가 다르면(시즌 드로어는 [추가]) 도우미가 `저장·추가·만들기·등록·확인` 을 차례로 시도한다.

**검증 배너** — 편집 화면 맨 위(`#stay_validation_banner`). 🔴 묶음(못 팜)과 🟡 묶음(채우면 좋음)으로 나뉜다.
🟡 줄의 [이건 넘어가기] 를 누르면 그 줄에만 `사유` 칸이 열리고, 사유를 적어야 [넘어가기] 가 먹는다.
🔴 가 하나라도 있으면 [판매 시작] 은 눌리지 않는다.

**위험 버튼** — 러너가 거부하는 글자는 [삭제]·[그룹 삭제]·[보관]·[보관 해제]·[판매 종료]·[판매 재개]·
[공용으로]·[전용으로 분리]·[세후가로 확정]·[N월 닫기](`1월 닫기` · `2026-01 닫기` 두 꼴) 이다.
글자와 별개로 **`hx-confirm` 이 붙은 버튼은 전부** 거부한다 — 운영 화면에서 확인창이 붙는 버튼은
이 목록보다 넓다(부가옵션·부과금·프로모션·시즌·요금제·룸 사진의 [삭제] 등).

**편집 화면 머리의 링크** — 오른쪽 위에 [상세보기]·[이력]·[목록으로]·[저장] 이 있다.
[상세보기] 는 여행사 도메인의 **고객 화면**을 새 탭으로 열고, [목록으로] 는 호텔 목록으로 **떠난다**.
러너는 둘 다 누르지 않는다 — 화면을 떠나면 드로어의 안 저장한 값이 사라지고 부트를 다시 올려야 한다.
머리의 [저장] 은 `기본정보` 탭의 전체 화면 저장 버튼이다(다른 탭의 [저장] 과 같은 글자다).

**세션** — 오래 두면 자동 로그아웃 경고 창(`#logout-warning-modal`)이 뜬다. `stayRun.keepAlive()` 로 [확인] 을 누른다.
이미 만료됐으면 드로어 안에 로그인 폼이 나타난다 → **즉시 중단하고 사용자에게 로그인을 부탁한다.** 비밀번호는 절대 대신 넣지 않는다.

**도구 한계** — 브라우저 JS 도구는 한 호출이 **45초**에서 끊긴다. 단계는 3~10개씩 묶고 단계마다 9~15초 제한을 걸어 누적 30초에서 끊는다.
탭이 뒤에 있으면 크롬이 페이지 타이머를 늦추므로 도우미는 대기를 **워커 타이머**로 잰다(그래서 뒤 탭에서도 동작한다). 스크린샷만 탭이 앞에 있어야 한다.
파일 업로드는 **한 번에 10MB** 까지다. 장당 4~5MB 사진이면 1~3장씩 나눠 올린다.

## 3. 화면별 메모

### 호텔 만들기 (목록 화면)
- 도시·거래처는 **자동완성 검색**이라 글자를 치고 결과를 눌러야 한다(도우미가 검색 칸에 글자를 넣고 keyup 까지 보낸다).
  화면 옵션은 `다낭(DAD)` 꼴이라 지시서의 `푸꾸옥 (PHU QUOC)` 을 통째로 치면 안 걸린다 — 도우미가 전체 → 괄호 앞 → 괄호 안 순으로 시도한다.
- 공급 통화는 **환율이 등록된 통화만** 목록에 뜬다. 없으면 사용자에게 알린다.
- 거래처를 고르면 수수료 네 칸이 저절로 찬다(`자동 입력됨 · 그대로 둠`).
- [호텔 만들기] 는 **전체 화면 이동**이다. JS 호출이 결과를 못 돌려주고 끊길 수 있다 —
  **스크린샷을 한 번 찍어 컨텍스트를 다시 맞추고, 새 편집 화면에서 부트를 다시 eval 한다.**
- **만들어지는 것은 마스터 하나뿐이다**(2026-09-04, CO-31661). 오퍼 0 · 룸 0 · 연결행 0 으로 시작한다 —
  종전의 `기본 오퍼`·룸 `스탠다드`·자동 연결행은 이제 생기지 않는다.
  화면에 서지 않는 필수 레코드(취소요청 설정·거래처 수수료 1행)와 `기본 요금제` **정본** 1행은 그대로 생긴다.
  그래서 **요금제만** 종전대로 새로 만들지 말고 정본을 고쳐 쓴다.
- 만든 직후 점검 배너는 "오퍼가 없습니다" 를 🔴 로 띄운다. 정상이다 — 오퍼를 만들면 사라진다.

### 기본정보 탭
- 이 탭만 다른 위젯을 쓴다 — 셀렉트가 목록을 펼치는 방식(Materialize)이고 자동완성은 select2 다. 도우미가 둘 다 처리한다.
- 저장은 **오른쪽 위 [저장]** 하나이고 **전체 화면 저장**이다. 저장 결과가 `timeout` 으로 보여도 **토스트("저장되었습니다")와 화면 값으로 확인**한다.
- 이미지: [이미지 직접등록] → 모달(`#content-modal`)에 지역·국가·도시 셀렉트, 이미지설명(Alt), PC 이미지 파일 1개, 모바일 이미지 파일 1개, 헤더 [저장].
  **한 번에 한 장**이라 7장이면 7번 반복한다. 대표이미지와 상품상세 이미지는 같은 모양의 버튼이고 올라가는 자리만 다르다.
  모달에는 파일 칸이 둘이라 `takeFiles({index:0, …})` 로 PC 이미지 칸을 지정한다. 미리보기가 만들어질 시간(`wait`)을 주지 않으면 "등록해주세요" 가 뜬다.

### 호텔 정보 탭
- 이 탭도 **전체 화면 저장**이다(탭 안 [저장]). 저장 결과가 `timeout` 으로 보여도 화면 값과 토스트로 확인한다.
- `추천 포인트` 는 [행 추가] 로 늘리는 반복 행이다. 지시서의 `추천 포인트 2 · 제목` 은 두 번째 행이다 — 행이 모자라면 도우미가 [행 추가] 를 먼저 누른다.
- **쌍으로 묶인 행이 있다.** 개장 연도·리노베이션 연도는 머리칸 `연식` 한 줄에, 위도·경도는
  머리칸 `좌표` 한 줄에 나란히 선다. 각 입력 앞에 작은 글자(`위도`·`경도`)가 붙어 있어
  도우미는 그 글자로 칸을 가른다 — 지시서는 `위도`·`경도` 처럼 **작은 글자 쪽**을 쓴다.
  `성급` 은 `연식` 행 **다음**이다.
- 위도·경도는 소수 6자리까지만 저장된다.

### 취소정책 탭
- [정책 만들기] → 드로어. `환불 가능` 을 켰을 때만 `취소 수수료 구간` 이 보인다. 구간은 [구간 추가] 로 늘린다.
- 정책 목록의 [공용으로] 는 **다른 호텔에도 영향을 주는 확인창 버튼**이다. 지시서가 요구해도 감독자 확인 없이 누르지 않는다.
- 같은 규칙의 정책이 이미 있으면 저장이 **막히지 않고 안내로 되돌아온다** — 드로어에
  [있는 것을 보기]·[그래도 새로 만들기] 두 버튼이 붙는다(`_cancellation_policy_form.html`).
  그때 `submit` 은 `stayed` 로 돌아온다. 러너는 **아무 것도 누르지 않고 멈추고** 사용자에게 묻는다 —
  같은 이름의 정책을 하나 더 만들지는 지시서가 정할 일이 아니다.

### 객실 탭
- **1번째 룸도 [룸 추가] 다.** 고쳐 쓸 `스탠다드` 행은 없다(2026-09-04, CO-31661).
- **[룸 추가] 는 룸 타입만 만든다 — 판매 연결행은 만들지 않는다.** 오퍼 select 도 없다.
  판매할 객실이 되려면 아래 `판매 연결` 카드에서 오퍼에 이어야 한다.
- 오퍼가 하나도 없으면 [룸 추가] 드로어가 폼 대신 **"오퍼를 먼저 만드세요"** 막힘 안내와
  [오퍼 탭으로 가기] 버튼을 그린다. 그때는 오퍼 단계를 먼저 끝낸다.
- `룸 이름` 바로 아래에 `룸 설명` 글상자가 있다.
- 침대 구성은 [침대 행 추가] 로 늘리는 반복 행(종류 셀렉트 + 개수). 되읽기가 침대 구성을 못 읽는 일이 잦다 — 화면으로 확인한다.
- 룸 사진은 드로어 아래쪽 `사진 추가` 파일 칸이고 **여러 장을 한 번에** 넣을 수 있다. 드로어 제목이 대상 룸인지 확인하고 올린다.
- **룸 사진에는 [저장] 이 없다.** [사진 추가] 는 `<button>` 이 아니라 **파일 칸을 감싼 `<label>`**
  이고, 그 파일 칸이 `hx-trigger="change"` 라 **고르는 즉시 올라간다**. 룸 사진 목록
  (`#stay_room_images`)만 제자리에서 갈린다(`_room_images_panel.html`).
  한도는 **최대 20장 · 장당 10MB** 다(패널 안내 문구).
- 그래서 이 단계의 지시서는 `→ [사진 추가]` 로 끝난다(2026-09-04 dict-audit 합의).
  **그 줄은 누를 저장 버튼이 아니라 올리는 행위 자체**를 가리킨다 —
  `stayRun.takeFiles({label:'사진 추가'})` 가 그 줄의 실행이고, 도우미가 요청이 끝날 때까지
  기다린 뒤 `autoUpload: true` · `uploaded` 로 알려 준다.
- **[사진 추가] 를 저장 버튼으로 누르려 하면 도우미가 `upload-label` 로 끊는다.** 끊지 않으면
  러너가 `저장·추가·만들기…` 대안을 훑다가 **룸 폼의 [저장]** 을 눌러, 사진이 붙기 전에 드로어를
  닫는다(실측으로 확인한 사고다). `대표이미지`·`상품상세 이미지` 는 그대로 `→ [저장]` 이다 —
  그쪽은 `기본정보` 탭의 진짜 저장 버튼이다.
- `판매 연결` 카드는 **오퍼마다 하나**다. [객실 추가] 는 그 오퍼에 룸 여러 개를 한꺼번에 잇는다.
  자동 연결행이 없어졌으므로 **1번째 룸부터 전부** 여기서 넣는다.
- 드로어 칸: `오퍼` 셀렉트 하나 + 룸 카테고리 체크박스 여러 개 + **체크박스마다 딸린 [오퍼별 표시명] 입력**
  (2026-09-04, CO-31667) + `새 룸 카테고리명 (선택)`·`새 룸 오퍼별 표시명 (선택)` 한 쌍
  (화면 글자 그대로다 — `stay/forms.py` `StayRoomBulkCreateForm`).
  그 두 칸은 **추가 드로어에서 늘 보인다**(편집 드로어에서만 `+ 새 룸 카테고리 만들기` 를 골라야 열린다).
  이미 그 오퍼에 연결된 룸은 체크박스도 표시명 칸도 잠긴다(`(이미 연결됨)`).
- **표시명 칸에는 라벨 요소가 없다** — 자리표시 글자가 N 칸 모두 같아 이름만으로는 가릴 수 없다.
  지시서는 `오퍼별 표시명 · <룸 카테고리명>` 으로 적고(그 차례로만 적는다), 도우미가 옆 체크박스
  글자를 이름에 붙여 찾는다(`stay_helper.js` `mateBoxLabel`). 카테고리명은 같은 단계의
  `룸 카테고리` 줄에 적힌 글자와 **한 글자도 다르지 않아야** 한다. 표 차례는 이렇다:

  ```
  | 오퍼 | 선택: <오퍼명> |
  | 룸 카테고리 | 선택: Single, Standard Double, … |
  | 오퍼별 표시명 · Single | 싱글룸 |
  | 오퍼별 표시명 · Standard Double | 스탠다드 더블룸 |
  | 새 룸 카테고리명 (선택) | 비움 |
  | 새 룸 오퍼별 표시명 (선택) | 비움 |
  ```
- 표시명을 이 드로어에서 넣었으면 연결행마다 [편집] 로 다시 넣을 일이 없다. 지시서가 따로
  `판매 연결 표시명 넣기` 단계를 두면 그때는 **행 이름을 `오퍼 · 룸`** 으로 찾는다.
- 연결행을 만들 때 **요금제 사본이 자동으로 배포된다**(`auto_apply` 정본, 없으면 기본 정본).
  그래서 `요금제 고치기` 단계는 그대로 필요하다.

### 오퍼 탭
- **첫 오퍼부터 [오퍼 추가]** 다(2026-09-04, CO-31661).
- **`오퍼 고치기` 라는 단계는 러너가 무조건 거부한다.** 제목이 그것이면 옛 화면의 `기본 오퍼`
  고쳐 쓰기라고 본다 — 이미 만든 오퍼를 되돌아가 고치는 지시서는 내지 않는다는 것이
  `stay-setup-guide` 쪽 규칙이고(그쪽 검사기도 오류로 막는다), 러너도 같게 맞춘다.
  오퍼 값을 바꿔야 하면 `오퍼 만들기` 단계의 값을 고쳐 지시서를 다시 만든다.
- 취소정책이 없는 오퍼는 **판매 시작이 막힌다**(2026-09-04, CO-31683: 경고 → 차단). 오퍼마다 기본 취소 정책을 고른다.
- 예약 시작·종료는 `2026-01-01 00:00` 꼴, 투숙 시작·종료는 `2026-01-01` 꼴이다.
- 행 버튼 중 [삭제]·[보관]·[판매 종료]·[판매 재개]·[보관 해제] 는 위험 버튼이다(전부 확인창이 붙는다).

### 오퍼 탭 — `연령 구간` 절 (2026-09-04 신설)
- 오퍼 목록 **아래**에 `연령 구간` 절이 붙는다(`#stay_offer_age_bands`). 오퍼 하나가 카드 하나이고
  카드 제목은 오퍼 이름, 카드 버튼은 **[연령 구간 추가]** 다. 드로어 제목은 `연령 구간 추가 — <오퍼명>`.
- 저장 버튼은 **[추가]**(편집이면 [저장]). 행 버튼은 [편집]·[삭제]이고 [삭제]는 확인창이다.
- 칸은 차례대로 `밴드 코드` · `노출명` · `최소 연령` · `최대 연령` · `방 인원수에 포함`(체크) ·
  `요금 기준 유형`(셀렉트) · `요금 기준 값` · `참조 밴드 코드`(셀렉트) · `상세(자유텍스트)`.
  모델의 `정원 산입 여부` 는 **화면에서 `방 인원수에 포함` 으로 덮여 있다** — 지시서는 화면 글자를 쓴다.
- `요금 기준 유형` 은 `성인 요금의 %` / `정액` / `타 밴드 요금과 동일` / `무료` 넷이고,
  **고른 유형에 따라 다음 줄이 서고 접힌다**: %·정액이면 `요금 기준 값`, 타 밴드면 `참조 밴드 코드`,
  무료면 둘 다 없다. 그래서 지시서는 **유형을 값보다 먼저** 적어야 하고, 무료 구간에는 값 줄을 내지 않는다.
  (칸이 늦게 서므로 도우미가 한 번 쉬었다 같은 이름으로 다시 찾는다 — `stay_helper.js` `fill` 의 2차 갈래.)
- `밴드 코드` 는 저장할 때 대문자로 굳고 영문·숫자·밑줄만 받는다.
- **나이 경계는 양끝이 포함이다.** 같은 오퍼 안에서 범위가 겹치면 폼이 거부한다 —
  `0~5.99` 와 `6~11.99` 는 괜찮지만 `0~6` 과 `6~11.99` 는 만 6세에서 겹쳐 막힌다
  (`services/age_band.ranges_overlap`). 계약서가 `11.99` 같은 실측 경계를 쓰는 이유다.
  다른 오퍼의 구간끼리는 겹쳐도 된다. 파서가 이 겹침을 미리 잡는다
  (`parse_guide.py --check` 의 `나이 범위가 겹치는 단계`).
- 이 절의 요금 기준은 **아동 정책 표기**일 뿐이다. 실제로 청구되는 금액은 `부과금` 탭의
  `연령별 단가` 가 정한다. 두 곳을 다 채워야 한다.

### 시즌 탭
- 시즌은 오퍼 카드 안에 있다. [시즌 추가] 로 만들고 **저장 버튼은 [추가]** 다(지시서는 [저장] 으로 적는다).
- 시즌 카드마다 [편집][가격][상태][재전개][삭제] 가 붙는다. 목록 열은
  `시즌 · 우선순위 · 전개 일수 · 구간 · 가격 셀 · 깔린 값 · 점검 · 액션` 이다 —
  전개 결과를 확인할 때 `가격 셀` 수와 `깔린 값` 을 함께 본다.
- **시즌 가격 채우기는 시즌 카드의 [가격]** → `가격 일괄 전개` 드로어다. 판매 단가·정가·공급 원가,
  `대상 룸` 체크(칸 이름이 `오퍼 · 룸`), `요금제` 체크(칸 이름이 `오퍼 · 룸 · 요금제`), 덮어쓰기 체크 두 개 → [이 단가로 깔기].
- 지시서의 회차 순서와 `이미 값이 있는 날도 덮기` 체크가 곧 결과다. **순서를 바꾸지 않는다.**
  넓은 시즌 위에 좁은 시즌을 얹는데 덮기가 해제면 **0셀이 깔린다** — 결과 셀 수를 보고 0이면 지시서 결함으로 보고한다.
- 날짜 규칙 유형을 바꾸면 보이는 칸이 달라진다(기간 범위 ↔ 월 목록 ↔ 요일 규칙 ↔ 날짜 나열). 유형을 먼저 고른다.

### 요금제 탭
- 정본은 `요금제 정본` 카드 안에 있고, 각 객실 줄 아래에 배포된 사본이 붙는다.
- 배포 대상은 표의 **`오퍼 → 룸` 제목 행 묶음**이다. 카드 범위를 표 그룹으로 잡지 않으면 첫 [요금제 추가] 가 열려 **엉뚱한 룸에 배포**된다.
- **[전체 적용] 은 아직 배포 안 된 객실이 있을 때만** 정본 행에 나타난다. 버튼이 없으면 `건너뜀 · 이미 배포됨`.
- **사본 [편집] 드로어에는 `기준 요금제` 체크 하나뿐**이다. 지시서가 정본 칸(요금제명·코드·포함물…)을 나열하면 러너는 칸 없음으로 멈춘다 — 체크만 켜고 저장하고 지시서 결함으로 보고한다.
- **`지금 모든 객실에 배포` 는 [정본 만들기] 드로어에만 있다**(`_rate_plan_catalog_form.html` 의
  `{% if create %}`). [편집] 으로 연 정본에는 그 체크도 `배포` 머리칸도 없고, 저장 버튼도
  [만들기] 가 아니라 [저장] 이다. 그래서 `요금제 고치기` 단계에 그 줄이 있으면 **지시서 결함**이다 —
  배포는 별개 단계(정본 행의 [전체 적용])다. 러너는 없는 체크 칸을 막지 않고 경고로만 남긴다.
- **`포함물` 반복 행에는 열 제목이 없다.** 두 입력은 자리표시 글자로만 갈린다 —
  왼쪽 `포함물 이름 (예: 조식 2인)`, 오른쪽 `설명 (선택)`. 정본·사본 드로어가 같은 마크업이다.
  행은 `<div>` 하나가 한 행이고 [행 추가] 로 늘린다. 지시서는 `포함물 1 · 포함물 이름` 으로 적는다.

### 가격 캘린더 탭
- 순서: **오퍼 줄 고르기 → 목표 달로 이동 → 룸 줄 고르기(개요 화면이면 [룸별 입력] 으로 전환) → 날짜 칸 클릭 → 인원 조합 행 채우기 → 그 행의 [저장]**.
- 개요 화면은 **판매일이 열린 달**에만 룸 줄을 보여 준다. 달을 먼저 옮긴다.
- 룸 줄은 룸 이름이 아니라 **오퍼별 표시명**으로 보인다. 도우미가 `객실` 탭 판매 연결 표에서 표시명을 찾아 바꿔 쓴다.
- 지시서 카드 표기는 다섯 꼴이다: `오퍼 · 룸 × 요금제 의 인원 조합 N 행` · `… 의 인원 무관 단일가 행` · `… 행` · `오퍼 의 표시명 × 요금제` · `… 의 인원별 가격 추가`. `인원 조합 빈 행` 은 인원 무관이다.
- 곱셈 기호는 **앞뒤에 빈칸이 있는 `×`** 만 인정한다(`Deluxe` 의 x 는 아니다).
- [룸별 입력] 전환은 늦게 끝나기도 해서 칩이 보일 때까지 기다렸다 한 번 더 누른다.
- **오퍼 줄은 오퍼가 둘 이상일 때만 그려진다.** 하나뿐이면 계약 이름이 글자로만 선다(누를 것이 없다).
- **오퍼 칩과 룸 칩은 둘 다 `.stay-coord-group` 안에 있다.** 가르는 것은 클래스다 —
  오퍼는 `.stay-offer-btn`, 룸 좌표는 `.stay-coord-btn`(`_calendar_month.html`).
  상자만 보고 아무 버튼이나 잡으면 오퍼 칩을 룸 칩으로 오인한다.
- 룸 좌표 칩은 **[룸별 입력] 화면에만** 있다. 전체 보기에서는 날짜 칸 안의 미니 행(`.stay-ov-row`)을
  눌러 그 좌표로 갈아탄다.
- 날짜 칸은 판매일이 열린 날만 `button.stay-cal-cell` 이다. 닫힌 날은 `span` 이라 눌리지 않는다.
- **`가격 셀 만들기` 인데 셀이 이미 있으면**(시즌 전개가 이미 깔았다) 새 행 [추가] 가 아니라 기존 행 [저장] 이다.
- 셀 편집창(`#stay_cell_edit`)은 표가 **하나이거나 둘**이다. 그 날짜에 셀이 있으면 기존 행 표 +
  `인원별 가격 추가` 표 둘이고, **하나도 없으면 `인원별 가격 추가` 표 하나뿐**이다.
  두 표의 인원 칸도 다르다 — 기존 행은 글자 칸, 새 행은 **이 계약이 이미 쓰는 키만 고르는 셀렉트**다
  (`PriceCellForm._use_occupancy_select`). 새 행에 없는 인원 조합을 넣을 길은 화면에 없다.
- 이 창은 Materialize 모달(`.modal.open`)이 아니라 Stay 의 2층 모달(`.stay-modal`)이다.

### 판매일 탭
- [판매일 열기] 드로어에서 시작일·종료일·요일 체크·대상 룸 체크 → [판매일 열기].
- 시작일이 오늘보다 앞이면 오늘 이후로 옮긴다.
- 월 단위 닫기 버튼은 `<N>월 닫기` 이고(계약이 해를 넘기면 `2026-01 닫기`), 열 머리는
  `월별 판매일 닫기` 다. 전부 확인창 버튼이다. **누르지 않는다.**

### 부과금 탭
- **시간대별 요율 행을 하나라도 추가하면 정액·정률 칸이 사라진다.** 정액/정률을 먼저 채우고 [요율 행 추가] 를 누른다.
- 한 행에 입력이 둘인 칸이 있다(`종류` = 셀렉트+이름, `부과 방식` = 셀렉트 둘, `정액 금액` = 방식+금액).
  라벨이 겹치면 도우미가 `모호` 로 알려 준다 — 라벨 뒤에 `#2` 를 붙인다.
- 정률 값은 되읽기가 못 읽는 일이 있다. 화면으로 확인한다.
- `대상 룸` 후보는 판매 연결이 있어야 뜬다.
- **`부과 방식` 과 `부과 단위` 는 다른 축이다.** 방식(`basis`)은 `정액` / `1박 요금의 %` 이고,
  단위(`per`)는 `체류당 1회` / `박당` / `인당` 이다. 둘을 섞어 적으면 옵션이 없다고 멈춘다.
- **`연령별 단가` 카드(2026-09-04 신설)는 조건부로 선다.** `부과 단위` 가 **인당**이고
  `부과 방식` 이 **정액**이며 **시간대별 요율 행이 0개**일 때만 보인다(`_charge_form.html` 의 두 `x-show`).
- 화면 칸 차례는 이렇다(지시서도 이 차례로 적는다 — 2026-09-04 dict-audit 합의):
  `종류` → `이름` → `부과 방식` → `부과 단위` → `정액 금액`/`정률` → `부과 유형` → `적용 날짜 (선택)` →
  `적용 룸 scope` → **`연령별 단가 · <노출명>`** → `시간대별 요율` → `설명`.
  요율 행을 먼저 넣으면 연령별 단가 카드가 사라진다. 파서가 이 차례를 미리 잡는다
  (`parse_guide.py --check` 의 `줄 차례가 어긋난 단계`).
- 연령별 단가 줄은 그 오퍼의 **연령 구간마다 하나**다. 칸 이름은 구간의 `노출명` 이고(표의 머리칸),
  열 제목은 `1인 단가 (<통화>)` 다. 지시서는 `연령별 단가 · <노출명>` 으로 적는다 —
  도우미가 통째로 못 찾으면 뒤 조각(노출명)으로 다시 찾는다.
- **비움과 0 은 뜻이 다르다.** 비우면 위의 정액 금액(성인가)과 같고, `0` 은 그 연령이 무료다.
  지시서에 `0` 이 적혀 있으면 `0` 을 넣는다 — 비우지 않는다.
- **차례가 어긋나면 서버가 조용히 버리지 않고 막는다**(`ChargeEditForm.clean` ④). 저장이
  `stayed` 로 돌아오고 셋 중 하나가 뜬다: "부과 단위가 “인당”이어야 합니다" ·
  "부과 방식이 “정액”일 때만 쓰입니다" · "시간대별 요율이 있으면 … 둘 중 하나만 두세요".
  그 문구가 보이면 값이 틀린 것이 아니라 **줄 차례가 틀린 것**이다 — 지시서 결함으로 보고한다.
- 그 오퍼에 연령 구간이 하나도 없으면 카드에 **입력이 아예 없고** 안내 문구만 선다.
  그때는 `오퍼` 탭의 `연령 구간` 을 먼저 만든다.

### 부가옵션 탭
- [부가옵션 추가] 로 정의를 만들고, 만들어진 카드의 [가격 추가] 로 가격 줄을 넣는다. 두 단계다.
- **같은 이름의 부가옵션이 오퍼마다 따로 있다.** 카드 표기가 `오퍼 의 이름` · `이름 중 오퍼가 X 인 카드` · `이름 — 오퍼 칸이 X 인 카드` 꼴이면 그 오퍼 카드로 좁힌다.
  오퍼 한정이 없으면 첫 카드에 들어가므로 **오퍼를 확인하고 실행**한다.
- `적용 방식` 은 `1회 적용 (박수·날짜와 무관)` / `날짜연동 (박수 따라감 — 엑스트라베드)` / `일자선택 (원하는 날만 — 조식)` 세 가지다.

### 프로모션 탭
- `단(tier)` 은 [단 추가] 로 늘리는 반복 행이다. 지시서의 `단 1 · …` 이 첫 번째 단이다.
- **프로모션 탭의 `전 오퍼 공통` 카드**(오퍼 없는 할인, 모든 오퍼에 붙음)는 **공통 프로모션이 0건이어도 늘 보인다**
  (2026-09-04, CO-31679 — 빈 상태 문구가 대신 뜬다). 보통 카드처럼 그 안의 [프로모션 추가] 를 누르면 된다.
  종전에는 카드가 감춰져서 러너가 [프로모션 추가] 요청의 오퍼 번호를 0 으로 바꿔 여는 우회를 썼다 — 그 우회는 지웠다.
- 오퍼가 하나도 없으면 프로모션 탭은 "오퍼가 없습니다" 안내를 띄운다. 오퍼 단계를 먼저 끝낸다.

### 혜택 탭
- 단독 혜택은 [혜택 추가]. 묶어 고르게 하려면 [택1 그룹 만들기] 로 그룹을 먼저 만들고(저장은 [만들기]) 그룹 카드의 [이 그룹에 혜택 추가].
- `제공 주기` 는 되읽기가 못 읽는 일이 있다.
- [그룹 삭제] 는 확인창 버튼이다.

### 검증 배너 (경고 넘어가기 — 이제는 쓰지 않는 단계)
- 합격선은 **판매 시작 전 🟡 0**이다. 지시서(v0.5+)는 `경고 넘어가기` 단계를 내지 않는다. 배너에 🟡 가 남으면 넘어가지 말고 지시서를 고쳐 다시 깐다(시즌 겹침 → 날짜 분리, 취소정책 없음 → 정책 만들기). 아래는 옛 지시서를 돌릴 때만 쓴다.
- 같은 규칙이 여러 건이면 「같은 문제 N건 ▼」로 접혀 있다. **펼친 뒤** 그 줄의 [이건 넘어가기] 를 누른다.
- 넘어갈 줄은 지시서 버튼 문장의 백틱 문구로 찾고, 없으면 제목 괄호 안 문구로 찾는다.
  낱말 사이와 **조사(에·이·가·을·를…) 앞**에 아무 글자나 올 수 있다 — `오퍼에 취소정책이 없습니다` 가 `오퍼 'X'에 취소정책이 없습니다` 에 맞는다.
- **같은 패턴에 맞는 줄은 모두** 넘어간다(한 단계에 최대 8줄).
- 사유는 필수다. [이건 넘어가기] 를 다시 누르면 사유 칸이 접히므로, 사유 칸이 안 보일 때만 누른다.
- 넘어간 줄에는 「넘어감」 표가 붙는다. [다시 보기] 로 되돌릴 수 있다.

|---|---|
| 옛 지시서: `오퍼 고치기`·`스탠다드` 행의 [편집] | 2026-09-04 뒤 화면에는 그 행이 없다. 러너가 거부한다 — 지시서를 다시 만든다 |

| 룸 추가 드로어에서 오퍼를 찾음 | 그 드로어는 룸 타입만 만든다. 오퍼 선택은 `판매 연결` 카드의 [객실 추가] 에 있다 |

| 이미지 모달에 여러 장을 한 번에 | 한 장씩 [저장] 을 장수만큼 반복 |
| 시즌 드로어에서 [저장] 을 찾다 실패 | 시즌 드로어의 저장은 [추가] 다 |
| 시즌 가격을 가격 캘린더에서 찾음 | `시즌` 탭 시즌 카드의 [가격] 이다 |
| 좁은 시즌을 얹었는데 0셀 | 넓은 시즌 위에는 `이미 값이 있는 날도 덮기` 를 켜야 한다 — 지시서 결함으로 보고 |
| 요금제가 엉뚱한 룸에 배포됨 | 요금제 탭 카드는 표의 `오퍼 → 룸` 제목 행 묶음이다. 배포 뒤 어느 룸에 붙었는지 확인 |
| 요금제 [전체 적용] 이 없다고 실패 처리 | 이미 배포된 상태다 — 건너뛰고 기록 |
| 부가옵션·프로모션이 첫 오퍼 카드에 들어감 | 카드 표기에 오퍼 한정이 있는지 보고, 없으면 사용자에게 확인 |
| 자동완성이 안 걸림 | 검색 칸에 글자를 넣고 keyup 까지 보내야 한다(도우미가 처리) |
| 확인창 버튼을 눌러 버림 | 도우미가 거부한다. 지시서가 요구하면 감독자가 대상 행을 확인한 뒤 직접 누른다 |
| 전체 화면 저장이 timeout 으로 보임 | 기본정보·호텔 정보·호텔 만들기는 전체 화면이다. 토스트와 화면 값으로 확인 |
| 저장했는데 조용히 실패 | 저장 결과가 `stayed` 인데 오류 문구가 없으면 화면을 눈으로 확인 |
| 자동 로그아웃 | 단계마다 `state()` 를 보고 경고가 뜨면 `keepAlive()` |
| 드로어를 연 채 새로 고침 | 하지 않는다. 닫고(`close()`) 다시 연다 |
| 부과금에서 정액 칸이 사라짐 | 요율 행을 먼저 추가했기 때문이다. 정액·정률 먼저 |
| 사진 업로드가 10MB 에서 막힘 | 1~3장씩 나눠 다리에 올린다 |
| 룸 사진을 올리고 [저장] 을 누름 | 룸 사진은 고르는 즉시 올라간다. [저장] 은 룸 폼을 저장해 드로어를 닫는 버튼이다 |
| 연령별 단가 칸이 화면에 없음 | `부과 방식` 이 `인당 · 정액` 이 아니거나 요율 행이 이미 있다. 순서를 지킨다 |
| 연령별 단가를 비워도 0 과 같다고 봄 | 비움 = 성인가, 0 = 무료. 다른 뜻이다 |
| 연령 구간에 `요금 기준 값` 칸이 없음 | `요금 기준 유형` 이 `무료`·`타 밴드 요금과 동일` 이다. 유형을 먼저 고른다 |
| 가격 캘린더에서 오퍼 칩을 룸 칩으로 오인 | 룸 좌표는 `.stay-coord-btn` 이다. `.stay-coord-group` 은 오퍼 줄도 쓴다 |
| 셀이 없는 날짜에서 `가격 셀 만들기` 가 실패 | 그 날은 표가 하나뿐이고 인원 칸이 셀렉트다. 러너 v0.4.0 에서 고쳤다 |
| JS 호출이 45초에서 끊김 | 한 호출에 3~10 단계, 단계마다 9~15초 제한, 누적 30초 예산 |
